## 1. 消息路由概述

### 1.1 什么是消息路由

消息路由决定消息如何从发送方到达接收方。QwenPaw 支持将消息从任一渠道路由到其他渠道，实现跨渠道的统一消息管理和会话桥接。

### 1.2 路由类型

| 类型 | 说明 | 源码路径 |
|------|------|---------|
| 直接路由 | 点对点消息发送 | `routing/direct.py` |
| 广播路由 | 一对多消息分发 | `routing/broadcast.py` |
| 主题路由 | 发布订阅模式 | `routing/topic.py` |
| 规则路由 | 条件匹配路由 | `routing/rule.py` |

`★ Insight ─────────────────────────────────────`
- 跨渠道消息路由的核心是**渠道抽象**：所有渠道实现统一的 `send()` 接口，路由层无需关心底层协议差异
- `channel + user_id` 的会话聚合实现了**跨渠道身份统一**：同一用户在不同渠道的消息汇聚到同一会话
- 主动发送（Proactive）和被动接收（Passive）的区分是**交互模式**的抽象：前者由 Agent 驱动，后者由外部事件驱动
`─────────────────────────────────────────────────`

## 4. 跨渠道路由

### 4.1 跨渠道问题

消息可能从钉钉来，需要路由到飞书去。跨渠道路由面临两个核心问题：

1. **消息格式转换**：不同渠道的消息格式不同，需要适配

## 5. 路由策略

### 5.1 策略类型

| 策略 | 说明 | 适用场景 |
|------|------|---------|
| AlwaysRoute | 总是路由 | 默认 |
| ConditionRoute | 条件路由 | 筛选消息 |
| FailoverRoute | 故障转移 | 高可用 |
| LoadBalanceRoute | 负载均衡 | 高并发 |

### 5.2 策略配置

```yaml
routing:
  policies:
    - type: condition
      condition:
        channel: dingtalk
        content_contains: ["/命令"]
      recipients:
        - agent_1
    - type: failover
      primary: agent_1
      secondary: agent_2
```

## 8. 错误处理

### 8.1 错误码

| 状态码 | 原因 | HTTPException detail |
|--------|------|----------------------|
| 400 | 请求参数缺失 | "field required" |
| 404 | Agent 不存在 | `Agent not found: {agent_id}` |
| 404 | 渠道不存在 | `Channel not found: {channel}` |
| 500 | ChannelManager 未初始化 | `Channel manager not initialized` |
| 500 | 发送失败 | `Failed to send message: {error}` |

### 8.2 异常处理

```python
try:
    await channel_manager.send_text(...)
except KeyError as e:
    raise HTTPException(status_code=404, detail=f"Channel not found: {channel}")
except AttributeError as e:
    raise HTTPException(status_code=500, detail="Channel manager not initialized")
except Exception as e:
    raise HTTPException(status_code=500, detail=f"Failed to send message: {str(e)}")
```

## 9. 设计意图

### 9.1 为什么要路由

消息路由的核心价值在于：

1. **统一接口**：隐藏底层渠道差异，提供一致的消息发送体验
2. **会话聚合**：通过 `hash(channel + user_id)` 实现跨渠道身份统一
3. **灵活性**：支持多种路由策略，适应不同业务场景

### 9.2 权衡取舍

| 权衡点 | 说明 |
|--------|------|
| 灵活性 vs 复杂性 | 支持多种路由策略增加了系统复杂度 |
| 统一性 vs 渠道特性 | 统一接口可能无法完全覆盖所有渠道的特殊能力 |
| 可靠性 vs 性能 | 可靠投递（如重试机制）会影响实时性 |
