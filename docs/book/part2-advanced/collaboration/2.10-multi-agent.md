## 1. 多智能体概述

### 1.1 为什么需要多智能体

单个智能体在处理复杂任务时面临局限性：专业能力有限、无法并行处理独立子任务、缺乏任务分解能力。多智能体协作通过将复杂任务分配给专业智能体并行执行，实现能力互补和效率提升。

### 1.2 协作模式

| 模式 | 说明 | 适用场景 |
|------|------|---------|
| 串行 | 依次执行 | 流程式任务，后一步依赖前一步结果 |
| 并行 | 同时执行 | 独立子任务，可同时处理 |
| 层次 | 主从结构 | 复杂任务分解为子任务 |
| 对等 | 平等协作 | 协商场景，多方共同决策 |

## 2. MultiAgentManager

### 2.1 核心类

**源码路径**: `src/qwenpaw/app/multi_agent_manager.py`

```python
class MultiAgentManager:
    """管理多个智能体工作空间。

    特性：
    - 延迟加载：工作空间仅在首次请求时创建
    - 生命周期管理：启动、停止、重新加载工作空间
    - 线程安全：使用异步锁进行并发访问
    - 热重载：重新加载单个工作空间而不影响其他
    - 并行启动：通过细粒度锁实现多个智能体并发启动
    """
```

### 2.2 get_agent 延迟加载与去重

```python
async def get_agent(self, agent_id: str) -> Workspace:
    """通过 ID 获取智能体工作空间（带去重的延迟加载）。

    相同 agent_id 的多个并发调用者会被协调：
    第一个调用者创建工作空间，其他等待。
    """
    # 快速路径：已加载（无需锁）
    if agent_id in self.agents:
        return self.agents[agent_id]

    async with self._lock:
        # 在锁下重新检查
        if agent_id in self.agents:
            return self.agents[agent_id]

        if agent_id in self._pending_starts:
            # 另一个任务正在启动此智能体；等待它
            event = self._pending_starts[agent_id]
        else:
            # 我们是第一个调用者 — 验证配置并声明启动
            config = load_config()
            agent_ref = config.agents.profiles[agent_id]
            event = asyncio.Event()
            self._pending_starts[agent_id] = event

    # 我们是启动者 — 在锁外创建以实现并行
    instance = Workspace(agent_id=agent_id, workspace_dir=agent_ref.workspace_dir)
    await instance.start()
    return instance
```

### 2.3 关键设计模式

| 模式 | 说明 |
|------|------|
| 双重检查锁定 | 先无锁检查，再在锁内重新检查，确保线程安全且高性能 |
| 延迟初始化 | 工作空间仅在首次请求时创建，避免预加载开销 |
| 细粒度锁 | 锁仅在字典操作时持有，不在工作空间创建期间持有 |
| 零停机重载 | 新实例立即服务请求，旧实例在后台等待任务完成后清理 |

### 2.4 生命周期

```
创建 → 注册 → 运行 → 通信 → 停止 → 清理
```

**并行启动所有已配置智能体**:

```python
async def start_all_configured_agents(self) -> dict[str, bool]:
    """并发启动配置中定义的所有已启用智能体。"""
    config = load_config()
    enabled_agents = {
        agent_id: ref
        for agent_id, ref in config.agents.profiles.items()
        if getattr(ref, "enabled", True)
    }

    async def start_single_agent(agent_id: str) -> tuple[str, bool]:
        try:
            await self.get_agent(agent_id)
            return (agent_id, True)
        except Exception as e:
            logger.error(f"Failed to start agent {agent_id}: {e}")
            return (agent_id, False)

    results = await asyncio.gather(
        *[start_single_agent(agent_id) for agent_id in enabled_agents],
        return_exceptions=False,
    )
    return dict(results)
```

## 3. ACP 协议

### 3.1 协议概述

ACP (Agent Communication Protocol) 是智能体间通信的标准化协议，支持两种模式：

| 模式 | 角色 | 说明 |
|------|------|------|
| ACP Server | 服务器 | 外部客户端连接 QwenPaw，QwenPaw 提供智能体能力 |
| ACP Tool | 客户端 | QwenPaw 连接外部 ACP 智能体，使用其工具 |

### 3.2 核心组件

**源码路径**: `src/qwenpaw/agents/acp/`

```
agents/acp/
├── __init__.py
├── core.py              # ACPErrors, SuspendedPermission
├── server.py           # QwenPawACPAgent, run_qwenpaw_agent()
├── client.py           # ACPHostedClient
├── service.py          # ACPService 单例
├── permissions.py      # 权限管理
└── tool_adapter.py     # 工具适配
```

### 3.3 消息格式

```python
class ACPMessage:
    """ACP 消息格式"""

    from_agent: str
    to_agent: str
```

**PromptBlocks 消息类型**:

| 类型 | 结构 | 说明 |
|------|------|------|
| `TextContentBlock` | `{type: "text", text: str}` | 文本内容 |
| `ImageContentBlock` | `{type: "image", url: str}` | 图片（URL 或 base64） |

### 3.4 异常体系

```python
class ACPErrors(Exception):
    def __init__(self, message: str, *, agent: Optional[str] = None):
        super().__init__(message)
        self.agent = agent

class ACPConfigurationError(ACPErrors): pass  # 配置错误
class ACPTransportError(ACPErrors): pass      # 传输错误
class ACPProtocolError(ACPErrors): pass       # 协议错误
class ACPSessionError(ACPErrors): pass        # 会话错误
```


### 4.2 会话数据结构

```python
@dataclass
class _Conversation:
    """单个 ACP 会话的状态"""
    chat_id: str                    # 聊天 ID
    agent: str                      # 智能体标识
    acp_session_id: str            # ACP 会话 ID
    cwd: str                        # 工作目录
    conn: Any                       # 连接对象
    process: Any                    # 子进程
    client: ACPHostedClient         # ACP 托管客户端
    turn_lock: asyncio.Lock         # 确保同一时刻只有一个 turn 在执行
    prompt_task: Optional[asyncio.Task]  # 当前 prompt 任务
```

### 4.3 执行流程

```python
async def run_turn(
    self,
    *,
    chat_id: str,
    agent: str,
    prompt_blocks: list[dict[str, Any]],
    cwd: str,
    on_message: MessageHandler,
) -> dict[str, Any]:
    """执行一次对话轮次"""
    conversation = await self._get_or_create_session(
        chat_id=chat_id,
        agent=agent,
        cwd=cwd,
    )

    async with conversation.turn_lock:
        if conversation.client.pending_permission is not None:
            raise ACPSessionError("Session is waiting for permission")

        conversation.client.start_prompt(on_message)
        conversation.prompt_task = asyncio.create_task(
            conversation.conn.prompt(
                session_id=conversation.acp_session_id,
                prompt=prompt_blocks,
            ),
        )
        return await self._wait_for_prompt_outcome(conversation)
```

## 6. 权限挂起机制

### 6.1 SuspendedPermission

当外部智能体请求执行敏感操作时，权限被挂起等待本地用户确认：

```python
@dataclass
class SuspendedPermission:
    """挂起的权限请求"""
    payload: dict[str, Any]              # 请求内容
    options: list[dict[str, Any]]        # 可选操作列表
    agent: str                           # 目标智能体
    tool_name: str                       # 工具名称
    tool_kind: str                       # 工具类型
    target: str | None = None            # 目标路径
    action: str | None = None           # 操作类型
    summary: str | None = None           # 请求摘要
    requires_user_confirmation: bool = True
```

### 6.2 权限流程

```
委托请求
    │
    ▼
检查权限配置
    │
    ├─── 允许 ───► 执行委托
    │
    └─── 需要确认 ───► SuspendedPermission
                              │
                              ▼
                        用户审批
                         /    \
                        /      \
                     批准      拒绝
                      │         │
                      ▼         ▼
                   执行       返回错误
```

## 7. 通信机制

### 7.1 直接通信

Agent 间通过 ACP 协议直接通信，外部智能体可通过 ACP 连接到 QwenPaw：

```
┌─────────────────┐                      ┌─────────────────┐
│  QwenPaw Agent  │ ◄─────── ACP ──────► │ External Agent  │
│                 │                      │  (Claude Code,   │

│  - 渠道消息处理  │                      └─────────────────┘
└─────────────────┘
```

### 7.2 通过 Manager

通过 MultiAgentManager 中转，实现工作空间隔离和生命周期管理：

```python
# 通过 Manager 获取智能体
manager = MultiAgentManager.get_instance()
agent = await manager.get_agent("planner")

# 通过 Manager 协调多智能体
async def collaborate(task: str):
    planner = await manager.get_agent("planner")
    executor = await manager.get_agent("executor")

    # 协作流程
    plan = await planner.run("规划任务")
    result = await executor.run(plan)
    return result
```

## 9. 设计意图

### 9.1 协作模式选择

| 场景 | 推荐模式 | 原因 |
|------|----------|------|
| 流程式处理 | 串行 | 每步依赖前一步结果 |
| 独立子任务 | 并行 | 子任务无依赖，可同时执行 |
| 复杂任务分解 | 层次 | 主智能体分解，子智能体执行 |
| 多方协商 | 对等 | 无主控，平等协作 |

### 9.2 权衡取舍

| 权衡点 | 串行 | 并行 |
|--------|------|------|
| 通信开销 | 低 | 高 |
| 任务复杂度 | 低-中 | 高 |
| 响应延迟 | 高 | 低（总体） |
| 错误传播 | 立即 | 需要结果聚合 |

### 9.3 架构决策

1. **Workspace 隔离**：每个智能体在独立文件系统中运行，安全性高但通信需通过 ACP
2. **异步优先**：使用 asyncio 实现非阻塞通信，支持高并发
3. **权限挂起**：敏感操作需要用户确认，平衡自动化与安全
