## 1. 插件系统概述

### 1.1 什么是插件

插件是 QwenPaw 的标准化扩展机制，允许开发者在不修改核心代码的前提下扩展系统功能。插件系统支持前后端一体化开发，通过标准化的接口注册 Provider、钩子和工具来扩展智能体能力。

**核心价值**：
- **模块级扩展**：插件提供完整的功能模块
- **启动时加载**：插件在应用启动时被发现和加载
- **低耦合**：插件通过标准 API 与核心系统交互
- **独立分发**：插件可独立开发、测试和发布

### 1.2 插件 vs 技能

| 对比项 | Plugin | Skill |
|--------|--------|-------|
| 粒度 | 模块级 | 功能级 |
| 加载时机 | 启动时 | 运行时 |
| 耦合度 | 低 | 更低 |
| 适用场景 | 大型扩展 | 小型功能 |
| 注册方式 | PluginApi | Skill 注册表 |


```python
class PluginManifest:
```

## 4. PluginRegistry

### 4.1 中心注册表

**源码路径**: `src/qwenpaw/plugins/registry.py`

PluginRegistry 采用单例模式，是插件系统的中心注册表：

```python
class PluginRegistry:
    """中心插件注册表 (单例模式)"""
    _instance = None

    def __new__(cls):
        if cls._instance is None:
            cls._instance = super().__new__(cls)
        return cls._instance
```

**核心属性**：

| 属性 | 类型 | 说明 |
|------|------|------|
| `_providers` | `Dict[str, ProviderRegistration]` | 已注册 Providers |
| `_startup_hooks` | `List[HookRegistration]` | 启动钩子（按 priority 排序） |
| `_shutdown_hooks` | `List[HookRegistration]` | 关闭钩子 |
| `_control_commands` | `List[ControlCommandRegistration]` | 控制命令处理器 |

### 4.2 注册内容详解

| 类型 | 存储 | 说明 |
|------|------|------|
| Provider | `_providers` | LLM Provider 注册 |
| Startup Hook | `_startup_hooks` | 应用启动时执行 |
| Shutdown Hook | `_shutdown_hooks` | 应用关闭时执行 |
| Control Command | `_control_commands` | CLI 控制命令 |

## 5. PluginApi

### 5.1 开发者接口

**源码路径**: `src/qwenpaw/plugins/api.py`

PluginApi 是插件开发者使用的主要接口：

```python
class PluginApi:
    def __init__(self, plugin_id: str, config: dict, manifest: dict = None):
        self.plugin_id = plugin_id
        self.config = config
        self.manifest = manifest or {}
        self._registry = None
```

### 5.2 核心方法

| 方法 | 说明 | 适用场景 |
|------|------|----------|
| `register_provider(provider_id, provider_class, label, base_url, **metadata)` | 注册自定义 LLM Provider | 接入私有模型 |
| `register_startup_hook(hook_name, callback, priority)` | 注册启动钩子 | 初始化资源 |
| `register_shutdown_hook(hook_name, callback, priority)` | 注册关闭钩子 | 清理资源 |
| `register_control_command(handler, priority_level)` | 注册控制命令 | 添加 CLI 命令 |

### 5.3 优先级系统

HookRegistration 使用优先级控制执行顺序：

| 优先级 | 说明 |
|--------|------|
| `priority=0` | 最高优先级（最先执行） |
| `priority=100` | 默认优先级 |
| `priority=200` | 最低优先级（最后执行） |

## 6. 插件生命周期

### 6.1 加载流程

```
启动阶段
────────────────────────────────────────────────────────────
1. PluginLoader.discover_plugins()
   └─► 扫描插件目录，查找 plugin.json

2. PluginLoader.load_all_plugins()
   └─► 对每个插件:
       ├─► 解析 manifest
       ├─► 动态导入 backend 模块
       ├─► 创建 PluginApi 实例
       └─► 调用 plugin.register(api)

3. 执行 startup_hooks（按 priority 排序）
```

### 6.2 卸载流程

```
关闭阶段
────────────────────────────────────────────────────────────
1. 取消后台启动任务（如未完成）

2. 执行 shutdown_hooks（按 priority 排序）

3. 关闭本地模型服务器

4. 停止所有 agents
```

### 6.3 生命周期图

```
加载(on_load) → 启用 → 运行 → 禁用 → 卸载(on_unload)
```

### 7.3 发现机制

**源码路径**: `src/qwenpaw/plugins/loader.py`

```python
def discover_plugins(self) -> list[tuple[PluginManifest, Path]]:
    """扫描插件目录，查找 plugin.json"""
    discovered = []
    for plugin_dir in self.plugin_dirs:
        for item in plugin_dir.iterdir():
            if not item.is_dir():
                continue
            manifest_path = item / "plugin.json"
            if manifest_path.exists():
                manifest = self._load_manifest(manifest_path)
                discovered.append((manifest, item))
    return discovered
```

## 8. 动态加载机制

### 8.1 加载实现

```python
async def load_plugin(self, manifest: PluginManifest, source_path: Path, config: dict | None = None):
    """加载单个插件"""

    # 1. 检查是否已加载
    if manifest.id in self._loaded_plugins:
        return self._loaded_plugins[manifest.id]

    # 2. 动态导入后端模块
    spec = importlib.util.spec_from_file_location(
        module_name,
        backend_entry_file,
        submodule_search_locations=[plugin_dir_str],
    )
    module = importlib.util.module_from_spec(spec)
    sys.modules[module_name] = module
    spec.loader.exec_module(module)

    # 3. 创建 PluginApi 并调用 register()
    api = PluginApi(manifest.id, config or {}, manifest_dict)
    api.set_registry(self.registry)
    result = plugin_def.register(api)
    if inspect.iscoroutine(result):
        await result

    # 4. 创建插件记录
    record = PluginRecord(
        manifest=manifest,
        source_path=source_path,
        enabled=True,
        instance=plugin_def,
    )
    self._loaded_plugins[manifest.id] = record
    return record
```

### 8.2 为什么使用 importlib

| 方式 | 优势 | 适用场景 |
|------|------|----------|
| `importlib.util.spec_from_file_location` | 动态指定路径加载，不影响主程序导入 | 插件加载 |
| 普通 `import` | 静态分析友好 | 常规模块 |

## 9. 实战：开发插件

### 9.1 插件结构

```
my_plugin/
├── plugin.json          # 插件清单
├── plugin.py           # 后端入口（必须导出 plugin 对象）
└── static/             # 前端资源（可选）
    └── index.html
```

### 9.2 完整示例

**源码路径**: `src/qwenpaw/plugins/examples/`

```python
class MyPlugin:
    """我的自定义插件"""
    name = "my_plugin"
    version = "1.0.0"

    async def on_startup(self):
        print("Plugin starting up!")

    async def on_shutdown(self):
        print("Plugin shutting down!")

plugin = MyPlugin()

def register(api):
    # 注册 Provider
    api.register_provider(
        provider_id="my-provider",
        provider_class=MyProvider,
        label="My Provider",
        base_url="https://api.example.com",
    )

    # 注册启动钩子
    api.register_startup_hook(
        hook_name="init",
        callback=plugin.on_startup,
        priority=100,
    )

    # 注册关闭钩子
    api.register_shutdown_hook(
        hook_name="cleanup",
        callback=plugin.on_shutdown,
        priority=100,
    )
```

## 11. 设计意图

### 11.1 插件化价值

1. **扩展性**：无需修改核心代码即可添加新功能
2. **模块化**：插件独立开发、测试和部署
3. **解耦**：插件通过标准 API 与系统交互
4. **可组合**：多个插件可同时启用，协同工作

### 11.2 权衡取舍

| 方面 | 灵活性 | 复杂性 |
|------|--------|--------|
| 动态加载 | 支持热插拔 | 调试难度增加 |
| 版本兼容 | 多版本共存 | 依赖管理复杂 |
| 隔离程度 | 沙箱隔离 | 资源共享受限 |
