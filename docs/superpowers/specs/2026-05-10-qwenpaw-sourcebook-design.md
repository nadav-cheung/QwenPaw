# QwenPaw 源码探秘——设计规格书

> 日期：2026-05-10
> 状态：已批准（含专家审视改进）
> **版本锚定**：本书基于 QwenPaw 源码 `src/qwenpaw/`（411 个 Python 文件，129,803 行）编写。读者应对照相同版本源码阅读，若源码有变动以源码为准。

## 概述

写一本类似《网络是怎么连接的》风格的源码分析书，面向刚学完 Python 语法的初学者。主线是一条消息从浏览器出发，穿过 HTTP、路由、调度、Agent、LLM、工具层，最终回到屏幕。每到一站停下来深入讲解原理。

## 目标读者

刚学完 Python 语法，没有实际项目经验的初学者。不假设了解 FastAPI、异步编程、设计模式。遇到这些概念时在正文中自然引入并用图解讲透。

## 推荐阅读路径

- **零基础读者**：从头到尾顺序阅读
- **有 FastAPI 经验的读者**：可快速浏览第 1、2 章，重点关注第 3 章起的 Agent 架构
- **有 AI Agent 开发经验的读者**：可直接从卷二（第 9 章）开始，按需回溯卷一
- **想直接动手贡献的读者**：先读卷一第 5-7 章（ReAct + Provider + Tool），再跳到卷三

完全独立成书，不假设读者读过 `teaching/` 目录中的教学书。

## 写作风格

图文并茂的原理讲解。每章围绕一个追问展开，用图解讲清原理。类似《网络是怎么连接的》风格——一条线串起所有知识点，概念按需引入，"概念出现是因为故事需要它，而不是因为大纲规定它。"

## 图解策略

- **段落内联的迷你示意图（≤5 节点）**：纯 ASCII（仅用英文和半角符号，不混用中文或全角字符），内嵌在代码块中
- **所有架构级图解（>5 节点）**：Mermaid 语法，包括流程图、类图、时序图、状态图等
- **"你在这里"导航标记**：纯 ASCII，不混用中文标签
- 每章至少 2-3 个核心图解
- 图解类型：流程图（请求走向）、架构图（模块关系）、时序图（调用顺序）、类图（继承/组合关系）
- **Mermaid 优势**：可维护、中文支持好、GitHub/VS Code/MkDocs 均可渲染
- **ASCII 使用原则**：仅用于段落中 3-5 节点的小图和导航标记，避免 CJK 字符导致的对齐问题
- **复杂图兜底策略**：当 Mermaid 图超过 15 个节点或涉及复杂嵌套时，考虑拆分为多个子图（用 Mermaid subgraph），或退回纯 ASCII 分步展示。不要试图用一张 Mermaid 图画出整个系统全景——拆成 2-3 张聚焦子图更清晰。

## 代码展示原则

遵循黄健宏《Redis 设计与实现》的方法论——"关注抽象和设计，而非源码细节"：

1. **展示的代码不超过 15 行**，超出用伪代码或关键行 + `...` 省略
2. **用伪代码而非大量粘贴源码**——只有当真实代码和伪代码一样短/简单时才展示真实代码
3. **每段代码前必须有上下文**：说明"我们在看什么、为什么看这段"
4. **关注机制、抽象和设计**，而非逐行翻译源码——这样书的内容保质期更长
5. **用函数名+类名引用代码，不写精确行号**——行号随版本变化很快失效，函数名稳定得多。例如写 `AgentRunner.query_handler()` 而非 `query_handler()` (line 408)。读者应使用 IDE 搜索函数名定位代码。
6. **代码片段应包含关键注释**——本书面向初学者，展示的代码片段应有简短的行内注释帮助理解，而非追求"代码干净"。伪代码同理，应标注每一步在做什么。

**注意**：误区内容应基于实际代码审查或社区问题中的真实案例，而非仅凭专家直觉。写作时可搜索 GitHub Issues 和社区讨论来验证某个误区是否真的"常见"。

### 卷间过渡

**卷一→卷二（第 9 章）**：先回顾卷一走过的完整请求链路，然后"拉远镜头"鸟瞰全景。第 9 章的定位是"回顾与鸟瞰"——让读者先确认自己理解了已经走过的路，再引入源码模块全景图。这个切换应该是自然的"登山到顶俯瞰"感，而非突兀的"换频道"。

**卷二→卷三（第 14 章末尾）**：从理解到创造是质的飞跃，需要在第 14 章末尾设置过渡桥段。用一个半引导式练习连接理解与创造，例如："你已经看懂了 Channel 的适配器模式。如果让你给它加一个'消息过滤'功能，你会改哪个文件？不用写代码，只需在源码中找到你会修改的位置，用一句话描述你的思路。"这个桥段让读者在心理上准备好从"看"切换到"做"。

**卷三→卷四（第 19 章末尾）**：从创造到评估的过渡。第 19 章"从零到 PR"本身就是创造和评估的结合——写代码（创造）+ 测试和审查（评估），天然衔接。

### 主线

用户在浏览器输入「你好，你能做什么？」，按下回车。跟着这句话穿过：

```
Browser -> HTTP Request -> FastAPI Router -> Runner Dispatch -> Agent Creation
-> Prompt Assembly -> ReAct Loop -> LLM Call -> Tool Execution -> SSE Response -> Browser Render
```

### 卷一·启程（第 1-8 章）

#### 第 1 章：浏览器按下回车之后

- **问题**：你按下回车，浏览器做了什么？HTTP 请求是怎么到达 Python 代码的？

- **关键文件**：`_app.py`、`routers/console.py`
