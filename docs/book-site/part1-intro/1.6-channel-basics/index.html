    本章导览¶

    项目 内容
    学习目标 1) 理解消息渠道的概念与作用 2) 掌握 Console 渠道的启动与配置 3) 了解多渠道配置的基本方法
    前置知识 第 1.1 章
    预计时长 30 分钟
    难度等级 ⭐⭐

    本章概述：消息渠道是 QwenPaw 与用户交互的桥梁，本章介绍渠道的基本概念、Console 渠道的配置使用，以及多渠道配置的基本方法。

    1. 消息渠道概述¶

    1.1 什么是消息渠道¶

    消息渠道是 QwenPaw 与用户交互的通道。通过配置不同的渠道，智能体可以接入钉钉、飞书、Discord、Telegram 等主流聊天平台，在用户习惯的聊天工具中提供服务。

    用户 → 渠道 → ChannelManager → Agent → 响应 → 渠道 → 用户

    1.2 支持的渠道¶

    渠道 说明 协议 配置难度
    Console Web UI 内置调试台 HTTP 零配置
    钉钉 企业内部办公 Stream SDK 需配置
    飞书 企业聊天 WebSocket 需配置
    Discord 社区平台 Gateway 需配置
    Telegram 国际常用 Polling 需配置

    1.3 渠道选择建议¶

    使用场景 推荐渠道 原因
    开发调试 Console 零配置，开箱即用
    企业内部 钉钉/飞书 与企业组织架构集成
    社区/国际用户 Discord/Telegram 配置简单，国际通用

    2. Console 渠道¶

    2.1 什么是 Console¶

    Console 是 QwenPaw 的内置 Web UI 渠道，提供交互式对话界面。启动后通过浏览器访问，即可与智能体对话。

    Console 渠道特点： - 零配置，开箱即用 - 支持 SSE 流式输出 - 兼容 Windows/macOS/Linux

    2.2 配置与启动¶

    源码路径: src/qwenpaw/app/channels/console/channel.py

    配置项:

    参数 说明 默认值
    enabled 是否启用 true
    port Web 服务端口 18792
    filter_thinking 隐藏思考过程 false
    show_tool_details 显示工具执行详情 true
    bot_prefix Bot 消息前缀 ""

    config.yaml 配置示例:

    channels:
  - type: console
    enabled: true
    port: 18792
    filter_thinking: false
    show_tool_details: true

    2.3 启动 Console¶

    # 默认启动（自动启用 Console 渠道）
qwenpaw run

# 启动后访问 http://localhost:18792

    启动成功后会看到类似输出：

    Console channel started on http://localhost:18792

    2.4 ANSI 颜色支持¶

    Console 渠道支持终端颜色输出，颜色会根据环境自动调整：

    # 自动检测终端能力，非终端环境颜色自动禁用
_USE_COLOR = os.isatty(sys.stdout.fileno())

_GREEN = "\033[32m" if _USE_COLOR else ""
_RESET = "\033[0m" if _USE_COLOR else ""

    在 CI/CD 环境或管道重定向时，颜色输出会自动关闭以避免 ANSI 转义码污染。

    2.5 Windows 编码处理¶

    Console 渠道对 Windows 平台做了特殊处理：

    # Windows 环境下自动配置 UTF-8 编码
if sys.platform == "win32":
    sys.stdout.reconfigure(encoding="utf-8", errors="replace")

    3. 消息流转机制¶

    3.1 消息模型¶

    class Msg:
    """基础消息模型"""
    content: str    # 消息内容
    sender: str     # 发送者 ID
    receiver: str   # 接收者 ID
    channel: str     # 渠道类型

    3.2 消息流程¶

    用户发送消息
    ↓
渠道接收（Console/钉钉/飞书/...）
    ↓
ChannelManager 路由到对应渠道
    ↓
Agent 处理消息
    ↓
响应通过原渠道返回用户

    3.3 渠道管理器¶

    ChannelManager 负责统一管理所有渠道：

    • 渠道注册与初始化
    • 消息路由分发
    • 多渠道并行支持

    4. 配置多渠道¶

    4.1 钉钉渠道配置¶

    步骤 1: 在钉钉开放平台创建企业自建应用，获取 App Key 和 App Secret

    步骤 2: 配置 config.yaml

    channels:
  - type: dingtalk
    enabled: true
    app_key: your_app_key
    app_secret: your_app_secret

    步骤 3: 验证连接

    qwenpaw channels test dingtalk --message "Hello"

    4.2 飞书渠道配置¶

    channels:
  - type: feishu
    enabled: true
    app_id: your_app_id
    app_secret: your_app_secret

    4.3 Telegram 渠道配置¶

    channels:
  - type: telegram
    enabled: true
    bot_token: your_bot_token

    4.4 Discord 渠道配置¶

    channels:
  - type: discord
    enabled: true
    bot_token: your_bot_token

    4.5 渠道策略¶

    策略 说明 可选值
    dm_policy 私聊策略 open（开放）/ allowlist（白名单）
    group_policy 群聊策略 open（开放）/ allowlist（白名单）
    require_mention 群聊是否需要 @ 机器人 true / false

    配置示例（钉钉，仅允许特定群组使用）：

    channels:
  - type: dingtalk
    enabled: true
    app_key: your_app_key
    app_secret: your_app_secret
    dm_policy: open
    group_policy: allowlist
    allow_from:
      - group_id_1
      - group_id_2

    5. Webhook 机制¶

    5.1 Webhook 原理¶

    Webhook 允许外部系统通过 HTTP 调用向 QwenPaw 发送消息，适用于自定义渠道集成。

    外部系统 → HTTP POST → Webhook 端点 → Agent → 响应

    5.2 Webhook 配置¶

    channels:
  - type: webhook
    enabled: true
    path: /webhook/custom
    secret: your_webhook_secret

    5.3 发送消息到 Webhook¶

    curl -X POST http://localhost:18792/webhook/custom \
  -H "Content-Type: application/json" \
  -H "X-Webhook-Secret: your_webhook_secret" \
  -d '{"content": "Hello", "sender": "user1"}'

    6. 常见问题¶

    问题 解答
    Console 无法访问 检查端口是否被占用，确认防火墙允许访问
    钉钉连接失败 检查 App Key/Secret 是否正确，确认应用已发布
    Telegram Bot 无响应 确认网络可访问 Telegram API，Bot Token 是否有效
    Windows 中文乱码 确保终端编码为 UTF-8（chcp 65001）
    颜色不显示 终端可能被重定向，颜色在非终端环境自动禁用
