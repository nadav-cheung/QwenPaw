    第 2.13 章 生命周期管理¶

    本章导览¶

    项目 内容
    学习目标 1) 理解两阶段启动的设计理念与实现 2) 掌握 ServiceManager 的服务依赖管理 3) 理解 Workspace 隔离机制与优雅关闭流程
    前置知识 第 2.1 章
    预计时长 50 分钟
    难度等级 ⭐⭐⭐
    核心关键词 两阶段启动 ServiceManager 优雅关闭 Workspace

    本章概述：深入分析两阶段启动和生命周期管理，理解如何通过 Phase 1 同步快速响应（<100ms）和 Phase 2 后台异步初始化实现零停机部署，掌握 ServiceManager 的优先级分组机制和 Workspace 隔离设计。

    1. 生命周期概述¶

    1.1 为什么需要生命周期管理¶

    生命周期管理确保系统正确初始化和关闭。对于 QwenPaw 这类复杂的多 Agent 系统，生命周期管理面临三大挑战：

    1. 快速响应：用户期望 qwenpaw app 命令立即返回，而不是等待所有 Agent 启动
    2. 资源争用：多个 Agent 同时启动可能导致数据库连接池耗尽、模型加载冲突
    3. 优雅关闭：Agent 处理中的请求不能被强制中断，需要完整的状态保存

    1.2 生命周期阶段¶

    创建 → 初始化 → 启动 → 运行 → 停止 → 清理
    阶段 说明
    创建 实例化核心管理器（MultiAgentManager, ProviderManager）
    初始化 Phase 1 同步设置，注册路由、中间件
    启动 Phase 2 后台初始化，启动所有 Agent
    运行 接受 HTTP 请求，Agent 处理消息
    停止 优雅关闭：取消任务 → 关闭钩子 → 保存状态
    清理 释放资源，输出日志

    2. 两阶段启动¶

    2.1 设计理念¶

    两阶段启动是现代 Web 应用的经典模式：快速响应 + 后台初始化。

    核心思想：将必须阻塞的初始化（<100ms）与可后台执行的初始化分离。Phase 1 完成后服务器即可接收请求，Phase 2 在后台继续完成重型任务。

    源码路径: src/qwenpaw/app/_app.py:219

    @asynccontextmanager
async def lifespan(app: FastAPI):
    startup_start_time = time.time()

    # ================================================================
    # Phase 1: Fast synchronous setup (target < 100ms)
    # ================================================================
    auto_register_from_env()

    # 遥测收集（可选）
    if not is_telemetry_opted_out(WORKING_DIR):
        collect_and_upload_telemetry(WORKING_DIR)

    # 迁移检查
    migrate_legacy_workspace_to_default_agent()
    ensure_default_agent_exists()
    migrate_legacy_skills_to_skill_pool()
    ensure_qa_agent_exists()

    # 创建核心管理器（无 I/O，即时完成）
    multi_agent_manager = MultiAgentManager()
    provider_manager = ProviderManager.get_instance()
    local_model_manager = LocalModelManager.get_instance()

    # 暴露到端点（必须在第一个请求到达前设置）
    app.state.multi_agent_manager = multi_agent_manager
    app.state.provider_manager = provider_manager
    app.state.local_model_manager = local_model_manager

    fast_elapsed = time.time() - startup_start_time
    logger.info(f"Server ready in {fast_elapsed:.3f}s")

    yield  # FastAPI 启动完成，响应请求

    # ================================================================
    # Phase 2: Background heavy initialization
    # ================================================================
    await _background_startup()

    2.2 Phase 1（同步）¶

    Phase 1 的目标是在 100ms 内完成，确保用户执行 qwenpaw app 后能立即看到服务器就绪。

    组件 耗时目标 说明
    配置加载 < 20ms 环境变量、配置文件读取
    基础服务 < 30ms Manager 实例化
    渠道初始化 < 50ms 自动注册、迁移检查
    总计 < 100ms 服务器开始接收请求

    Phase 1 完成的工作：

    1. 自动模块注册：auto_register_from_env() 扫描并注册所有内置组件
    2. 遥测初始化：设置 Telemetry 收集器（如未 opt-out）
    3. 遗留配置迁移：检测并迁移旧版配置格式
    4. 创建核心管理器：MultiAgentManager / ProviderManager / LocalModelManager

    关键约束：Phase 1 中不能有阻塞 I/O 操作。所有管理器实例化必须是瞬时的，不能加载模型或连接数据库。

    2.3 Phase 2（异步）¶

    Phase 2 在后台执行，不阻塞请求处理。使用 asyncio.create_task() 创建后台任务。

    源码路径: src/qwenpaw/app/_app.py:296

    async def _background_startup():
    # 1. 启动所有配置的 Agent（真正并行）
    await multi_agent_manager.start_all_configured_agents()

    # 2. 本地模型恢复
    provider_manager.start_local_model_resume(local_model_manager)

    # 3. 插件系统
    plugin_loader = PluginLoader(plugin_dirs)
    loaded_plugins = await plugin_loader.load_all_plugins(configs=plugin_configs)

    # 4. 注册插件 Provider
    for provider_id, provider_reg in plugin_loader.registry.get_all_providers().items():
        provider_manager.register_plugin_provider(...)

    # 5. 注册插件控制命令
    for cmd_reg in control_commands:
        register_command(cmd_reg.handler)
        command_registry.register_command(...)

    # 6. 执行插件 Startup Hooks
    for hook in plugin_loader.registry.get_startup_hooks():
        result = hook.callback()
        if inspect.iscoroutine(result) or inspect.isawaitable(result):
            await result

    # 7. 审批服务设置
    get_approval_service().set_channel_manager(default_agent.channel_manager)
    组件 说明
    模型加载 加载 LLM 模型（最耗时）
    MCP 初始化 连接 MCP 服务器
    Agent 启动 启动所有配置的 Agent
    插件加载 扫描并初始化所有插件
    技能扫描 扫描技能目录

    2.4 启动时序图¶

    t=0ms     FastAPI 启动请求
    ↓
t=10ms    初始化核心管理器（MultiAgentManager, ProviderManager, LocalModelManager）
    ↓

    3. ServiceManager¶

    3.1 核心类¶

    源码路径: src/qwenpaw/app/workspace/service_manager.py:173

    ServiceManager 负责管理工作区内所有服务的启动和停止顺序。

    class ServiceManager:
    """服务管理器"""

    def __init__(self):
        self.services: dict[str, Any] = {}
        self.dependencies: dict[str, list[str]] = {}

    def register(self, descriptor: ServiceDescriptor) -> None:
        """注册服务"""

    async def start_all(self) -> None:
        """启动所有服务"""

    async def stop_all(self) -> None:
        """停止所有服务"""

    3.2 服务描述符¶

    @dataclass
class ServiceDescriptor:
    name: str                          # 服务名称
    service_class: type                # 服务类
    init_args: dict                    # 初始化参数
    start_method: str                  # 启动方法名
    stop_method: str                   # 停止方法名
    dependencies: list[str]            # 依赖的其他服务
    priority: int                      # 启动优先级（越小越先）

    3.3 依赖管理¶

    ServiceManager 使用优先级分组机制：同优先级并发，不同优先级串行。

    服务启动顺序：

    优先级 服务 并发 说明
    10 Runner 否 AgentRunner，必须首先就绪
    20 memory_manager 是 记忆管理器（可复用）
    20 mcp_manager 是 MCP 管理器
    20 chat_manager 是 聊天管理器
    25 runner_start 否 Runner 启动（依赖 Runner 就绪）
    30 channel_manager 否 渠道管理器
    40 cron_manager 否 定时任务管理器
    50 agent_config_watcher 否 Agent 配置监听（热重载）

    执行图解：

    Priority 10: Runner [串行]
    ↓
Priority 20: memory_manager || mcp_manager || chat_manager [三者并发]
    ↓
Priority 25: runner_start [串行]
    ↓
Priority 30: channel_manager [串行]
    ↓
Priority 40: cron_manager [串行]
    ↓
Priority 50: agent_config_watcher [串行]

    设计意图： - Priority 10 Runner 必须串行：因为其他所有服务都依赖 Runner - Priority 20 三者并发：因为它们相互无依赖，可并行初始化加速 - Priority 25 runner_start 必须串行：必须等 Runner 完全就绪才能启动

    3.4 单个 Agent 启动流程¶

    async def start_one_agent(agent_id: str):
    # 1. 加载 Agent 配置
    config = load_agent_config(agent_id)

    # 2. 创建 Workspace
    workspace = Workspace(agent_id=agent_id, config=config)

    # 3. 注入可复用组件（如 memory_manager）
    await workspace.set_reusable_components(...)

    # 4. 启动 Workspace（按优先级启动所有服务）
    await workspace.start()

    # 5. 注册到 MultiAgentManager
    manager.register(agent_id, workspace)

    4. Workspace 隔离¶

    4.1 Workspace 概念¶

    源码路径: src/qwenpaw/app/workspace/workspace.py

    Workspace 是 Agent 的运行时隔离单元，每个 Agent 拥有独立的工作区。

    class Workspace:
    """工作区隔离"""

    def __init__(self, agent_id: str, config: WorkspaceConfig):
        self.agent_id = agent_id
        self.workspace_dir = Path(f"workspace/{agent_id}")
        self._service_manager = ServiceManager()

    设计原则：多 Agent 共享状态在单进程内通过内存管理，但每个 Agent 的运行时资源完全隔离。

    4.2 隔离内容¶

    资源 隔离方式
    文件系统 workspace/{agent_id}/ 独立目录
    内存状态 独立 ServiceManager 实例
    配置 独立 WorkspaceConfig 副本
    渠道 独立 ChannelManager 实例
    任务跟踪 独立 TaskTracker 实例

    4.3 可复用组件¶

    为了加速启动，Workspace 支持可复用组件（Shared Components）：

    async def set_reusable_components(self, memory_manager, mcp_manager, ...):
    """注入可复用组件，避免重复初始化"""
    self._memory_manager = memory_manager  # 可被多个 Agent 共享
    self._mcp_manager = mcp_manager

    复用条件： - 组件无 Agent 相关状态 - 组件初始化耗时（如模型加载） - 组件是线程安全的

    5. 优雅关闭¶

    5.1 关闭流程¶

    源码路径: src/qwenpaw/app/_app.py:449

    try:
    yield
finally:
    # 1. 取消后台启动任务（如仍在运行）
    if not _bg_task.done():
        _bg_task.cancel()
        await _bg_task

    # 2. 执行插件关闭钩子
    plugin_registry = app.state.plugin_registry
    if plugin_registry is not None:
        for hook in plugin_registry.get_shutdown_hooks():
            result = hook.callback()
            if iscoroutine(result):
                await result

    # 3. 关闭本地模型服务器
    local_model_mgr = app.state.local_model_manager
    if local_model_mgr is not None:
        await local_model_mgr.shutdown_server()
        local_model_mgr.shutdown_server_sync()  # 同步回退

    # 4. 停止 MultiAgentManager（停止所有 Agent）
    multi_agent_mgr = app.state.multi_agent_manager
    if multi_agent_mgr is not None:
        await multi_agent_mgr.stop_all()

    logger.info("Application shutdown complete")

    关闭步骤详解：

    步骤 操作 说明
    1 取消后台启动任务 如 _background_startup 仍在运行
    2 执行插件关闭钩子 按 priority 排序，允许异步
    3 关闭本地模型服务器 异步+同步双重回退
    4 停止 MultiAgentManager 停止所有 Agent 及组件

    5.2 关闭钩子执行顺序¶

    # 插件关闭钩子按 priority 排序执行
for hook in plugin_registry.get_shutdown_hooks():
    try:
        result = hook.callback()
        if inspect.iscoroutine(result) or inspect.isawaitable(result):
            await result
    except Exception as e:
        logger.error(f"✗ Failed shutdown hook: {hook.hook_name}")
        continue  # 继续执行其他钩子

    设计意图：一个插件的关闭钩子失败不应影响其他插件。

    5.3 信号处理¶

    信号 说明 处理
    SIGTERM 终止请求 优雅关闭
    SIGINT Ctrl+C 优雅关闭
    SIGHUP 终端关闭 忽略，保持运行 
    import signal

def setup_signal_handlers():
    """设置信号处理器"""
    signal.signal(signal.SIGTERM, _handle_shutdown)
    signal.signal(signal.SIGINT, _handle_shutdown)

    # 忽略 SIGHUP（终端关闭）
    signal.signal(signal.SIGHUP, signal.SIG_IGN)

    7. TaskTracker 后台任务管理¶

    源码路径: src/qwenpaw/app/runner/task_tracker.py:83

    TaskTracker 跟踪工作区内的所有活动任务，用于优雅关闭时等待任务完成。

    async def wait_all_done(self, timeout: float = 300.0) -> bool:
    """Wait for all active tasks to complete (default 5min timeout)."""
    async def _wait_loop() -> None:
        while await self.has_active_tasks():
            await asyncio.sleep(0.5)
    try:
        await asyncio.wait_for(_wait_loop(), timeout=timeout)
        return True
    except asyncio.TimeoutError:
        return False

    外部请求注册机制：

    async def stream_query(self, request, *args, **kwargs):
    """Dynamically route to the correct workspace runner."""
    workspace = await self._get_workspace(request)
    runner = workspace.runner

    # 注册任务到 workspace 的 TaskTracker
    run_key = f"ext-{uuid.uuid4().hex}"
    await workspace.task_tracker.register_external_task(run_key)

    try:
        async for item in runner.stream_query(request, *args, **kwargs):
            yield item
    finally:
        await workspace.task_tracker.unregister_external_task(run_key)

    8. 设计意图¶

    8.1 两阶段启动价值¶

    价值 说明
    快速响应 HTTP 请求在 Phase 1 后即可响应，不需要等待所有 Agent 就绪
    优雅降级 部分 Agent 启动失败不影响其他 Agent 和 HTTP 服务
    开发体验 qwenpaw app 命令返回快，开发者无需等待

    8.2 权衡取舍¶

    取舍 说明
    快速响应 vs 完整性 Phase 1 后服务器就绪，但 Agent 可能未完全启动
    并发 vs 资源争用 Phase 2 并发启动所有 Agent，但需控制并发度避免资源耗尽
    启动速度 vs 关闭速度 快速启动意味着需要更复杂的关闭逻辑

    9. 知识检查¶

    2. 源码题：分析 ServiceManager 的依赖管理。Priority 20 的三个服务（memory_manager、mcp_manager、chat_manager）为什么可以并发启动？

    本章小结¶

    要点 内容
    两阶段启动 Phase 1 同步(<100ms) + Phase 2 异步后台
    服务管理 ServiceManager 优先级分组启动
    工作区隔离 Workspace 独立文件系统、配置、渠道
    优雅关闭 5 步流程：取消任务 → 关闭钩子 → 保存状态 → 停止服务 → 清理资源
