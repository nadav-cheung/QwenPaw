    1. Provider 系统概述¶

    1.1 为什么需要 Provider¶

    Provider 抽象层让 QwenPaw 能够支持多种 LLM 提供商，通过统一接口封装不同模型 API 的差异。系统内置 24+ Provider，支持模型发现、连接检查、多模态探测和密钥加密存储。

    核心职责： - 统一封装不同模型 API 的差异 - 提供模型发现、连接检查、多模态探测能力 - 管理 API 密钥加密存储 - 支持 Provider 热切换和自定义 Provider 扩展

    1.2 支持的提供商¶

def _normalize_base_url(base_url: str) -> str:
    """规范化 base_url，去除末尾 /v1"""
    normalized_base_url = (base_url or "").rstrip("/")
    if normalized_base_url.endswith("/v1"):

    return normalized_base_url

def _openai_compatible_base_url(self) -> str:
    """返回 OpenAI 兼容的 base_url，加上 /v1"""
    return self._normalize_base_url(self.base_url) + "/v1"

    5.3 重试机制¶

    可重试错误码: {429, 500, 502, 503, 504, 529}

    重试流程:

    chat() 调用
         │
         ▼
获取信号量 (max_concurrent)
         │
         ▼
try: 执行 chat
         │
         ├── 成功 → yield chunks → 释放信号量
         │
         └── 失败
                 │
                 ├── 不可重试 → 释放信号量 → 抛出异常
                 │
                 └── 可重试
                         │
                         ├── 还有重试次数 → 计算延迟 → sleep → 重试
                         │
                         └── 没有重试次数 → 释放信号量 → 抛出异常

    流式响应槽位管理: 信号量槽位在首个 chunk 到达后释放，避免流式响应期间占用槽位导致其他调用者饥饿。

    6. 模型探测¶

    6.1 能力检测¶

    源码路径: src/qwenpaw/providers/multimodal_prober.py

    class MultimodalProber:
    """检测模型多模态能力"""

    async def probe(self, provider: Provider, model_id: str) -> ProbeResult:
        """探测模型支持的功能"""
        # 图像探测
        image_result = await self._probe_image(provider, model_id)
        # 视频探测
        video_result = await self._probe_video(provider, model_id)
        return ProbeResult(
            supports_image=image_result,
            supports_video=video_result,
        )

    6.2 探测数据¶

    探测图像: 32x32 红色 PNG (96 bytes) 探测视频: 64x64 蓝色 H.264 MP4 (1.8KB)

    探测策略: 使用颜色识别作为判断依据，颜色是视觉任务的最简单形式，正确答案明确（红色），易于验证。

    6.3 支持的能力¶

    能力 说明 探测方式
    vision 支持图片输入 发送红色图像，检测是否识别颜色
    function_calling 支持函数调用 检查 API 兼容性
    streaming 支持流式输出 检查 stream 参数支持

    7. 设计意图¶

    7.1 Provider 模式优势¶

    1. 统一接口: 不同的 LLM API 有不同的接口设计，Provider 抽象层提供统一接口
    2. 可替换性: 可以在运行时切换不同的模型提供商
    3. 可扩展性: 通过继承 BaseProvider 可以添加新的提供商
    4. 关注分离: 调用方不需要关心底层模型的具体实现

    7.2 权衡取舍¶

    方面 云端模型 本地模型
    成本 按 token 计费 一次性硬件投入
    性能 强大算力，低延迟 依赖本地硬件
    隐私 数据离开本地 数据不出本地
    可用性 需要网络连接 可离线使用
    灵活性 随时切换模型 受硬件限制

    7.3 工厂模式与包装器¶

    为什么需要多层包装: - TokenRecordingModelWrapper: 记录 token 使用量，用于计费和监控 - RetryChatModel: 处理瞬态错误和限流，保证可靠性

    包装顺序很重要：RetryChatModel 在最外层，确保所有调用都经过重试逻辑。
