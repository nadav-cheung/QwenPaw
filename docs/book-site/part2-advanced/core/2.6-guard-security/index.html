    本章概述：深入分析 QwenPaw 的多层安全防护机制，理解如何通过纵深防御策略保护 AI Agent 的工具调用安全。

    1. 安全系统概述¶

    1.1 为什么需要安全¶

    QwenPaw 作为本地 AI 助手，可能执行危险操作——Shell 命令、文件读写、网络请求等。当 AI 智能体调用工具时，恶意输入可能包含：

    • 命令注入：通过 $() 或反引号注入恶意命令
    • 路径遍历：访问 /etc/passwd 或 SSH 密钥等敏感文件
    • 数据泄露：窃取 API Key 或环境变量
    • 权限提升：尝试 sudo 或 su 获取更高权限

    QwenPaw 的安全系统由三大模块构成：

    模块 路径 职责
    tool_guard security/tool_guard/ 工具调用前的安全审查
    secret_store security/secret_store.py 敏感数据的加密存储
    skill_scanner security/skill_scanner/ 技能文件的安全扫描

    1.2 多层防护¶

    QwenPaw 采用纵深防御（Defense in Depth）策略，设置多层安全屏障：

    层级 防护类型 说明
    第一层 ToolGuard 工具调用守卫，拦截危险工具调用
    第二层 FileGuard 文件访问守卫，保护敏感路径
    第三层 ApprovalGuard 审批流程，人工确认高风险操作
    第四层 SecretGuard 密钥保护，敏感信息加密存储

    2. ToolGuard¶

    2.1 三层守护架构¶

    ToolGuard 是 QwenPaw 的核心安全组件，通过 ToolGuardMixin 拦截智能体的工具调用。

    源码路径: src/qwenpaw/security/tool_guard/

    ToolGuardMixin._acting()           # 拦截点
        │
        ▼
ToolGuardEngine.guard()           # 编排器
        │
        ├─► FilePathToolGuardian    (always_run=True)
        ├─► RuleBasedToolGuardian   (always_run=False)
        └─► ShellEvasionGuardian    (always_run=False)
        │
        ▼
ToolGuardResult  ──► is_safe? ──► [放行 | 拦截+审批]

    三个默认守卫：

    1. FilePathToolGuardian — 始终运行（always_run=True），保护敏感文件路径
    2. RuleBasedToolGuardian — 基于 YAML 正则规则的守卫
    3. ShellEvasionGuardian — 检测 Shell 命令混淆技术

    2.2 守卫基类¶

    源码路径: src/qwenpaw/security/tool_guard/guardians/__init__.py:15-46

    class BaseToolGuardian(ABC):
    """工具守卫抽象基类"""

    def __init__(self, name: str, *, always_run: bool = False) -> None:
        """
        Args:
            name: 守卫名称（用于日志和报告）
            always_run: True 则即使工具不在 guarded_tools 列表也执行
                        用于 FilePathToolGuardian（始终保护敏感路径）
        """
        self.name = name
        self.always_run = always_run

    @abstractmethod
    def guard(
        self,
        tool_name: str,
        params: dict[str, Any],
    ) -> list[GuardFinding]:
        """审查工具调用，返回发现的问题列表（空列表=安全）"""

    2.3 决策流程¶

    源码路径: src/qwenpaw/agents/tool_guard_mixin.py:346-400

    async def _decide_guard_action(self, tool_call: dict[str, Any]) -> "_GuardAction | None":
    engine = self._tool_guard_engine
    tool_name = str(tool_call.get("name", ""))
    tool_input = tool_call.get("input", {})

    # 1. 引擎禁用或工具名为空 → 不拦截
    if not tool_name or not engine.enabled:
        return None

    # 2. 检查是否在拒绝列表 → 自动拒绝
    if engine.is_denied(tool_name):
        denied_result = engine.guard(tool_name, tool_input)
        return _GuardAction("auto_denied", tool_name, tool_input, guard_result=denied_result)

    # 3. 检查是否需要预批准 → 预批准则直接执行
    guarded = engine.is_guarded(tool_name)
    if guarded and await self._consume_preapproval(tool_name, tool_input):
        return _GuardAction("preapproved", tool_name, tool_input)

    # 4. 运行守卫检查
    guard_result = engine.guard(tool_name, tool_input, only_always_run=not guarded)

    # 5. 有发现且需要审批 → 进入审批流程
    if guard_result is not None and guard_result.findings:
        if self._should_require_approval():
            return _GuardAction("needs_approval", tool_name, tool_input, guard_result=guard_result)

    # 6. 无问题 → 正常执行
    return None

    决策流程图：

    工具调用 → 风险评估 → 白名单检查 → 黑名单检查 → 审批 → 执行

    核心 guard 方法：

    def guard(self, tool_name: str, params: dict[str, Any]) -> list[GuardFinding]:
    findings: list[GuardFinding] = []

    # Shell命令：从命令字符串提取路径
    if tool_name == "execute_shell_command":
        command = params.get("command", "")
        for raw_path in _extract_paths_from_shell_command(command):
            self._check_value(tool_name, "command", raw_path, findings, snippet=command)
        return findings

    # 已知文件工具：只检查文件路径参数
    known_params = _TOOL_FILE_PARAMS.get(tool_name)
    if known_params:
        for param_name in known_params:
            raw_value = params.get(param_name)
            self._check_value(tool_name, param_name, raw_value, findings)
        return findings

    # 其他工具：扫描所有看起来像路径的字符串参数
    for param_name, param_value in params.items():
        if not _looks_like_path_token(param_value):
            continue
        self._check_value(tool_name, param_name, param_value, findings)

    return findings

    保护路径： - .qwenpaw.secret — 本项目密钥目录 - .copaw.secret — 旧项目名（兼容性） - 用户配置的敏感路径

    3.3 第三层：ShellEvasionGuardian¶

    源码路径: src/qwenpaw/security/tool_guard/guardians/shell_evasion_guardian.py:499-545

    职责：检测 Shell 命令混淆/逃避技术

    检测的攻击模式：

    1. 命令替换: $(), 反引号, <(), >(), =()
    2. 混淆标志: ANSI-C 引用 $'...', locale 引用 $\"..."
    3. 反斜杠转义空白: echo\\ test
    4. 反斜杠转义操作符: \;, \|, \&
    5. 隐藏换行符: 多行命令隐藏
    6. 注释引号去同步: 注释中的引号导致状态追踪错误
    7. 引用换行攻击: 引号内换行后跟 # 开头的行

    QuoteState 类 — 引用状态追踪：

    class _QuoteState:
    """Tracks shell quoting context character-by-character."""
    __slots__ = ("in_single", "in_double", "escaped")

    def feed(self, char: str) -> None:
        if self.escaped:
            self.escaped = False
            return
        if char == "\\" and not self.in_single:
            self.escaped = True
            return
        if char == "'" and not self.in_double:
            self.in_single = not self.in_single
            return
        if char == '"' and not self.in_single:
            self.in_double = not self.in_double

    这个有限状态机逐字符追踪 Shell 引号状态。只有在引号之外检测到的 $() 才算命令替换，这是它能区分 echo '$foo'（无害）和 echo $(whoami)（危险）的原因。

    def _extract_paths_from_shell_command(command: str) -> list[str]:
    """使用 shlex.split() 解析命令，提取文件路径"""
    tokens = shlex.split(command, posix=True)
    candidates: list[str] = []
    for token in tokens:
        # 处理重定向操作符: >out.txt, 2>err.log
        if token.startswith(_SHELL_REDIRECT_OPERATORS):
            candidates.append(token[1:])
        # 检查是否像路径
        if _looks_like_path_token(token):
            candidates.append(token)
    return deduped  # 去重

    6.3 审批实现¶

    源码路径: src/qwenpaw/agents/tool_guard_mixin.py:402-426

    async def _execute_guard_action(self, action: "_GuardAction", tool_call: dict) -> dict | None:
    if action.kind == "auto_denied":
        return await self._acting_auto_denied(tool_call, action.tool_name, action.guard_result)
    if action.kind == "preapproved":
        return await self._run_approved_tool_call(tool_call, action.tool_name, action.tool_input)
    if action.kind == "needs_approval":
        return await self._acting_with_approval(tool_call, action.tool_name, action.guard_result)
    return None

    预批准机制：用户审批通过后，生成一个 preapproval token，该 token 只对完全相同的参数有效，防止 "rm foo.txt" 的审批被用于 "rm -rf /"。

    6.4 审批流程状态机¶

    工具调用被拦截
      │
      ▼
  等待用户审批
      │
      ├─► APPROVED ──► 执行工具
      │
      ├─► DENIED ────► 返回拒绝消息
      │
      └─► TIMEOUT ───► 返回超时错误

    7. SecretGuard¶

    7.1 密钥保护¶

    源码路径: src/qwenpaw/security/secret_store.py

    SecretGuard 负责敏感数据（API Key、JWT Secret、环境变量）的加密存储。

    核心算法：Fernet 对称加密

    def _get_fernet() -> Fernet:
    """返回缓存的 Fernet 实例（延迟初始化）"""
    global _cached_fernet
    if _cached_fernet is None:
        master_key = _get_master_key()
        fernet_key = base64.urlsafe_b64encode(master_key[:32])
        _cached_fernet = Fernet(fernet_key)
    return _cached_fernet

    加密算法：Fernet = AES-128-CBC（加密）+ HMAC-SHA256（完整性校验）。这是"认证加密"（Authenticated Encryption），同时提供机密性和完整性保护。

    7.2 主密钥获取逻辑¶

    def _get_master_key() -> bytes:
    """主密钥解析：进程缓存 → OS Keychain → 文件 → 生成新密钥"""
    global _cached_master_key

    # 第一层：进程内缓存（最快路径，无需加锁）
    if _cached_master_key is not None:
        return _cached_master_key

    # 第二层：双重检查锁定
    with _master_key_lock:
        if _cached_master_key is not None:
            return _cached_master_key

        # 第三层：尝试从 OS Keychain 读取
        key_hex = _try_keyring_get()
        if key_hex is None:
            # 第四层：从文件读取
            key_hex = _read_key_file()

        if key_hex is None:
            # 兜底：生成新密钥
            key_hex = _generate_master_key()
            _try_keyring_set(key_hex)
            _write_key_file(key_hex)

        _cached_master_key = bytes.fromhex(key_hex)
        return _cached_master_key

    7.3 加密/解密 API¶

    def encrypt(plaintext: str) -> str:
    """加密字符串，返回 'ENC:<base64密文>' 格式"""
    if not plaintext:
        return plaintext
    fernet = _get_fernet()
    ciphertext = fernet.encrypt(plaintext.encode("utf-8"))
    return f"{_ENC_PREFIX}{base64.b64encode(ciphertext).decode('ascii')}"

def decrypt(value: str) -> str:
    """解密：如果是 'ENC:' 前缀则解密，否则直接返回"""
    if not is_encrypted(value):
        return value
    try:
        fernet = _get_fernet()
        raw = base64.b64decode(value[len(_ENC_PREFIX):])
        plaintext = fernet.decrypt(raw).decode("utf-8")
        return plaintext
    except Exception:
        return value  # 解密失败返回原值（优雅降级）

    9. 设计意图¶

    9.1 纵深防御¶

    三层守卫体现了纵深防御思想：

    层级 保护范围 绕过难度
    FilePathToolGuardian 文件系统级别 低（攻击者只需避免访问已知敏感路径）
    RuleBasedToolGuardian 命令行参数级别 中（需要构造不触发任何正则的模式）
    ShellEvasionGuardian 语义级别 高（即便躲过正则，也难以躲过结构分析）

    架构启示：不要依赖单一安全层。每一层都应该能够独立拦截常见攻击，同时层间互补。

    9.2 插件化架构¶

    BaseToolGuardian 是简单的 ABC，定义了最小接口：

    class BaseToolGuardian(ABC):
    @abstractmethod
    def guard(self, tool_name, params) -> list[GuardFinding]: ...

    这意味着未来可以热插拔新型守卫： - LLMAsJudgeToolGuardian：用另一个 LLM 判断工具调用是否安全 - ASTAnalyzerToolGuardian：用抽象语法树分析而非正则 - NetworkMonitorToolGuardian：监控工具是否发起异常网络请求

    9.3 权衡取舍¶

    考量 设计选择 权衡
    安全性 vs 易用性 默认放行，但高风险操作需审批 平衡安全与效率
    性能 vs 安全 异步执行守卫，不阻塞工具调用 接受轻微延迟换取安全
    误报 vs 漏报 偏向误报（宁可错杀不可放过） 用户可配置白名单

    10. 与 Agent 的集成¶

    10.1 Mixin + MRO 拦截¶

    源码路径: src/qwenpaw/agents/react_agent.py:76

    class QwenPawAgent(ToolGuardMixin, ReActAgent):
    """QwenPaw 智能体，集成工具、技能和记忆管理。

    MRO 说明
    ~~~~~~~~
    ``ToolGuardMixin`` 通过 Python MRO 覆盖 ``_acting`` 和 ``_reasoning``：
    QwenPawAgent → ToolGuardMixin → ReActAgent
    """

    为什么用 Mixin 而非继承？ - Mixin 可以在运行时组合，不影响被混入类的继承结构 - 多个 Mixin 可以组合（MRO 保证顺序） - 便于测试和单独验证每个 Mixin

    10.2 always_run 设计¶

    FilePathToolGuardian 设置 always_run=True，确保敏感文件保护永远不会漏过——即使管理员只配置了 denied_tools 黑名单，文件守卫仍会运行。
