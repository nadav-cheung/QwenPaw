    1. 类层次结构¶

    1.1 继承链¶

    QwenPawAgent → ToolGuardMixin → ReActAgent → Agent

    源码路径: src/qwenpaw/agents/react_agent.py:76

    class QwenPawAgent(ToolGuardMixin, ReActAgent):
    """QwenPaw 智能体核心类，MRO 顺序决定方法解析"""

    # MRO note: ToolGuardMixin 覆盖 _acting 和 _reasoning
    # 子类若重写这两个方法，必须调用 super() 以保持安全拦截生效

    方法解析顺序（MRO）：

    优先级 类 主要职责
    1 QwenPawAgent 媒体过滤、命令处理、记忆管理
    2 ToolGuardMixin 工具安全拦截
    3 ReActAgent ReAct 推理-执行循环
    4 Agent 基础智能体抽象

    1.2 Mixin 模式¶

    Python 多继承中，Mixin 是一种"混入"类，用于：

    • 不依赖继承层次即可横向扩展功能
    • 方法冲突由 MRO 决定谁优先
    • 保持类职责单一，便于组合
    # ToolGuardMixin 示例
class ToolGuardMixin:
    async def _acting(self, ...):  # 拦截工具调用
        # 安全检查逻辑
        return await super()._acting(...)  # 放行到 ReActAgent

class QwenPawAgent(ToolGuardMixin, ReActAgent):
    pass  # MRO: QwenPawAgent → ToolGuardMixin → ReActAgent → Agent

    关键设计：Mixin 只扩展行为，不改变接口契约。调用方无需知道内部有多少层 Mixin。

    3. ReAct 推理-执行循环¶

    3.1 推理阶段¶

    源码路径: src/qwenpaw/agents/react_agent.py:796-874

    async def _reasoning(
    self,
    tool_choice: Literal["auto", "none", "required"] | None = None,
) -> Msg:
    """推理阶段：让模型决定下一步行动"""

    # 第一层：主动媒体过滤（模型不支持多模态时）
    if not get_active_model_supports_multimodal():
        n = self._proactive_strip_media_blocks()
        if n > 0:
            logger.warning(f"Proactively stripped {n} media block(s)")

    # 第二层：被动重试（模型调用失败时）
    try:
        msg = await super()._reasoning(tool_choice=tool_choice)
    except Exception as e:
        if not self._is_bad_request_or_media_error(e):
            raise
        # 媒体错误 → 剥离媒体块重试
        n_stripped = self._strip_media_blocks_from_memory()
        msg = await super()._reasoning(tool_choice=tool_choice)

    # 第三层：自动续期（模型返回纯文本时催促工具调用）
    return await self._auto_continue_if_text_only(msg, tool_choice)

    三层保护机制：

    1. 主动过滤：模型不支持多模态时，预剥离媒体块
    2. 被动重试：模型拒绝媒体时，剥离后重试
    3. 自动续期：模型该用工具却返回文本时，注入提示催促

    3.2 执行阶段¶

    执行阶段由 ReActAgent._acting 实现，QwenPawAgent 通过 ToolGuardMixin 拦截：

    # ToolGuardMixin._acting 伪代码
async def _acting(self, reasoning_result):
    # 1. 安全检查：验证工具调用是否合法
    if not self._guard_check(reasoning_result):
        return self._blocked_response()

    # 2. 调用父类执行
    return await super()._acting(reasoning_result)

    4.2 工具注册¶

    注册策略（同名工具冲突时）：

    策略 行为
    override 用新工具覆盖已有
    skip 保留已有（默认）
    raise 抛出异常
    rename 重命名新工具

    异步执行：只有 execute_shell_command 支持 async_execution=True，允许后台任务。

    def _register_hooks(self) -> None:
    # Bootstrap 钩子
    bootstrap_hook = BootstrapHook(
        working_dir=self._workspace_dir or WORKING_DIR,
        language=self._language,
    )
    self.register_instance_hook(
        hook_type="pre_reasoning",
        hook_name="bootstrap_hook",
        hook=bootstrap_hook.__call__,
    )

    # 记忆压缩钩子
    if self._enable_memory_manager and self.memory_manager is not None:
        memory_compact_hook = MemoryCompactionHook(
            memory_manager=self.memory_manager,
        )
        self.register_instance_hook(
            hook_type="pre_reasoning",
            hook_name="memory_compact_hook",
            hook=memory_compact_hook.__call__,

    5.3 元类包装机制¶

    AgentScope 使用 _ReActAgentMeta 元类自动包装 _reasoning 和 _acting：

    # agentscope/agent/_agent_meta.py
class _ReActAgentMeta(_AgentMeta):
    def __new__(mcs, name, bases, attrs):
        # 为每个 _reasoning/_acting 方法添加钩子包装
        for func_name in ["_reasoning", "_acting"]:
            if func_name in attrs:
                attrs[func_name] = _wrap_with_hooks(attrs[func_name])
        return super().__new__(mcs, name, bases, attrs)

    重入保护：防止多层包装导致钩子重复执行：

    # 元类包装内部
hook_guard_attr = f"_hook_running_{func_name}"

async def async_wrapper(self, *args, **kwargs):
    # 已在执行中？跳过钩子直接执行原函数
    if getattr(self, hook_guard_attr, False):
        return await original_func(self, *args, **kwargs)
    # ...

    6. 设计意图¶

    6.1 为什么用 Mixin¶

    优势：

    方面 说明
    组合优于继承 ToolGuardMixin 可与任意 Agent 基类组合
    单一职责 每个 Mixin 只负责一件事（安全拦截、媒体过滤）
    MRO 解耦 子类无需知道各 Mixin 的加载顺序

    权衡：

    • MRO 复杂时难以追踪，建议用 ClassName.__mro__ 调试
    • Mixin 不应依赖具体子类，只通过父类接口通信

    6.2 权衡取舍¶

    设计决策 取 舍
    多继承 Mixin 灵活组合功能 MRO 复杂度
    钩子系统 无侵入扩展 重入保护负担
    媒体三重保护 兼容多种模型 增加调用延迟
    命令处理器 用户体验好 增加初始化复杂度
