    1. Runner 概述¶

    1.1 什么是 Runner¶

    Runner（执行器）负责处理用户请求的整个生命周期，从接收请求到返回响应，是 QwenPaw 与外部系统交互的桥梁。

    核心职责: - 请求路由：判断请求类型（命令 vs 普通查询） - Agent 管理：创建和管理 Agent 实例 - 会话管理：维护对话状态的持久化 - 任务追踪：管理后台任务的执行和状态

    源码路径: src/qwenpaw/app/runner/

    1.2 Runner vs Agent¶

    对比项 Agent Runner
    职责 核心智能体逻辑（推理、工具调用） 请求路由和调度
    位置 业务层 框架层
    生命周期 每次请求新建 长驻运行
    核心方法 reply()（ReAct 循环） query_handler()（请求入口）

    协作关系:

    Request → Runner.query_handler() → Agent.reply() → Response
              ↓
        命令路由 / 会话管理 / 任务追踪

    1.3 核心文件架构¶

    文件 职责
    runner.py AgentRunner 核心类，请求处理引擎
    models.py Pydantic 数据模型：ChatSpec, ChatUpdate, ChatHistory
    session.py SafeJSONSession — 异步 JSON 文件会话状态持久化
    command_dispatch.py 命令路由：daemon > control > conversation
    task_tracker.py SSE 流式输出、后台任务追踪、断线重连缓冲

    2.2 关键设计：每次请求新建 Agent 实例¶

    核心设计: 每次请求都创建新的 QwenPawAgent 实例，而非复用。

    优势: - 配置变更即时生效（AgentConfig、MCPClients、Skills 都重新加载） - 无需显式重建 Agent 或重启进程 - 避免状态残留

    开销考量: - 大部分时间花在等待 LLM 响应上 - Agent 初始化相对轻量 - 会话状态通过 SafeJSONSession 持久化

    2.3 依赖注入¶

    AgentRunner 通过 setter 方法注入依赖，实现松耦合：

    def set_chat_manager(self, chat_manager):

    def _is_command(query: str | None) -> bool:
    """True if query is any known command.

    Priority order: daemon > control > conversation
    """
    if not query or not query.startswith("/"):
        return False
    if parse_daemon_query(query) is not None:
        return True
    if _is_control_command(query):
        return True
    return _is_conversation_command(query)

    4. 请求流水线¶

    4.1 流水线 stages¶

    1. Parse → 2. Validate → 3. PreProcess → 4. Agent.Run → 5. PostProcess → 6. Response

    4.2 源码实现¶

    源码路径: src/qwenpaw/app/runner/pipeline.py

    class Pipeline:
    """请求处理流水线"""

    async def execute(self, request: Request) -> Response:
        for stage in self.stages:
            request = await stage.process(request)
        return request.response

    4.3 核心处理流程¶

    query_handler 方法（12 阶段处理）:

    Stage 1:  审批检查 → 检查待审批的工具调用
Stage 2:  命令路由 → 判断命令类型，进入对应处理路径
Stage 3:  上下文设置 → 设置 contextvars
Stage 4:  Agent 构建准备 → 收集配置和上下文
Stage 5:  Mission 检测 → 检测 /mission 命令
Stage 6:  Agent 实例化 → 创建 QwenPawAgent
Stage 7:  聊天注册 → 自动注册会话
Stage 8:  技能注入 → 处理 /skillname 命令
Stage 9:  会话加载 → 从 JSON 加载历史状态
Stage 10: 执行 → 流式输出或 Mission 执行
Stage 11: 错误处理 → 异常转换和调试信息
Stage 12: 清理 → 保存状态，更新会话

    4.4 流式输出机制¶

    可中断的流式输出:

    async def _stream_printing_messages_interruptible(
    agents: list[Any],
    coroutine_task: Coroutine,
) -> AsyncGenerator[tuple[Msg, bool], None]:
    """支持外部取消的流式输出"""
    queue: asyncio.Queue = asyncio.Queue()
    for agent in agents:
        agent.set_msg_queue_enabled(True, queue)

    task = asyncio.create_task(coroutine_task)
    try:
        while True:
            printing_msg = await queue.get()
            if isinstance(printing_msg, str) and printing_msg == _PRINT_END_SIGNAL:
                break
            msg, last, _ = printing_msg
            yield msg, last
    except asyncio.CancelledError:
        await _cancel_streaming_agent_task(task)
        raise

    特点: - 使用 asyncio.Queue 传递消息 - 支持外部取消时立即取消 Agent 任务 - 通过 task.add_done_callback() 通知队列结束

    7. 设计意图¶

    7.1 流水线模式优势¶

    1. 清晰分离: 每个阶段职责明确，易于理解和维护
    2. 可扩展性: 新增阶段只需实现 process() 方法
    3. 可测试性: 各阶段可独立单元测试
    4. 错误隔离: 单阶段失败不影响其他阶段

    7.2 三层命令路由设计¶

    优先级依据: - daemon: 系统级操作，需要最快响应 - control: 影响当前任务的操作 - conversation: 对话管理，可以稍后处理

    7.3 权衡取舍¶

    设计选择 优势 代价
    每次请求新建 Agent 热重载即时生效 初始化开销
    文件存储 Session 跨进程可访问 性能低于内存存储
    三层命令路由 职责清晰 增加复杂度
