**关键理解**：
- Java 用**拦截器链 + AOP** 做方法级安全，Python 用**守卫引擎 + 规则文件**
- Java 的 `Filter` 链对应 Python 的 guardian 遍历执行
- Java 配置倾向 Java 代码（`@Bean`），Python 配置倾向 YAML 文件
- 两者都支持**拒绝优先**：发现威胁立即阻止，而非放行后审计

def match(self, value: str) -> tuple[re.Match[str] | None, str | None]:
    # 首先检查排除模式
    if any(ep.search(value) for ep in self.compiled_exclude_patterns):
        return None, None
    # 匹配模式
    for pattern in self.compiled_patterns:
        m = pattern.search(value)
        if m:
            return m, pattern.pattern
    return None, None
```

## ShellEvasionGuardian - Shell 混淆检测

### 检测的攻击模式

1. **命令替换**: `$()`, 反引号, `<()`, `>()`, `=()`
2. **混淆标志**: ANSI-C 引用 `$'...'`, locale 引用 `$"..."`
3. **反斜杠转义空白**: `echo\\ test`
4. **反斜杠转义操作符**: `\;`, `\|`, `\&`
5. **隐藏换行符**: 多行命令隐藏
6. **注释引号去同步**: 注释中的引号导致状态追踪错误
7. **引用换行攻击**: 引号内换行后跟 # 开头的行

### _QuoteState 类 - 引用状态追踪

class _QuoteState:
    __slots__ = ("in_single", "in_double", "escaped")

    def feed(self, char: str) -> None:
        if self.escaped:
            self.escaped = False
            return
        if char == "\\" and not self.in_single:
            self.escaped = True
            return
        if char == "'" and not self.in_double:
            self.in_single = not self.in_single
            return
        if char == '"' and not self.in_single:
            self.in_double = not self.in_double
```

### 决策流程

**文件**: `src/qwenpaw/agents/tool_guard_mixin.py:346-400`

```python
async def _decide_guard_action(self, tool_call: dict[str, Any]) -> "_GuardAction | None":
    engine = self._tool_guard_engine
    tool_name = str(tool_call.get("name", ""))
    tool_input = tool_call.get("input", {})

    # 1. 引擎禁用或工具名为空 → 不拦截
    if not tool_name or not engine.enabled:
        return None

    # 2. 检查是否在拒绝列表 → 自动拒绝
    if engine.is_denied(tool_name):
        denied_result = engine.guard(tool_name, tool_input)
        return _GuardAction("auto_denied", tool_name, tool_input, guard_result=denied_result)

    # 3. 检查是否需要预批准 → 预批准则直接执行
    guarded = engine.is_guarded(tool_name)
    if guarded and await self._consume_preapproval(tool_name, tool_input):
        return _GuardAction("preapproved", tool_name, tool_input)

    # 4. 运行守卫检查
    guard_result = engine.guard(tool_name, tool_input, only_always_run=not guarded)

    # 5. 有发现且需要审批 → 进入审批流程
    if guard_result is not None and guard_result.findings:
        if self._should_require_approval():
            return _GuardAction("needs_approval", tool_name, tool_input, guard_result=guard_result)

    # 6. 无问题 → 正常执行
    return None
```

async def _execute_guard_action(self, action: "_GuardAction", tool_call: dict) -> dict | None:
    if action.kind == "auto_denied":

    if action.kind == "preapproved":

```java
// Java 的 SecurityFilterChain 类似 ToolGuardEngine
@Configuration
public class SecurityConfig {
    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            .addFilterBefore(new ToolGuardFilter(), BasicAuthenticationFilter.class)
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/api/**").authenticated()
            );

    }

// ToolGuardFilter 类似 RuleBasedToolGuardian
public class ToolGuardFilter extends OncePerRequestFilter {
    @Override
    protected void doFilterInternal(HttpServletRequest request,
                                    HttpServletResponse response,
                                    FilterChain chain) throws ServletException, IOException {
        // 1. 解析工具名称和参数
        String toolName = request.getHeader("X-Tool-Name");
        Map<String, Object> params = parseParams(request);

        // 2. 调用守卫规则检查
        List<GuardFinding> findings = ruleGuardian.guard(toolName, params);

        // 3. 根据严重性决策
        if (findings.stream().anyMatch(f -> f.severity == GuardSeverity.CRITICAL)) {
            throw new AccessDeniedException("Tool call blocked by security policy");
        }
        chain.doFilter(request, response);
    }
}
```

2. **误报率优化**
   内置的 `ShellEvasionGuardian` 检测多种混淆技术，但可能产生误报。请分析以下场景：
   - 用户输入 `echo "SELECT * FROM users WHERE name = '$name'"` 作为 SQL 查询工具的参数
   - `$name` 被检测为 `$()` 命令替换攻击

   请设计一种机制：在不降低安全性的前提下，减少这类误报。可以考虑白名单、参数来源标记或上下文感知等方案。

3. **嵌套 JSON 参数的守卫**
   当前守卫直接对 `tool_input` 字典进行模式匹配。但如果工具参数是嵌套 JSON 字符串（如 `"payload": "{\"cmd\": \"rm -rf /\"}"`），守卫可能无法检测到其中的危险内容。请设计一个递归守卫方法 `deep_guard`，能够递归解析嵌套结构并检测深层威胁。
