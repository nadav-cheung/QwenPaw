## 概述

QwenPaw 的心跳系统是一个后台自检机制，定期检查智能体健康状态、记忆状况，并在需要时主动向用户发送摘要或提醒。本文档介绍心跳系统的功能和使用方法。

## 1. 心跳简介

### 1.1 什么是心跳

心跳（Heartbeat）是智能体定时执行的自检任务，用于：

- 检查记忆系统状态
- 生成记忆摘要
- 主动向用户发送提醒或摘要
- 清理过期数据

### 1.2 心跳与定时任务的区别

| 特性 | 心跳 (Heartbeat) | 定时任务 (Cron) |
|------|------------------|-----------------|
| 触发方式 | 定时自动触发 | 手动配置 |
| 主要功能 | 健康检查、记忆整理 | 自定义任务执行 |
| 用户交互 | 主动通知用户 | 可选通知 |
| 上下文 | 有完整记忆上下文 | 可选上下文 |

## 3. 钩子系统详解

### 3.1 BootstrapHook 首次引导

**源码路径**: `src/qwenpaw/agents/hooks/bootstrap.py`

`BootstrapHook` 在用户首次交互时检查 `BOOTSTRAP.md` 文件并显示设置引导：

```python
class BootstrapHook:
    """Hook for bootstrap guidance on first user interaction."""

    def __init__(
        self,
        working_dir: Path,
        language: str = "zh",
    ):
        self.working_dir = working_dir
        self.language = language

    async def __call__(
        self,
        agent,
        kwargs: dict[str, Any],
    ) -> dict[str, Any] | None:
        # 1. 检查 .bootstrap_completed 标记文件是否存在
        bootstrap_completed_flag = self.working_dir / ".bootstrap_completed"
        if bootstrap_completed_flag.exists():
            return None

        # 2. 检查 BOOTSTRAP.md 是否存在
        bootstrap_path = self.working_dir / "BOOTSTRAP.md"
        if not bootstrap_path.exists():
            return None

        # 3. 检查是否首次用户交互
        messages = await agent.memory.get_memory()
        if not is_first_user_interaction(messages):
            return None

        # 4. 加载引导文本并前置到首条用户消息
        bootstrap_guidance = build_bootstrap_guidance(self.language)
        prepend_to_message_content(msg, bootstrap_guidance)

        # 5. 创建完成标记
        bootstrap_completed_flag.touch()
```

**触发流程**:
```
用户首次发送消息
    ↓
检查 .bootstrap_completed 标记（不存在则继续）
    ↓
检查 BOOTSTRAP.md 是否存在
    ↓
检查是否首次用户交互（messages 为空或仅有一条）
    ↓
前置引导文本到首条用户消息
    ↓
创建 .bootstrap_completed 标记文件
```

### 3.3 MemoryCompactionHook 上下文压缩

**源码路径**: `src/qwenpaw/agents/hooks/memory_compaction.py`

`MemoryCompactionHook` 是推理前钩子，在上下文接近满时自动触发压缩：

```python
class MemoryCompactionHook:
    """Hook for automatic memory compaction when context is full."""

    _REENTRANCY_ATTR = "_memory_compact_hook_running"

    def __init__(self, memory_manager: "BaseMemoryManager"):
        self.memory_manager = memory_manager

    async def __call__(
        self,
        agent: ReActAgent,
        kwargs: dict[str, Any],
    ) -> dict[str, Any] | None:
        # 防止重复执行（QwenPawAgent 和 ReActAgent 都被包装）
        if getattr(agent, self._REENTRANCY_ATTR, False):
            return None
        setattr(agent, self._REENTRANCY_ATTR, True)

        try:
            # 1. 获取 token 计数
            agent_config = load_agent_config(self.memory_manager.agent_id)
            token_counter = get_token_counter(agent_config)

            # 2. 计算剩余空间
            system_prompt = agent.sys_prompt
            compressed_summary = memory.get_compressed_summary()
            str_token_count = await token_counter.count(...)

            left_compact_threshold = (
                running_config.memory_compact_threshold - str_token_count
            )

            # 3. 检查是否需要压缩
            messages = await memory.get_memory(prepend_summary=False)
            messages_to_compact, _, is_valid = await self.memory_manager.check_context(...)

            if not is_valid:
                # 4. 执行压缩
                compact_content = await self.memory_manager.compact_memory(
                    messages=messages_to_compact,
                    previous_summary=memory.get_compressed_summary(),
                )

                # 5. 标记消息为已压缩
                await memory.mark_messages_compressed(messages_to_compact)
                await memory.update_compressed_summary(compact_content)
        finally:
            setattr(agent, self._REENTRANCY_ATTR, False)
```

**关键设计**:
- **防重入**: 使用 `_memory_compact_hook_running` 属性防止重复执行
- **保留最近**: `MEMORY_COMPACT_KEEP_RECENT` 保留最近的消息
- **异步摘要**: 使用 `add_async_summary_task()` 不阻塞主流程
- **配置驱动**: `memory_compact_threshold`、`memory_compact_reserve` 等参数

### 3.4 钩子执行时机

**推理前钩子（Pre-reasoning Hooks）**:

| 钩子 | 触发时机 | 功能 |
|------|---------|------|
| `BootstrapHook` | 首次用户交互 | 显示设置引导 |
| `MemoryCompactionHook` | 每次推理前 | 检查并压缩上下文 |
| `AgentContextHook` | 每次推理前 | 设置 agent/session 上下文 |

**执行顺序**:
```
用户消息到达
    ↓
BootstrapHook (仅首次)
    ↓
MemoryCompactionHook (每次)
    ↓
AgentContextHook (每次)
    ↓
开始推理 (_reasoning)
```

### 3.5 钩子注册机制

**源码路径**: `src/qwenpaw/agents/react_agent.py`

钩子在 QwenPawAgent 初始化时注册：

```python
class QwenPawAgent(ReActAgent):
    def __init__(self, ...):
        super().__init__(...)

        # 注册推理前钩子
        self.pre_reasoning_hooks = [
            BootstrapHook(workspace_dir, language),
            MemoryCompactionHook(memory_manager),
            AgentContextHook(),
        ]

    async def _reasoning(self, ...):
        # 执行所有钩子
        for hook in self.pre_reasoning_hooks:
            await hook(self, kwargs)
```

async def heartbeat_memory_maintenance():
    """心跳 - 记忆整理"""
    
    # 1. 检查记忆大小
    memory_size = await get_memory_size()
    
    # 2. 如果超过阈值，执行压缩

## 9. 总结

### 核心要点

1. **心跳机制**: 定时自检系统，检查记忆状态、磁盘空间、模型可用性
2. **BootstrapHook**: 首次交互时检查 BOOTSTRAP.md 显示设置引导
3. **HEARTBEAT.md**: 工作目录配置文件，定义检查间隔和通知规则
4. **记忆整理**: 心跳触发时自动执行记忆压缩和清理
5. **主动通知**: 发现问题时通过配置的渠道主动通知用户

### 关键配置

| 配置项 | 说明 |
|--------|------|
| `heartbeat.enabled` | 是否启用心跳 |
| `heartbeat.interval_minutes` | 检查间隔（默认 60 分钟） |
| `heartbeat.checks` | 执行哪些检查 |
| `heartbeat.notification` | 通知配置 |

### 故障排查流程

```
心跳不触发
    │
    ├─► 检查启用心跳: 查看 config.json 中 heartbeat.enabled
    │
    ├─► 检查间隔配置: 查看 HEARTBEAT.md 或 config.json
    │
    └─► 查看日志: grep heartbeat ~/.qwenpaw/logs/qwenpaw.log

通知发送失败
    │
    ├─► 检查渠道配置: qwenpaw channels list
    │
    ├─► 测试渠道连接: qwenpaw channels list
    │
    └─► 检查通知设置: notification.enabled 是否为 true
```

## 12. 知识检查

### 检查 1

心跳系统中 `interval_minutes` 字段的作用是什么？如果将其设置为 0 会发生什么？

<details>
<summary>参考答案</summary>

`interval_minutes` 控制心跳检查的执行间隔（单位为分钟），默认值为 60。如果设置为 0，心跳任务将不会自动触发，等同于禁用定时检查。正确的做法是通过 `enabled: false` 来显式禁用心跳。

</details>

### 检查 2

`MemoryCompactionHook` 为什么需要防重入机制（`_REENTRANCY_ATTR`）？如果不防重入会导致什么问题？

<details>
<summary>参考答案</summary>

因为 QwenPawAgent 和 ReActAgent 都会被包装，推理前钩子可能被调用两次。如果不防重入，同一轮对话中会执行两次上下文压缩，导致：1) 重复计算浪费资源；2) 已压缩的消息可能被再次压缩，造成信息丢失；3) 并发修改记忆状态可能引发数据不一致。

</details>

### 检查 3

心跳检查项 `memory` 和定时任务中的记忆整理有什么区别？它们各自适用的场景是什么？

<details>
<summary>参考答案</summary>

心跳的 `memory` 检查是自动化的周期性维护，主要做状态检查、阈值监控和触发压缩，适合日常自动运维。定时任务中的记忆整理是用户自定义的、可精确控制执行时间的任务，适合需要特定时间点（如凌晨）执行深度清理或摘要生成的场景。两者互补：心跳保证基线健康，定时任务提供精细化控制。

</details>
