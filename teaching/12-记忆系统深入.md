### 2.1 工作原理

InMemoryMemory 是 AgentScope 框架内置的短期记忆系统：

```python
class InMemoryMemory:
    """AgentScope 内置的内存记忆"""
    
    def __init__(self, max_token_limit: int = 128000):
        self.max_token_limit = max_token_limit
        self._memory: List[Msg] = []
    
    async def add(self, msg: Msg, marks: Optional[_MemoryMark] = None) -> None:
        """添加消息到记忆"""
        self._memory.append(msg)
    
    async def get_memory(self) -> List[Msg]:
        """获取当前记忆内容"""
        return self._memory
    
    def load_state_dict(self, state: dict) -> None:
        """从状态字典加载"""
        self._memory = [Msg.from_dict(m) for m in state]
    
    def dump_state_dict(self) -> dict:
        """导出为状态字典"""
        return [m.to_dict() for m in self._memory]
```

### 2.2 Token 计数

```python
def count_tokens(text: str) -> int:
    """计算文本的 token 数量（估算）"""
    # 粗略估算：中文约 2 字符/token，英文约 4 字符/token
    chinese_chars = len([c for c in text if ord(c) > 0x4e00])
    other_chars = len(text) - chinese_chars
    return chinese_chars // 2 + other_chars // 4
```

### 2.3 上下文窗口管理

当上下文接近上限时，`MemoryCompactionHook` 会触发压缩：

```python
async def check_context(memory_manager, messages) -> tuple:
    """检查是否需要压缩"""
    total_tokens = sum(count_tokens(m.content) for m in messages)
    remaining = memory_manager.max_token_limit - total_tokens
    
    # 如果剩余空间不足 20%，触发压缩
    if remaining < memory_manager.max_token_limit * 0.2:
        return messages, remaining, False  # is_valid = False
    
    return messages, remaining, True
```

**`compact_memory` 方法** (第311-386行) - 记忆压缩实现：

```python
async def compact_memory(
    self,
    messages: list[Msg],
    previous_summary: str = "",
    extra_instruction: str = "",
    **_kwargs,
) -> str:
    """Compact messages into a condensed summary.

    Args:
        messages: 要压缩的消息列表
        previous_summary: 上一次压缩的摘要
        extra_instruction: 额外指令
        compact_ratio: 压缩比例（来自 context_compact 配置）

    Returns:
        压缩后的摘要字符串，失败时返回空字符串
    """
    self._prepare_model_formatter()
    agent_config = load_agent_config(self.agent_id)
    cc = agent_config.running.context_compact

    result = await self._reme.compact_memory(
        messages=messages,
        as_llm=self.chat_model,
        as_llm_formatter=self.formatter,
        as_token_counter=get_token_counter(agent_config),
        language=agent_config.language,
        max_input_length=agent_config.running.max_input_length,
        compact_ratio=cc.memory_compact_ratio,  # 压缩比例（如 0.5）
        previous_summary=previous_summary,
        return_dict=True,  # 返回字典格式 {is_valid, history_compact, ...}
        add_thinking_block=cc.compact_with_thinking_block,
        extra_instruction=extra_instruction,
    )

    # 检查压缩结果有效性
    if not result.get("is_valid", True):
        # 保存无效结果用于调试
        filepath = os.path.join(agent_config.workspace_dir, f"compact_invalid_{uuid.uuid4().hex[:8]}.json")
        with open(filepath, "w") as f:
            json.dump(result, f, ensure_ascii=False, indent=2)
        logger.error(f"Invalid compact result saved to {filepath}")
        return ""

    return result.get("history_compact", "")
```

## 4. 记忆压缩 (MemoryCompactionHook)

### 4.1 压缩时机

```python
class MemoryCompactionHook:
    """推理前钩子，检查并压缩记忆"""
    
    async def __call__(self, agent, kwargs) -> None:
        # 1. 检查上下文大小
        messages, remaining, is_valid = await agent.memory_manager.check_context()
        
        # 2. 如果需要压缩
        if not is_valid:
            # 3. 获取之前的摘要
            previous_summary = agent.memory_manager.get_previous_summary()
            
            # 4. 执行压缩
            summary = await agent.memory_manager.compact_memory(
                messages=messages,
                previous_summary=previous_summary,
            )
            
            # 5. 更新记忆
            await agent.memory_manager.replace_messages_with_summary(summary)
```

### 4.2 压缩算法

```python
async def compact_memory(
    self,
    messages: List[Msg],
    previous_summary: str = "",
    extra_instruction: str = "",
    compact_ratio: float = 0.5,
) -> str:
    """
    将大量对话压缩为简洁摘要
    
    Args:
        messages: 要压缩的消息列表
        previous_summary: 上一次压缩的摘要
        extra_instruction: 额外指令（如保留特定信息）
        compact_ratio: 压缩比例（0.0-1.0）
    """
    
    # 1. 构建压缩提示
    system_prompt = f"""你是一个记忆压缩专家。请将以下对话压缩为简洁的摘要。

压缩规则：
- 保留关键信息、决策、偏好
- 去除重复和次要细节
- 使用简洁的语言
- 压缩后保留的信息量：{int(compact_ratio * 100)}%

{f"额外的保留要求：{extra_instruction}" if extra_instruction else ""}
{f"之前的摘要：{previous_summary}" if previous_summary else ""}
"""
    
    user_prompt = "\n".join([
        f"[{msg.name}]: {msg.content}"
        for msg in messages
    ])
    
    # 2. 调用 LLM
    response = await self.chat_model.chat([
        Msg("system", system_prompt, "system"),
        Msg("user", user_prompt, "user"),
    ])
    
    return response.content
```

```python
async def dream_memory(self, **kwargs) -> None:
    """运行一次梦境记忆优化：通过智能体查询执行梦境任务"""
    logger.info("running dream-based memory optimization")

    self._prepare_model_formatter()
    agent_config = load_agent_config(self.agent_id)

    # 1. 构建梦境提示
    query_text = self._get_dream_prompt(language, current_date)

        name="DreamOptimizer",
        model=self.chat_model,
        sys_prompt="You are a Dream Memory Organizer...",
        toolkit=self.summary_toolkit,
        formatter=self.formatter,
    )

    # 4. 执行梦境
    user_msg = Msg(name="dream", role="user", content=[TextBlock(...)])
    response = await dream_agent.reply(user_msg)
```

**触发条件检查** (`_should_trigger_proactive` 函数):

```python
def _should_trigger_proactive(
    config: ProactiveConfig,
    last_time: datetime,
    now: datetime,
    time_since_last_trigger: float,
) -> bool:
    """判断是否应该触发主动响应"""

    # 1. 检查空闲时间
    idle_elapsed = (now - last_time).total_seconds() / 60
    if idle_elapsed < config.idle_minutes:
        return False

    # 2. 检查模式启用时长
    mode_elapsed = (now - config.mode_enabled_time).total_seconds() / 60
    if mode_elapsed < config.idle_minutes:
        return False

    # 3. 检查冷却时间（60 秒）
    if time_since_last_trigger < 60:
        return False

    # 4. 检查是否有运行中的任务
    if config.running_task_id is not None:
        return False

    return True
```

### 13.7 向量搜索 + 全文搜索混合机制

ReMeLightMemoryManager 支持两种搜索模式的加权融合：

| 搜索模式 | 权重 | 说明 |
|---------|------|------|
| 向量搜索 (Vector) | 0.7 | 使用嵌入模型进行语义相似度匹配 |
| BM25 全文搜索 | 0.3 | 传统关键词匹配，确保精确术语命中 |

**混合搜索实现** (`chroma_file_store.py` 第507-605行):

```python
# 1. 候选池计算
candidates = min(200, max(1, int(limit * candidate_multiplier)))
# candidate_multiplier 默认 3.0，limit=5 时最多 15 个候选

# 2. 并行执行两种搜索
vector_results = await vector_search(query, candidates)
keyword_results = await keyword_search(query, candidates)

# 3. 分数合并
for result in vector_results:
    result.score *= vector_weight  # 0.7
for result in keyword_results:
    if key in merged:
        merged[key].score += result.score * text_weight  # 0.3
    else:
        result.score = result.score * text_weight
```

**向量搜索** (第334-418行):
- 使用 ChromaDB HNSW 索引进行余弦距离计算
- 分数转换: `score = max(0.0, 1.0 - distance / 2.0)`
- 失败时回退到随机分数 (0.3-0.7)

**BM25/关键词搜索** (第420-505行):
- 使用 ChromaDB `$contains` 操作符
- 大小写不敏感（多种变体）
- 分数 = `match_count / n_words + phrase_bonus(0.2)`

### 14.5 关键差异

1. **存储后端**：QwenPaw 用 ChromaDB（嵌入式），Java 常用 PostgreSQL + pgvector
2. **压缩方式**：QwenPaw 用 LLM 动态摘要，Java 通常用固定算法
3. **搜索方式**：QwenPaw 混合搜索（向量 0.7 + BM25 0.3），Java 需要手动配置
4. **主动优化**：QwenPaw Dream 在凌晨空闲时运行，Java 用 `@Scheduled`
5. **配置方式**：QwenPaw 用 config.json，Java 用 `@ConfigurationProperties`

## 15. 总结

### 核心要点

1. **三层记忆架构**: 短期记忆(InMemoryMemory) → 长期记忆(ReMeLightMemoryManager) → 主动优化(Dream)
2. **ReMeLight 引擎**: 结合向量搜索(0.7权重)和BM25全文搜索(0.3权重)的混合检索
3. **记忆压缩**: MemoryCompactionHook 在上下文接近上限时自动触发压缩
4. **Dream 优化**: AI 驱动的记忆整理，在空闲时执行去冗并状态覆写
5. **主动记忆**: ProactiveTrigger 在用户空闲时主动生成响应

### 关键配置

| 配置项 | 说明 |
|--------|------|
| `compact_threshold` | 触发压缩的剩余空间比例 (默认 0.2) |
| `compact_ratio` | 压缩后的保留比例 (默认 0.5) |
| `enable_dream` | 是否启用 Dream 优化 |
| `dream_trigger_hours` | Dream 触发小时 (默认 [2,3,4]) |
| `enable_proactive` | 是否启用主动记忆 |
| `proactive_idle_minutes` | 主动触发空闲阈值 (默认 30分钟) |

### 故障排查流程

```
记忆搜索无结果
    │
    ├─► 检查向量索引: ~/.qwenpaw/workspaces/<agent>/memory/embeddings/

    │
    ├─► 检查 enable_dream: 配置中是否为 true
    │
```

## ★ Insight ─────────────────────────────────────
**Dream 为什么在深夜执行**：默认 `dream_cron: "0 23 * * *"` 设置在23:00，是因为此时用户不太可能使用系统，AI 对记忆的修改不会与用户对话产生上下文冲突。梦境执行时会创建临时的 `DreamOptimizer` Agent，这个 Agent 的系统提示词是专门为记忆整理优化的。

**压缩不是删除**：当上下文快要满时，`compact_memory` 会把旧消息压缩成摘要，而不是删除。摘要保留了关键信息（如决策、结论），丢弃了过程细节。这是为什么长时间运行的任务不会丢失"记忆"，只是变得更浓缩。

**记忆搜索不是向量检索**：虽然底层用了向量相似度，但 `memory_search` 主要在 Markdown 文件上做全文搜索加语义排序，不是严格的向量数据库查询。文件格式（Markdown）使得搜索结果可以直接展示给用户，无需额外转换。
