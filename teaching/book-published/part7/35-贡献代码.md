## 1. 贡献流程概述

### 1.1 完整流程

```
1. Fork 项目
       ↓
2. Clone 到本地
       ↓
3. 创建功能分支
       ↓
4. 编写代码
       ↓
5. 运行测试
       ↓
6. 提交 Commit
       ↓
7. Push 到你的仓库
       ↓
8. 创建 Pull Request
       ↓
9. Code Review
       ↓
10. 合并到主仓库
```

### 1.2 贡献类型

| 类型 | 说明 | 示例 |
|------|------|------|
| **代码** | 新功能或修复 | 添加新渠道支持 |
| **文档** | 改进文档 | 修复错别字 |
| **测试** | 增加测试 | 添加单元测试 |
| **Bug 报告** | 问题反馈 | Issue 中报告 Bug |
| **建议** | 功能建议 | Issue 中提出建议 |

## 2. 创建 Pull Request

### 2.1 准备工作

确保：
- 你的代码基于最新代码
- 所有测试通过
- 代码符合规范
- 提交信息清晰

### 2.2 创建 PR

1. 访问你的 GitHub 仓库
2. 点击「Compare & pull request」
3. 填写 PR 模板
4. 提交 PR

### 2.3 PR 模板

```markdown
## 描述
<!-- 简要说明这个 PR 做什么 -->

## 类型
- [ ] 新功能 (Feature)
- [ ] Bug 修复 (Bug fix)
- [ ] 文档更新 (Documentation)
- [ ] 代码重构 (Refactoring)
- [ ] 测试 (Tests)

## 涉及模块
<!-- 这个 PR 影响哪些模块 -->

## 测试
<!-- 如何测试这个 PR -->

## Checklist
- [ ] 代码遵循项目规范
- [ ] 添加了必要的测试
- [ ] 所有测试通过
- [ ] 文档已更新（如需要）
```

## 3. 代码规范

### 3.1 Python 代码规范

QwenPaw 使用以下工具：

| 工具 | 用途 |
|------|------|
| **Black** | 代码格式化 |
| **Ruff** | Linting（替代 Flake8） |
| **mypy** | 类型检查 |

### 3.2 代码风格

**命名规范**：

```python
# 变量和函数：小写下划线
user_name = "小明"
def get_user_info():
    pass

# 类名：首字母大写
class UserProfile:
    pass

# 常量：全大写下划线
MAX_RETRY_COUNT = 3

# 私有属性：前导下划线
class User:
    def __init__(self):
        self._internal = 123  # 私有
```

### 3.3 导入顺序

```python
# 1. 标准库
import os
import sys
from typing import Dict, List

# 2. 第三方库
import httpx
from fastapi import APIRouter

# 3. 本地导入（相对导入）
from ..utils import helper

# 分组之间空一行
```

### 3.4 文档字符串

```python
def calculate_area(radius: float) -> float:
    """计算圆的面积。

    Args:
        radius: 圆的半径

    Returns:
        圆的面积

    Raises:
        ValueError: 如果半径为负数
    """
    if radius < 0:
        raise ValueError("半径不能为负数")
    return 3.14 * radius ** 2
```

## 4. 编写测试

### 4.1 测试结构

```python
# tests/test_example.py

import pytest
from qwenpaw.example import MyClass

class TestMyClass:
    """测试 MyClass"""

    def setup_method(self):
        """每个测试方法前调用"""
        self.instance = MyClass()

    def teardown_method(self):
        """每个测试方法后调用"""
        self.instance = None

    def test_basic(self):
        """基本功能测试"""
        result = self.instance.process()
        assert result is not None

    @pytest.mark.asyncio
    async def test_async(self):
        """异步功能测试"""
        result = await self.instance.async_process()
        assert result == expected_value
```

### 4.2 测试命名

```python
class TestUserProfile:
    def test_get_name_returns_correct_value(self):
        """测试获取名称返回正确值"""
        pass

    def test_set_age_with_negative_raises_error(self):
        """测试设置负数年龄会抛出错误"""
        pass
```

### 4.3 测试覆盖率

```bash
# 查看覆盖率
pytest --cov=src/qwenpaw --cov-report=html

# 最低覆盖率要求
# 每个新功能至少 80% 覆盖
```

## 5. Commit 规范

### 5.1 Commit 信息格式

```
<类型>(<模块>): <简短描述>

[可选的详细描述]

[可选的脚注]
```

### 5.2 类型

| 类型 | 说明 |
|------|------|
| `feat` | 新功能 |
| `fix` | Bug 修复 |
| `docs` | 文档 |
| `style` | 格式（不影响功能） |
| `refactor` | 重构 |
| `test` | 测试 |
| `chore` | 构建/工具 |

### 5.3 示例

```bash
# 好例子
git commit -m "feat(agent): add memory consolidation hook

- Add on_memory_consolidate hook
- Support periodic Dream operation
- Add config option for consolidation interval"

# 坏例子
git commit -m "fix stuff"
git commit -m "update"
```

## 6. Code Review

### 6.1 Review 流程

```
1. 作者提交 PR
2. 维护者/贡献者 Review
3. 提出问题或建议
4. 作者修改
5. 重复直到 approved
6. 合并
```

### 6.2 作为 Reviewer

**要做的**：
- 检查代码逻辑
- 验证测试覆盖
- 确保文档完整
- 提出建设性建议

**不要做的**：
- 人身攻击
- 吹毛求疵
- 拒绝解释原因

### 6.3 常用 Review 短语

| 短语 | 含义 |
|------|------|
| `LGTM` | Looks Good To Me，可以合并 |
| `nit:` | 小问题，不阻止合并 |
| `suggestion:` | 建议，不是必须 |
| `question:` | 有疑问需要澄清 |
| `blocking:` | 必须解决才能合并 |

## 7. 常见问题

### 7.1 如何处理冲突？

```bash
# 1. 拉取最新代码
git fetch upstream

# 2. 切换到你的分支
git checkout feature/my-feature

# 3. 变基到 main
git rebase upstream/main

# 4. 解决冲突
# 编辑冲突文件
git add .
git commit

# 5. 强制推送
git push --force
```

### 7.2 PR 太大了怎么办？

拆分 PR：
- 按功能拆分
- 按模块拆分
- 先提交基础重构，再提交业务逻辑

### 7.3 Review 通过后做什么？

1. 确保所有 CI 通过
2. 等待维护者合并
3. 删除你的分支（可选）
