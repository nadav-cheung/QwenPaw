> **一句话概述**：本章深入分析 QwenPaw 的应用生命周期管理，包括两阶段启动（Phase 1 同步快速响应 + Phase 2 后台初始化）、优雅关闭的四个步骤和信号处理机制，帮助读者理解零停机部署的实现原理。

## 概述

QwenPaw 的生命周期管理覆盖应用启动、Agent 运行和关闭的全流程，通过两阶段启动和优雅关闭实现零停机部署。

## 1. 两阶段启动

源码路径：`src/qwenpaw/app/_app.py:219`

### 1.1 Phase 1（同步，<100ms）

快速响应用户请求：

```python
# src/qwenpaw/app/_app.py:219
@asynccontextmanager
async def lifespan(app: FastAPI):
    startup_start_time = time.time()
    add_project_file_handler(LOG_FILE_PATH)

    # ================================================================
    # Phase 1: Fast synchronous setup (target < 100ms)
    # ================================================================

    auto_register_from_env()

    # 遥测收集（可选）
    if not is_telemetry_opted_out(WORKING_DIR):
        collect_and_upload_telemetry(WORKING_DIR)

    # 迁移检查
    migrate_legacy_workspace_to_default_agent()
    ensure_default_agent_exists()
    migrate_legacy_skills_to_skill_pool()
    ensure_qa_agent_exists()

    # 创建核心管理器（无 I/O，即时完成）
    multi_agent_manager = MultiAgentManager()
    provider_manager = ProviderManager.get_instance()
    local_model_manager = LocalModelManager.get_instance()

    # 暴露到端点（必须在第一个请求到达前设置）
    app.state.multi_agent_manager = multi_agent_manager
    app.state.provider_manager = provider_manager
    app.state.local_model_manager = local_model_manager
    app.state.plugin_loader = None
    app.state.plugin_registry = None

    fast_elapsed = time.time() - startup_start_time
    logger.info(f"Server ready in {fast_elapsed:.3f}s")

    yield  # FastAPI 启动完成，响应请求

    # ================================================================
    # Phase 2: Background heavy initialization
    # ================================================================
    await _background_startup()
```

### 1.2 Phase 2（后台）

不阻塞请求处理：

```python
# src/qwenpaw/app/_app.py:296
async def _background_startup():
    # 1. 启动所有配置的 Agent（真正并行）
    await multi_agent_manager.start_all_configured_agents()

    # 2. 本地模型恢复
    provider_manager.start_local_model_resume(local_model_manager)

    # 3. 插件系统
    plugin_loader = PluginLoader(plugin_dirs)
    loaded_plugins = await plugin_loader.load_all_plugins(configs=plugin_configs)

    # 4. 注册插件 Provider
    for provider_id, provider_reg in plugin_loader.registry.get_all_providers().items():
        provider_manager.register_plugin_provider(...)

    # 5. 注册插件控制命令
    for cmd_reg in control_commands:
        register_command(cmd_reg.handler)
        command_registry.register_command(...)

    # 6. 执行插件 Startup Hooks
    for hook in plugin_loader.registry.get_startup_hooks():
        result = hook.callback()
        if inspect.iscoroutine(result) or inspect.isawaitable(result):
            await result

    # 7. 审批服务设置
    get_approval_service().set_channel_manager(default_agent.channel_manager)
```

## 2. 优雅关闭

源码路径：`src/qwenpaw/app/_app.py:449`

### 2.1 关闭流程

```python
# src/qwenpaw/app/_app.py:455
try:
    yield
finally:
    # 1. 取消后台启动任务（如仍在运行）
    if not _bg_task.done():
        _bg_task.cancel()
        await _bg_task

    # 2. 执行插件关闭钩子
    plugin_registry = app.state.plugin_registry
    if plugin_registry is not None:
        for hook in plugin_registry.get_shutdown_hooks():
            result = hook.callback()
            if iscoroutine(result):
                await result

    # 3. 关闭本地模型服务器
    local_model_mgr = app.state.local_model_manager
    if local_model_mgr is not None:
        await local_model_mgr.shutdown_server()
        local_model_mgr.shutdown_server_sync()  # 同步回退

    # 4. 停止 MultiAgentManager（停止所有 Agent）
    multi_agent_mgr = app.state.multi_agent_manager
    if multi_agent_mgr is not None:
        await multi_agent_mgr.stop_all()

    logger.info("Application shutdown complete")
```

### 2.2 关闭钩子执行顺序

| 步骤 | 操作 | 说明 |
|------|------|------|
| 1 | 取消后台启动任务 | 如 `_background_startup` 仍在运行 |
| 2 | 执行插件关闭钩子 | 按 priority 排序 |
| 3 | 关闭本地模型服务器 | 异步+同步双重回退 |
| 4 | 停止 MultiAgentManager | 停止所有 Agent 及组件 |

### 2.3 插件关闭钩子

```python
# 插件关闭钩子按 priority 排序执行
for hook in plugin_registry.get_shutdown_hooks():
    try:
        result = hook.callback()
        if inspect.iscoroutine(result) or inspect.isawaitable(result):
            await result
    except Exception as e:
        logger.error(f"✗ Failed shutdown hook: {hook.hook_name}")
```

## 3. 信号处理

### 3.1 捕获的信号

| 信号 | 说明 | 处理 |
|------|------|------|
| SIGTERM | 终止请求 | 优雅关闭 |
| SIGINT | Ctrl+C | 优雅关闭 |
| SIGHUP | 终端关闭 | 忽略，保持运行 |

### 3.2 配置示例

```python
import signal
import sys

def setup_signal_handlers():
    """设置信号处理器"""
    signal.signal(signal.SIGTERM, _handle_shutdown)
    signal.signal(signal.SIGINT, _handle_shutdown)

    # 忽略 SIGHUP（终端关闭）
    signal.signal(signal.SIGHUP, signal.SIG_IGN)
```

### 4.1 等待所有任务完成

```python
# src/qwenpaw/app/runner/task_tracker.py:83
async def wait_all_done(self, timeout: float = 300.0) -> bool:
    """Wait for all active tasks to complete (default 5min timeout)."""
    async def _wait_loop() -> None:
        while await self.has_active_tasks():
            await asyncio.sleep(0.5)
    try:
        await asyncio.wait_for(_wait_loop(), timeout=timeout)
        return True
    except asyncio.TimeoutError:
        return False
```

## 7. 最佳实践

### 7.1 后台任务超时设置

## 8. 常见问题

### 8.1 Phase 2 后台任务卡住

**问题**：服务器启动后，后台初始化长时间未完成。

**原因**：某个插件或 Agent 启动阻塞。

**解决**：
1. 检查日志中的 Phase 2 进度
2. 使用 `qwenpaw doctor` 检查配置
3. 减少同时启动的 Agent 数量

### 8.2 SIGTERM 未触发关闭

**问题**：容器收到 SIGTERM 但进程未退出。

**原因**：未正确传递信号给 Python 进程。

**解决**：确保 Dockerfile 中使用 `exec` 替换进程：
```dockerfile
CMD ["python", "-m", "qwenpaw", "app"]
# 而非
CMD python -m qwenpaw app  # 这会创建 shell 进程
```

### 8.3 会话状态丢失

**问题**：重启后用户会话丢失。

**原因**：`save_session_state` 未被调用或异步写入失败。

**解决**：检查 `SafeJSONSession` 的错误日志，确保 `aiofiles` 正常工作。

## 🐍 来自 Java 的你

### 核心概念对照

| Java | Python / QwenPaw | 说明 |
|------|-------------------|------|
| Servlet 生命周期 (init/service/destroy) | Agent 生命周期 (startup/running/shutdown) | Servlet 容器管理 init→service→destroy；QwenPaw 通过两阶段启动和优雅关闭管理生命周期 |
| @PostConstruct | startup hook (Phase 1) | @PostConstruct 在依赖注入完成后执行；QwenPaw 的 Phase 1 在应用就绪前完成核心初始化 |
| @PreDestroy | shutdown hook | @PreDestroy 在 Bean 销毁前回调；QwenPaw 通过 signal handler 注册关闭钩子 |
| ContextLoaderListener | 两阶段启动 | ContextLoaderListener 在 Servlet 容器启动时初始化 Spring 根上下文；QwenPaw 的两阶段启动将关键路径与后台任务分离 |
| Spring Boot ApplicationRunner | startup 事件 | ApplicationRunner 在 Spring 上下文就绪后执行；QwenPaw 的 Phase 2 在后台异步执行非关键初始化 |

### 关键差异

Spring Boot 的启动是单阶段的——ApplicationContext 完全就绪后应用才开始接受请求。QwenPaw 采用两阶段启动设计：Phase 1 在 500ms 内完成核心初始化并开始监听，Phase 2 在后台异步完成隧道、探测等非关键任务。这意味着 QwenPaw 在启动后可能部分功能尚未就绪，是典型的"快速可用、渐进就绪"策略。

## 8. Contributor 指南

### 8.1 适合新手修改的文件

| 文件 | 难度 | 原因 |
|------|------|------|
| `app/_app.py` 的日志配置部分 | ⭐ | 日志配置相对独立，危险低 |
| `app/workspace/service_manager.py` 的启动顺序 | ⭐⭐ | 需要理解服务依赖关系 |
| 插件钩子注册顺序 | ⭐⭐ | 涉及加载顺序，影响启动稳定性 |
| 信号处理逻辑 | ⭐⭐⭐ | 需要理解进程生命周期 |

### 8.2 危险区域

| 文件/模块 | 危险原因 |
|-----------|----------|
| `lifespan()` 的 Phase 1 逻辑 | 错误导致应用无法启动 |
| `shutdown()` 的四个步骤顺序 | 错误导致资源泄漏或连接断开 |
| SIGHUP/SIGINT 处理 | 错误导致无法优雅关闭 |
| `auto_register_from_env()` | 可能重复注册或漏注册 |

### 8.4 如何避免破坏架构

**启动顺序规范**：
- Phase 1 必须完成核心管理器创建，但不执行 I/O 操作
- Phase 2 的后台任务必须可取消
- 关闭时先停止接受新请求，再等待现有任务完成

**信号处理规范**：
- SIGTERM 用于优雅关闭
- SIGINT (Ctrl+C) 用于前台关闭
- SIGHUP 应被忽略（不支持热重载）
