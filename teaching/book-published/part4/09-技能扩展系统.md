## 1. Skills 系统设计理念

### 1.1 设计目标

QwenPaw 的 Skills 系统旨在为智能体提供**可插拔、可扩展**的能力增强机制。核心设计理念包括：

| 特性 | 说明 |
|------|------|
| **模块化** | 每个 Skill 是独立的目录包，包含完整的描述和脚本 |
| **安全优先** | 所有 Skill 必须通过安全扫描才能激活 |
| **多渠道支持** | Skill 可配置在特定渠道（console、discord、telegram 等）生效 |
| **版本管理** | 支持内置 Skill 的版本追踪和更新 |
| **全球化** | 支持多语言 Skill（en/zh）变体 |

### 1.2 架构概览

```
┌─────────────────────────────────────────────────────────────┐
│                     Skills Hub                              │
│              (clawhub.ai / LobeHub / GitHub)               │
└─────────────────────────┬───────────────────────────────────┘
                          │ 安装/同步
┌─────────────────────────▼───────────────────────────────────┐
│                   Skill Pool                                │
│              (~/.qwenpaw/skill_pool/)                       │
│    ┌─────────────────────────────────────────────────┐      │
│    │  skill_name/                                   │      │
│    │  ├── SKILL.md        # Skill 主描述文件         │      │
│    │  ├── references/     # 参考文档                  │      │
│    │  └── scripts/       # Python 脚本              │      │
│    └─────────────────────────────────────────────────┘      │
└─────────────────────────┬───────────────────────────────────┘
                          │ 下载到工作空间
┌─────────────────────────▼───────────────────────────────────┐
│                Workspace Skills                              │
│           (workspaces/{agent_id}/skills/)                   │
└─────────────────────────────────────────────────────────────┘
```

### 1.3 核心组件

| 组件 | 文件路径 | 职责 |
|------|----------|------|
| `SkillService` | `agents/skills_manager.py` | 工作空间级别的 Skill 生命周期管理 |
| `SkillPoolService` | `agents/skills_manager.py` | 共享 Skill 池管理 |
| `SkillScanner` | `security/skill_scanner/scanner.py` | 安全扫描编排器 |
| `PatternAnalyzer` | `security/skill_scanner/analyzers/pattern_analyzer.py` | 正则签名模式匹配分析器 |
| `SkillsHub` | `agents/skills_hub.py` | Skill 市场客户端 |

## 2. SKILL.md 格式规范

### 2.1 文件结构

每个 Skill 的核心是 `SKILL.md` 文件，采用 **Frontmatter** 格式：

```markdown
---
name: pdf
description: "使用此技能处理所有 PDF 相关任务..."
license: Proprietary
metadata:
  builtin_skill_version: "1.1"
  qwenpaw:
    emoji: "📄"
    requires: {}
---

# PDF 处理指南

技能详细描述和使用说明...
```

### 2.2 Frontmatter 字段说明

| 字段 | 类型 | 必需 | 说明 |
|------|------|------|------|
| `name` | string | 是 | Skill 唯一标识符 |
| `description` | string | 是 | 技能功能描述，会展示给用户 |
| `metadata.version` | string | - | 内置技能版本号 |
| `metadata.qwenpaw.emoji` | string | - | UI 显示的表情符号 |
| `metadata.qwenpaw.requires` | object | - | 依赖环境变量或二进制工具 |

### 2.3 多语言支持

内置 Skill 采用 `-en` / `-zh` 后缀区分语言版本：

```
skills/
├── pdf-en/           # 英文版
│   └── SKILL.md
├── pdf-zh/           # 中文版
│   └── SKILL.md
├── docx-en/
└── docx-zh/
```

系统会根据用户界面语言偏好自动选择对应版本。

## 3. Skill 生命周期管理

### 3.1 SkillService - 工作空间级别管理

`SkillService` 负责单个工作空间内的 Skill 管理：

```python
from pathlib import Path
from agents.skills_manager import SkillService

workspace_dir = Path("workspaces/agent_001")
service = SkillService(workspace_dir)

# 列出所有 Skill
skills = service.list_all_skills()

# 创建新 Skill
service.create_skill(
    name="my_skill",
    content=skill_md_content,
    references={"guide.md": "# Guide..."},
    scripts={"process.py": "print('hello')"},
)

# 启用/禁用 Skill
service.enable_skill("my_skill")
service.disable_skill("my_skill")

# 设置渠道路由
service.set_skill_channels("my_skill", channels=["discord", "telegram"])

# 保存 Skill（编辑）
service.save_skill(
    skill_name="my_skill",
    content=updated_content,
)

# 删除 Skill
service.delete_skill("my_skill")
```

### 3.2 SkillPoolService - 共享池管理

`SkillPoolService` 管理全局共享的 Skill 池：

```python
from agents.skills_manager import SkillPoolService

pool = SkillPoolService()

# 列出池中所有 Skill
all_skills = pool.list_all_skills()

# 从工作空间上传到池
pool.upload_from_workspace(
    workspace_dir=Path("workspaces/agent_001"),
    skill_name="custom_skill",
)

# 从池下载到工作空间
pool.download_to_workspace(
    skill_name="shared_docx",
    workspace_dir=Path("workspaces/agent_002"),
)
```

### 6.3 创建 Python 脚本

在 `scripts/` 目录中创建可执行脚本：

```python
#!/usr/bin/env python3
# scripts/process.py
"""自定义数据处理脚本"""

import json
import sys
from pathlib import Path


def process_file(input_path: str, output_path: str) -> dict:
    """处理输入文件并生成输出"""
    with open(input_path, 'r') as f:
        data = json.load(f)

    # 处理逻辑
    result = {
        "status": "success",
        "records": len(data),
        "data": data[:10]  # 限制返回前10条
    }

    with open(output_path, 'w') as f:
        json.dump(result, f, indent=2)

    return result


if __name__ == "__main__":
    if len(sys.argv) < 3:
        print("Usage: process.py <input.json> <output.json>")
        sys.exit(1)

    input_file = sys.argv[1]
    output_file = sys.argv[2]

    result = process_file(input_file, output_file)
    print(json.dumps(result, indent=2))
```

## 7. Skill 安全扫描机制

### 7.1 扫描架构

**源码路径**: `src/qwenpaw/security/skill_scanner/`

**PatternAnalyzer** (`analyzers/pattern_analyzer.py` 第236-260行):

```python
class PatternAnalyzer(BaseAnalyzer):
    """基于 YAML 正则签名的模式匹配分析器"""

    def __init__(self, rules_path: Path | None = None, *, policy: ScanPolicy | None = None) -> None:
        super().__init__(name="pattern", policy=policy)
        loader = RuleLoader(rules_path)
        self._rules = loader.load_rules()

    def analyze(self, skill_dir: Path, files: list[SkillFile],
                *, skill_name: str | None = None) -> list[Finding]:
        findings: list[Finding] = []
        for sf in files:
            content = sf.read_content()
            is_doc = self.policy.is_doc_path(sf.relative_path)
            applicable = self._get_rules(sf.file_type)
            for rule in applicable:
                if self.policy.is_rule_disabled(rule.id):
                    continue
                matches = rule.scan_content(content, file_path=sf.relative_path)
                for match in matches:
                    severity = rule.severity
                    override = self.policy.get_severity_override(rule.id)
                    if override:
                        severity = Severity(override)
                    findings.append(Finding(...))
        return findings
```

## 8. 最佳实践

### 8.1 Skill 编写规范

1. **描述清晰**：Frontmatter 的 `description` 应准确说明技能用途
2. **代码安全**：避免在 SKILL.md 中直接编写可执行代码
3. **版本管理**：更新内置 Skill 时递增 `builtin_skill_version`
4. **依赖声明**：明确声明所需的环境变量和命令行工具

### 8.2 安全注意事项

1. **不信任用户输入**：所有通过 Skill 脚本处理的数据都应验证
2. **限制文件访问**：使用 `references/` 而非直接文件路径
3. **敏感信息**：避免在 Skill 中硬编码密钥，使用环境变量注入
4. **沙箱执行**：考虑在受限环境中执行未验证的 Skill 脚本

### 8.3 性能优化

| 问题 | 解决方案 |
|------|----------|
| 扫描超时 | 配置文件限制 `timeout: 30` |
| 大文件 | 在 `ScanPolicy.file_limits` 设置 `max_file_size_bytes` |
| 频繁扫描 | 启用 mtime 缓存（自动生效） |
| 规则过多 | 使用 `rule_scoping` 禁用不需要的规则 |

| 错误 | 原因 | 解决方案 |
|------|------|----------|
| `SkillsError: SKILL.md missing` | 未找到 SKILL.md 文件 | 确保 Skill 目录包含 SKILL.md |
| `SkillScanError: CRITICAL findings` | 安全扫描失败 | 检查并修复安全问题或加入白名单 |
| `SkillConflictError` | Skill 名称冲突 | 使用 `suggest_conflict_name()` 获取建议名称 |
| `ImportError: No file locking module` | 缺少锁文件模块 | 确保系统安装了 `fcntl` (Linux/macOS) 或 `msvcrt` (Windows) |

## 来自 Java 的你

### 核心概念对照

| Java | Python / QwenPaw | 说明 |
|------|-------------------|------|
| Java SPI (`ServiceLoader`) | Skill 插件系统 | QwenPaw 的 Skill 通过目录结构 + `SKILL.md` 声明，无需 `META-INF/services/` 文件 |
| `ServiceLoader<Skill>` | `SkillLoader` / `SkillService` | QwenPaw 按 `SKILL.md` 的 Frontmatter 自动发现和加载技能 |
| `@Service` / `@Component` | Skill 装饰器 / 配置 | Skill 的注册通过 `SkillService` API 完成，而非 Spring 组件扫描 |
| OSGi Bundle | Skill 目录 | Skill 是包含 `SKILL.md` + 脚本的目录，无需 MANIFEST.MF 或 Bundle-Activator |
| `META-INF/services/` | `SKILL.md` | QwenPaw 用 Markdown Frontmatter 声明技能元数据，比 SPI 配置文件更可读 |

### 关键差异

Java SPI 需要在 `META-INF/services/` 中创建以接口全限定名命名的文件，QwenPaw 的 Skill 只需一个 `SKILL.md` 文件加目录结构。Skill 的安装、启用、禁用都通过 API 或 CLI 完成，不需要 OSGi 那样的类加载器隔离。

## 8. Contributor 指南

### 8.1 适合新手修改的文件

| 文件 | 难度 | 原因 |
|------|------|------|
| `src/qwenpaw/agents/skills/` 内置 Skill | ⭐ | 内置 Skill 结构简单，测试容易 |
| `SKILL.md` 文档优化 | ⭐ | 纯文档工作，无代码风险 |
| 新增 Skill 触发词 | ⭐⭐ | 修改触发词映射，逻辑简单 |
| `skills_hub.py` 的 Hub 适配器 | ⭐⭐ | 需要理解各 Hub API 格式 |

### 8.2 危险区域

| 文件/模块 | 危险原因 |
|-----------|----------|
| `skills_manager.py` 的 manifest 写入逻辑 | 错误可能损坏用户配置 |
| `skill_scanner.py` 的扫描规则 | 错误的规则可能漏过恶意代码或误杀正常 Skill |
| `_normalize_bundle()` | 错误可能允许路径遍历攻击 |

### 8.3 调试方法

**启用调试日志**
```python
import logging

logging.getLogger("qwenpaw.security.skill_scanner").setLevel(logging.DEBUG)
```

**测试 Skill 安装**
```bash
# 使用 --no-scan 跳过扫描快速测试
qwenpaw skills install my_skill --from-path ./my_skill --no-scan

# 查看 Skill 状态

```

### 8.4 添加新 Skill 的标准流程

1. **创建 Skill 目录结构**
```
my_skill/
├── SKILL.md
├── references/
└── scripts/
    └── __init__.py
```

2. **编写 SKILL.md**（参考 2.1 节格式）

3. **安全自检**
```bash
python -c "from qwenpaw.security.skill_scanner import scan_skill_directory; print(scan_skill_directory('./my_skill'))"
```

4. **提交 PR** 包含：
   - Skill 源码
   - 单元测试（如有）
   - 更新文档

### 8.5 如何避免破坏架构

**Skill 发现机制**：
- 不要直接修改 `skill_pool/` 目录下的文件，通过 API 操作
- manifest 是自动生成的，不要手动编辑

**扫描器规则**：
- 添加新规则时必须在测试用例中覆盖
- 规则变更需要至少两个 Maintainer 批准
