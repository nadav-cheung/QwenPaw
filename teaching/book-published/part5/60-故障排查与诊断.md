## 1. qwenpaw doctor 命令

源码路径：`src/qwenpaw/cli/doctor_cmd.py:339`

### 1.1 命令结构

```bash
# 只读检查
qwenpaw doctor

# 修复操作（需确认）
qwenpaw doctor fix

# 预览修复计划（不写入）
qwenpaw doctor fix --dry-run

# 指定修复项
qwenpaw doctor fix --only ensure-working-dir,ensure-workspace-dirs
```

### 1.2 检查类别

| 类别 | 检查项 |
|------|--------|
| Environment | Python 版本、环境变量 |
| Config | config.json 有效性 |
| Agents | Workspace、Profiles、enabled agents |
| Channels | 已启用渠道凭证 |
| MCP | MCP 客户端配置 |
| Skills | 技能布局 |
| Security | 安全基线 |
| Memory | 嵌入配置 |
| Workspace |  Hygiene 清洁度 |
| Cron | jobs.json 有效性 |
| API | health/version 端点 |

### 1.3 Doctor Fix ID 列表

## 4. 常见故障排查

### 4.1 工作目录问题

```bash
# 问题：WORKING_DIR 不存在或不可写
# 解决：
qwenpaw doctor fix --dry-run --only ensure-working-dir
qwenpaw doctor fix --only ensure-working-dir
```

**诊断检查项**：
- `~/.qwenpaw` 目录是否存在
- 目录权限是否可写
- 磁盘空间是否充足

### 4.2 Agent 配置问题

```bash
# 问题：agent.json 缺失或损坏
# 解决：
qwenpaw doctor fix --dry-run --only seed-missing-agent-json,reset-invalid-agent-json
```

**诊断检查项**：
- `agent.json` 是否存在
- JSON 格式是否有效
- `profiles` 字段是否完整

### 4.3 模型连接问题

```bash
# 问题：LLM 不可达
# 排查：
qwenpaw models list  # 列出配置的模型
qwenpaw doctor --deep  # 深度检查（包括网络连通性）

# 手动测试连接
curl -X POST http://localhost:8000/api/config/providers/{provider}/check \
  -d '{"model": "gpt-4"}'
```

**常见原因**：
1. API Key 配置错误或过期
2. 网络无法访问境外服务
3. 模型名称拼写错误
4. 账户余额不足

### 4.4 Console 静态文件缺失

```bash
# 问题：index.html 不存在
# 解决：
qwenpaw doctor fix --dry-run --only rebuild-console-npm
cd console && npm ci && npm run build
```

### 4.5 Cron 任务配置错误

```bash
# 问题：jobs.json 格式错误
# 检查：
qwenpaw doctor --only validate-all-jobs-json

# 修复：
qwenpaw doctor fix --only normalize-jobs-cron
```

**常见 cron 格式错误**：
- 字段数量不对（应为 5 或 6）
- 分钟值超出 0-59
- 小时值超出 0-23

### 4.6 渠道凭证缺失

```bash
# 问题：渠道启动失败，凭证不完整
# 检查渠道配置：
qwenpaw channels list

# 常见缺失凭证：
# - Telegram: BOT_TOKEN
# - Discord: BOT_TOKEN, GUILD_ID
# - Feishu: APP_ID, APP_SECRET
```

## 5. 日志分析

### 5.1 日志文件位置

```python
# 默认日志路径
LOG_FILE_PATH = "~/.qwenpaw/logs/qwenpaw.log"
```

### 5.2 日志级别配置

```bash
# 设置日志级别
export QWENPAW_LOG_LEVEL=DEBUG

# 或在 config.json 中配置
{
  "logging": {
    "level": "DEBUG",
    "file": "~/.qwenpaw/logs/qwenpaw.log"
  }
}
```

### 5.3 常见错误关键字

| 关键字 | 可能原因 |
|--------|----------|
| `ConnectionTimeout` | 网络超时，服务不可达 |
| `AuthenticationError` | 认证失败，Token 过期 |
| `PermissionDenied` | 权限不足，文件不可写 |
| `FileNotFoundError` | 配置文件缺失 |
| `JSONDecodeError` | 配置文件格式错误 |

## 🐍 来自 Java 的你

### 核心概念对照

| Java | Python / QwenPaw | 说明 |
|------|-------------------|------|
| jstack (Thread Dump) | qwenpaw doctor | jstack 打印线程堆栈定位死锁和阻塞；qwenpaw doctor 全面检查配置、连接、依赖状态 |
| jmap (Heap Dump) | 日志分析 | jmap 导出堆内存分析内存泄漏；QwenPaw 通过结构化日志定位 Token 溢出、连接异常等问题 |
| VisualVM / JConsole | 内置诊断面板 | VisualVM 需要独立 GUI 工具连接 JMX；QwenPaw 将诊断功能直接内嵌为 CLI 子命令 |
| Arthas (阿里开源诊断) | qwenpaw 调试命令 | Arthas 通过字节码增强实现运行时诊断；QwenPaw 通过 doctor 命令和日志体系提供诊断能力 |
| Thread Dump / CPU Flame Graph | 状态检查 (doctor check) | Java 通过线程转储和火焰图分析性能瓶颈；QwenPaw 通过分类检查项逐项验证各模块健康状态 |

### 关键差异

Java 应用的故障排查通常依赖独立的 JVM 工具链（jstack/jmap/Arthas），需要额外的工具安装和 JMX 连接配置。QwenPaw 将诊断能力内置为 `qwenpaw doctor` 命令，一条命令即可完成配置验证、连接测试、依赖检查等多项诊断，还支持 `--dry-run` 预览和 `fix` 自动修复，开箱即用程度更高。
