## 概述

QwenPaw 在模型首次使用时通过实际探测判断其多模态能力（图像/视频/音频支持），结果缓存供后续路由使用，避免重复探测开销。通过 ExpectedCapabilityRegistry 维护所有内置模型的预期能力，与实际探测结果对比，检测文档偏差。

**核心设计目标：**
- **零配置：** 新增模型无需手动标注多模态能力
- **准确性：** 实际 API 探测确保能力判断准确
- **高效性：** 探测结果缓存，避免重复探测开销
- **可观测性：** 偏差记录帮助发现文档与实际的差异

## 4. 探测评估函数

源码路径：`src/qwenpaw/providers/multimodal_prober.py:114`

### 4.1 图像探测评估

```python
# src/qwenpaw/providers/multimodal_prober.py:114
def evaluate_image_probe_answer(
    answer: str,
    model_id: str,
    start_time: float,
    reasoning: str = "",
) -> tuple[bool, str]:
    """Shared evaluation for image color-probe answers.

    Returns ``(supported, message)`` tuple.
    """
    answer = answer.lower().strip()
    reasoning = reasoning.lower().strip()

    # 检查回答中是否包含红色系关键词
    if any(kw in answer for kw in _RED_KW):
        elapsed = time.monotonic() - start_time
        logger.info(f"Image probe done: model={model_id} result=True {elapsed:.2f}s")
        return True, f"Image supported (answer={answer!r})"

    # 也检查 reasoning 中是否有红色系关键词
    if reasoning and any(kw in reasoning for kw in _RED_KW):
        return True, f"Image supported (reasoning, answer={answer!r})"

    return False, f"Model did not recognise image (answer={answer!r})"
```

### 4.2 错误关键词检测

```python
# src/qwenpaw/providers/multimodal_prober.py:89
def _is_media_keyword_error(exc: Exception) -> bool:
    """Check if exception message contains media-related keywords.

    用于快速判断是否是媒体不支持错误，
    而非其他类型的 API 错误。
    """
    error_str = str(exc).lower()
    keywords = [
        "image", "video", "vision", "multimodal",
        "image_url", "video_url", "does not support",
    ]
    return any(kw in error_str for kw in keywords)
```

## 6. 探测流程

### 6.1 首次探测流程

```
模型首次使用
    │
    ▼
检查缓存中是否有 probe_source
    │
    ├── probe_source = probed → 直接使用缓存结果
    │
    └── probe_source = null/unknown → 执行实际 API 探测
              │
              ▼
        探测完成
              │
              ▼
        比较与 ExpectedCapabilityRegistry 的差异
              │
              ▼
        记录偏差（如有）→ 缓存结果
```

### 6.2 图像探测流程

```
1. 构造请求
   ├── 嵌入图像: _PROBE_IMAGE_B64 (32x32 红色 PNG)
   └── 提示词: _IMAGE_PROBE_PROMPT

2. 发送请求到模型 API

3. 评估响应
   ├── 回答包含 _RED_KW → supports_image = True
   └── 回答不含关键词 → supports_image = False

4. 缓存结果到 ModelInfo.supports_image
```

### 6.3 视频探测流程

```
1. 构造请求
   ├── 嵌入视频: _PROBE_VIDEO_B64 或 _PROBE_VIDEO_URL
   └── 提示词: "描述这个视频的内容"

2. 发送请求到模型 API

3. 评估响应
   ├── 能处理 → supports_video = True
   └── 报错（含媒体关键词）→ supports_video = False
```

### 6.4 批量探测优化

```python
# 跳过已知模型
async def probe_models_batch(models: list[ModelInfo]):
    for model in models:
        if model.supports_multimodal is not None:
            continue  # 已探测，跳过
        await probe_model_multimodal(model.provider, model.id)
```

**解决方案：**
```python
# 对比探测结果与预期
for model in provider.models:
    baseline = registry.get(model.provider, model.id)
    if not baseline:
        continue

    probed = await probe_model_multimodal(model.provider, model.id)

    if probed.supports_image != baseline.expected_image:

            provider_id=model.provider,
            model_id=model.id,
            field="image",
            expected=baseline.expected_image,
            actual=probed.supports_image,
```

## 11. 常见问题

### Q1: 探测结果与预期不符

**原因：**
- 模型版本更新后能力变化
- 文档信息过时
- 探测图像/视频被 Provider 拒绝

**排查步骤：**
```python
# 1. 查看探测日志
logging.getLogger("providers.multimodal_prober").setLevel(logging.DEBUG)

# 2. 检查探测数据是否正确
print(f"Image size: {len(_PROBE_IMAGE_B64)} bytes")

# 3. 手动验证
result = await probe_model_multimodal(provider_id, model_id)
print(f"Result: {result}")

# 4. 查看预期能力基准
baseline = registry.get(provider_id, model_id)
print(f"Expected: image={baseline.expected_image}, video={baseline.expected_video}")
```

### Q2: 探测导致 API 调用浪费

**原因：**
- 每次使用都触发探测
- 缓存未生效

**解决方案：**
```python
# 确保缓存生效
model = provider_manager.get_model(provider_id, model_id)
print(f"probe_source: {model.probe_source}")  # 应为 "probed"

# 预热探测（启动时）
await provider_manager.probe_model_multimodal(provider_id, model_id)

# 禁用自动探测，使用手动探测
provider_manager.update_config({"auto_probe": False})
```

### Q3: 本地模型探测失败

**原因：**
- Ollama 未启用 vision 模态
- llama.cpp 编译时未包含视频支持
- 模型文件不支持多模态

**解决方案：**
```bash
# 检查 Ollama 版本
ollama --version

# 检查已安装模型
ollama list

# 重新拉取带 vision 的模型
ollama pull llama3.2-vision
```

### Q4: 探测超时

**原因：**
- 网络延迟
- 模型响应慢
- Provider 限流

**解决方案：**
```python
# 增加超时时间
result = await probe_model_multimodal(
    provider_id, model_id,
    timeout=30.0  # 默认 15s
)

# 使用快速探测（只测图像）
result = await probe_model_multimodal(
    provider_id, model_id,
    image_only=True  # 跳过视频探测
)
```

## 13. 总结

**核心要点：**

1. **探测机制：** 基于颜色识别的图像探测 + 异常检测的视频探测
2. **缓存策略：** 探测结果缓存在 ModelInfo，避免重复探测
3. **能力基准：** ExpectedCapabilityRegistry 维护预期能力，对比发现偏差
4. **probe_source：** documentation（文档）/ probed（已测）/ unknown（未知）
5. **偏差检测：** false_negative（假阴性）和 false_positive（假阳性）两种偏差类型

**探测数据：**
- 图像：32x32 红色 PNG (96 bytes)
- 视频：64x64 蓝色 H.264 MP4 (1.8KB)
- 提示词：询问图像主色，验证是否识别

**最佳实践：**
- 生产环境启用探测缓存
- 测试环境验证能力基准准确性
- 探测失败时使用保守估计（默认不支持）
- 视频探测可设置为 image_only 加快速度

## 🐍 来自 Java 的你

### 核心概念对照

| Java | Python / QwenPaw | 说明 |
|------|-------------------|------|
| ServiceLoader 探测 | 模型探测 (MultimodalProber) | ServiceLoader 在运行时扫描 META-INF/services 发现实现；QwenPaw 通过实际调用模型来探测其能力 |
| SPI 机制 | capability detection | Java SPI 通过接口+配置文件解耦；QwenPaw 通过探测结果动态构建能力映射 |
| Class.forName | 模型测试 (probe 方法) | Class.forName 反射加载类验证可用性；QwenPaw 向模型发送测试请求验证功能支持 |
| BeanPostProcessor | 探测钩子 (ExpectedCapabilityRegistry) | BeanPostProcessor 在 Bean 初始化后执行后处理；QwenPaw 在探测完成后与期望基线进行偏差检测 |

### 关键差异

Java 的 ServiceLoader/SPI 是静态声明式探测——在类路径中查找配置文件即可发现实现类，不涉及实际功能验证。QwenPaw 的探测是动态实测式——向模型发送真实的图像/工具调用请求，根据返回结果判断能力是否可用，探测结果可能因模型版本、网络状况而变化。

## 11. Contributor 指南

### 11.1 适合新手修改的文件

| 文件 | 原因 |
|------|------|
| `src/qwenpaw/providers/capability_probe.py` | 探测逻辑独立，新增探测容易 |
| `src/qwenpaw/providers/expected_capabilities.py` | 能力注册表简单，添加新模型容易 |

### 11.2 危险区域（修改前请联系 Maintainer）

| 区域 | 原因 |
|------|------|
| `capability_probe.py` 探测逻辑 | 修改可能影响模型能力判断，导致功能异常 |
| `ExpectedCapabilityRegistry` 缓存 | 缓存机制复杂，修改可能泄露旧数据 |

```python
# 单独测试图像探测
from qwenpaw.providers.capability_probe import probe_vision
```
