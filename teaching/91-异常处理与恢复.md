## 概述

QwenPaw 通过 QueryErrorDump、SafeJSONSession 和进程守护实现异常处理与恢复，确保系统在发生错误时能够保存上下文并继续运行。系统设计遵循"fail-safe"原则，尽可能保留错误上下文便于事后分析。

**核心特性：**
- **错误转储：** QueryErrorDump 持久化完整错误上下文
- **JSON 容错：** SafeJSONSession 自动修复损坏的 JSON
- **进程守护：** systemd 确保进程崩溃后自动重启
- **会话恢复：** 异常后从持久化状态恢复

**源码路径：** `src/qwenpaw/app/runner/`

## 1. QueryErrorDump

源码路径：`src/qwenpaw/app/runner/query_error_dump.py:48`

### 1.1 功能说明

当 Agent 处理请求发生异常时，QueryErrorDump 将完整的错误上下文转储到文件，供事后分析和调试。

### 1.2 转储内容

| 内容 | 说明 |
|------|------|
| 异常类型 | 异常类名（如 `ValueError`） |
| 堆栈跟踪 | `traceback.format_exc()` 完整堆栈 |
| 请求参数 | AgentRequest 序列化（脱敏后） |
| 局部变量 | 通过 `locals()` 捕获（已脱敏） |
| 时间戳 | 异常发生时间 |
| 临时文件路径 | 相关缓存文件位置 |

### 1.3 敏感信息脱敏

```python
# src/qwenpaw/app/runner/query_error_dump.py
_SENSITIVE_KEYS = frozenset({
    "password", "token", "api_key", "secret",
    "authorization", "credential", "jwt",
})

def _scrub_sensitive(locals_: dict) -> dict:
    """移除敏感信息，避免日志泄露"""
    result = {}
    for key, value in locals_.items():
        if any(s in key.lower() for s in _SENSITIVE_KEYS):
            result[key] = "[REDACTED]"
        else:
            result[key] = value
    return result
```

### 1.4 使用示例

```python
# src/qwenpaw/app/runner/query_error_dump.py:48
def write_query_error_dump(
    request: AgentRequest,
    exc: Exception,
    locals_: dict,
) -> str:
    """将错误上下文写入临时文件，返回文件路径"""
    dump_data = {
        "exception_type": type(exc).__name__,
        "traceback": traceback.format_exc(),
        "request": request.model_dump() if hasattr(request, 'model_dump') else str(request),
        "timestamp": datetime.now().isoformat(),
        "locals": _scrub_sensitive(locals_),
    }
    dump_path = WORKING_DIR / f"error_dump_{uuid.uuid4().hex[:8]}.json"
    with open(dump_path, "w", encoding="utf-8") as f:
        json.dump(dump_data, f, ensure_ascii=False, indent=2)
    return str(dump_path)
```

### 1.5 错误转储流程

```
Agent.run() 异常
    │
    ▼
write_query_error_dump()
    │
    ├── 捕获异常信息
    ├── 脱敏敏感数据
    ├── 写入 error_dump_{uuid}.json
    │
    ▼
返回错误响应
    │
    ▼
通知管理员（可选）
```

## 2. SafeJSONSession 容错

源码路径：`src/qwenpaw/app/runner/session.py`

### 2.1 JSON 损坏场景

| 场景 | 示例 |
|------|------|
| 尾随逗号 | `{"a": 1,}` |
| 引号缺失 | `{"a": 'value'}` |
| 注释 | `{"a": 1} // comment` |
| 控制字符 | `{"a": 1}\n\r` |
| Python 风格 | `{'a': 1}` (单引号) |

### 2.2 修复机制

```python
# src/qwenpaw/config/utils.py:456
def json_repair(s: str) -> str:
    """使用 json_repair 库修复损坏的 JSON"""
    from json_repair import repair_json
    return repair_json(s)
```

### 2.3 SafeJSONSession 使用

```python
class SafeJSONSession:
    """支持容错的 JSON 会话管理"""

    async def load(self) -> dict:
        """加载会话，自动修复损坏的 JSON"""
        content = await self._read_file()

        try:
            return json.loads(content)
        except json.JSONDecodeError:
            # 修复损坏的 JSON
            repaired = json_repair(content)
            return json.loads(repaired)

    async def save(self, data: dict) -> None:
        """保存会话（带原子性）"""
        temp_path = self.path.with_suffix(".tmp")
        content = json.dumps(data, indent=2)

        # 原子性写入
        temp_path.write_text(content, encoding="utf-8")
        temp_path.replace(self.path)
```

```
    ▼
Python 脚本手动编辑错误
    │
    ▼
并发写入导致文件损坏
```

## 3. 进程守护

### 3.1 自启动配置

```bash
# /etc/systemd/system/qwenpaw.service
[Unit]
Description=QwenPaw Agent
After=network.target

[Service]
Type=simple
User=qwenpaw
WorkingDirectory=/home/qwenpaw
ExecStart=/usr/bin/qwenpaw start
Restart=always
RestartSec=5
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
```

### 3.2 systemd 指令说明

| 指令 | 说明 |
|------|------|
| `Restart=always` | 任何退出都重启 |
| `RestartSec=5` | 重启前等待 5 秒 |
| `Type=simple` | 进程为主进程 |

### 3.3 崩溃恢复流程

```
异常发生
    │
    ▼
QueryErrorDump 保存上下文
    │
    ▼
进程退出（异常码）
    │
    ▼
systemd 检测到进程退出
    │
    ▼
RestartSec=5 等待
    │
    ▼
Restart=always 触发重启
    │
    ▼
加载上次会话状态
```

## 4. 异常处理最佳实践

### 4.1 异常分类

| 异常类型 | 处理方式 | 示例 |
|----------|----------|------|
| 可恢复 | 重试 + 降级 | 网络超时、API 限流 |
| 不可恢复 | 记录 + 清理 | 配置错误、内存不足 |
| 致命 | 转储 + 重启 | 未捕获异常 |

### 4.2 重试策略

```python
import asyncio

async def retry_with_backoff(
    func,
    max_retries=3,
    base_delay=1.0,
    max_delay=60.0,
):
    """指数退避重试"""
    for attempt in range(max_retries):
        try:
            return await func()
        except RecoverableError as e:
            if attempt == max_retries - 1:
                raise
            delay = min(base_delay * (2 ** attempt), max_delay)
            logger.warning(f"Retry {attempt + 1}/{max_retries} after {delay}s")
            await asyncio.sleep(delay)
```

### 4.3 降级策略

```python
async def handle_with_fallback(primary_func, fallback_func):
    """主函数失败时使用降级函数"""
    try:
        return await primary_func()
    except ServiceUnavailableError:
        logger.warning("Primary service unavailable, using fallback")
        return await fallback_func()
```

### Q1: 错误转储文件过多占用磁盘

```bash
find /path/to/workspace -name "error_dump_*.json" -mtime +7 -delete

# 设置转储文件上限
# 在配置中限制最大转储数量
```

### Q2: JSON 修复后数据丢失

**原因：**
- json_repair 无法修复严重损坏的 JSON
- 部分数据无法恢复

**解决方案：**
```python
# 修复前备份
content = original_file.read()
repaired = json_repair(content)

# 验证修复结果
if len(repaired) < len(content) * 0.5:
    logger.error("JSON repair resulted in significant data loss")
    # 使用备份或默认配置
```

### Q3: 进程反复重启

**原因：**
- 致命错误未修复
- 配置持续损坏

**解决方案：**
```bash
# 1. 停止自动重启
sudo systemctl stop qwenpaw

# 2. 手动排查问题
python -c "from qwenpaw import app; app.main()"

# 3. 修复后重新启动
sudo systemctl start qwenpaw
```

### Q4: 无法捕获的异常

**原因：**
- 异步任务中的异常
- 子进程异常

**解决方案：**
```python
# 全局异常处理器
async def global_exception_handler(loop, context):
    exc = context.get("exception")
    if exc:
        await write_critical_dump(exc, context)
    loop.default_exception_handler(context)

# 设置异常处理器
loop = asyncio.get_event_loop()
loop.set_exception_handler(global_exception_handler)
```

## 9. 总结

**核心要点：**

1. **QueryErrorDump：** 持久化完整错误上下文到 JSON，包含堆栈、请求、脱敏后的局部变量
2. **SafeJSONSession：** 自动修复损坏的 JSON，支持会话文件容错加载
3. **进程守护：** systemd Restart=always 确保进程崩溃后自动重启
4. **错误处理：** 可恢复错误重试降级，不可恢复错误记录清理

**异常分类：**
- 可恢复：网络超时、API 限流 → 重试 + 降级
- 不可恢复：配置错误 → 记录 + 告警
- 致命：未捕获异常 → 转储 + 重启

**最佳实践：**
- 遵循"早抛出、晚捕获"原则
- 记录足够的上下文信息
- 敏感信息脱敏
- 设置错误率告警
