> **一句话概述**：记忆管理系统基于 ReMeLight 实现，支持 Chroma 向量搜索和本地文件两种后端，通过 MemoryCompactionHook 在上下文接近窗口上限时自动压缩，并提供 Dream Memory 定时优化机制。

记忆管理系统管理 Agent 的对话记忆、上下文压缩和记忆摘要，支持 Chroma 向量数据库和本地文件两种存储后端。

## 上下文压缩

### MemoryCompactionHook

**文件**: `src/qwenpaw/agents/hooks/memory_compaction.py`

**核心逻辑**:

```python
class MemoryCompactionHook:
    """Hook for automatic memory compaction when context is full."""

    async def __call__(
        self,
        agent: ReActAgent,
        kwargs: dict[str, Any],
    ) -> dict[str, Any] | None:
        # 1. 重入保护
        if getattr(agent, self._REENTRANCY_ATTR, False):
            return None

        # 2. 获取token计数
        token_counter = get_token_counter(agent_config)
        str_token_count = await token_counter.count(...)

        left_compact_threshold = (
            running_config.memory_compact_threshold - str_token_count
        )

        # 3. 压缩工具结果
        if trc.enabled:
            await self.memory_manager.compact_tool_result(...)

        # 4. 检查是否需要压缩
        (messages_to_compact, _, is_valid) = await self.memory_manager.check_context(...)

        # 5. 执行压缩
        if running_config.context_compact.context_compact_enabled:
            compact_content = await self.memory_manager.compact_memory(...)
```

### compact_memory 方法

```python
async def compact_memory(
    self,
    messages: list[Msg],
    previous_summary: str = "",
    extra_instruction: str = "",
    **_kwargs,
) -> str:
    """Compact messages into a condensed summary."""
    self._prepare_model_formatter()
    agent_config = load_agent_config(self.agent_id)
    cc = agent_config.running.context_compact

    result = await self._reme.compact_memory(
        messages=messages,
        as_llm=self.chat_model,
        as_llm_formatter=self.formatter,
        as_token_counter=get_token_counter(agent_config),
        language=agent_config.language,
        max_input_length=agent_config.running.max_input_length,
        compact_ratio=cc.memory_compact_ratio,  # 默认0.75
        previous_summary=previous_summary,
        return_dict=True,
        add_thinking_block=cc.compact_with_thinking_block,
        extra_instruction=extra_instruction,
    )
    return result.get("history_compact", "")
```

```python
async def dream_memory(self, **kwargs) -> None:
    """Run one dream-based memory optimization."""
    logger.info("running dream-based memory optimization")

    # 创建备份
    self.backup_path = Path(self.working_dir).absolute() / "backup"
    self.backup_path.mkdir(parents=True, exist_ok=True)

    memory_file = Path(self.working_dir) / "MEMORY.md"
    if memory_file.exists():
        timestamp = datetime.now().strftime("%Y%m%d_%H%M%S")
        backup_file = self.backup_path / f"memory_backup_{timestamp}.md"
        shutil.copyfile(memory_file, backup_file)

    # 创建ReActAgent执行梦境任务
    dream_agent = ReActAgent(...)
```

**Dream提示词原则**:
- 极简去冗: 只保留"核心业务决策"、"确认的用户偏好"、"高价值可复用经验"
- 状态覆写: 用新状态替换旧状态
- 归纳整合: 将零碎规则提炼为通用条目
- 废弃剔除: 删除已证伪的假设

## 如果你来自 Java

QwenPaw 的记忆管理系统与 Java 生态中的缓存/会话管理系统有对应之处，但针对 LLM 场景做了特殊优化。

### 概念对应表

| Java 概念 | QwenPaw | 说明 |
|-----------|---------|------|
| **JCache (JSR-107)** | `BaseMemoryManager` | 缓存抽象接口 |
| **Caffeine Cache** | `ReMeLightMemoryManager` | 高性能内存缓存 |
| **Ehcache** | `AgentMdManager` | 持久化缓存 |
| **Guava Cache** | `MemoryCompactionHook` | 自动淘汰+压缩 |
| **Session Management** | `messages` 列表 | 对话上下文 |
| **Redis** | `chroma` 向量后端 | 分布式存储 |
| **Hibernate 2nd Level Cache** | 向量相似度搜索 | 语义缓存 |

### 上下文压缩对比

Java 没有直接类比，但类似 LRU 缓存淘汰：

```java
// Java: Guava Cache 自动淘汰
LoadingCache<Key, Value> cache = CacheBuilder.newBuilder()
    .maximumSize(1000)
    .expireAfterWrite(10, TimeUnit.MINUTES)
    .removalListener(notification -> {
        // 淘汰时压缩/归档旧条目
        archive(notification.getValue());
    })
    .build(keyLoader);
```

QwenPaw 的上下文压缩更智能——不是简单的 LRU，而是用 LLM 生成摘要：

```python
# QwenPaw: 上下文压缩
compact_content = await memory_manager.compact_memory(
    messages=messages,
    compact_ratio=0.75,  # 压缩到 75%
    extra_instruction="保留核心决策和用户偏好"
)
```

### 向量存储对比

```java
// Java: Redis + Vector 扩展 (RediSearch)
VectorIndex index = new VectorIndex("embeddings");
index.add("doc1", new float[]{0.1f, 0.2f, ...});
List<SearchResult> results = index.search(
    new float[]{0.3f, 0.1f, ...},
```

```python
# QwenPaw: Chroma 向量数据库
results = await memory_manager.memory_search(
    query="user preferences",
    max_results=5,
    min_score=0.3

```

### 记忆后端对比

| 特性 | Java | QwenPaw |
|------|------|---------|
| 内存缓存 | Caffeine, Guava | `ReMeLightMemoryManager` (内存) |
| 持久化 | Redis, JDBC | `AgentMdManager` (文件) |
| 向量搜索 | Redis + RediSearch, Pinecone | Chroma (本地向量DB) |
| 压缩策略 | LRU/LFU/FIFO | LLM 摘要生成 |
| 分布式 | Redis Cluster | Chroma Client-Server |

### Session vs Messages

Java HttpSession vs QwenPaw messages：

```java
// Java: HttpSession 存储用户数据
HttpSession session = request.getSession();
session.setAttribute("user", user);
session.setAttribute("cart", cart);
```

```python
# QwenPaw: 消息列表作为记忆
messages = await memory_manager.get_memory()
# messages 是 [{role: "user", content: "..."}, ...]
```

**核心差异：** Java 缓存是键值对，适合随机访问；QwenPaw 记忆是消息流，适合顺序处理和摘要生成。

### Dream Memory 的独特性

Java 中没有直接类比——Dream Memory 是用 LLM 主动分析和整合历史记忆，这是 LLM 时代特有的能力。

```python
# QwenPaw: 梦境记忆
await manager.dream_memory()
# LLM 阅读 MEMORY.md，生成优化后的版本
```

**总结：** Java 缓存体系成熟但缺乏 LLM 上下文意识，QwenPaw 的记忆系统在上下文压缩和语义搜索上有独特优势。
