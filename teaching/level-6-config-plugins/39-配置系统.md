## 2. 三层加载架构详解

### 2.1 第一层：环境变量（EnvVarLoader）

**源码：** `src/qwenpaw/constant.py:4`（dotenv 加载） + `constant.py:12-86`（EnvVarLoader）

环境变量层在所有配置之前生效，由 `_get_env()` 函数和 `EnvVarLoader` 类联合处理。

### dotenv 自动加载

```python
# src/qwenpaw/constant.py:4
from dotenv import load_dotenv
load_dotenv()  # 自动加载 .env 文件到环境变量
```

这行代码在 `constant.py` 模块首次被 import 时执行，意味着任何后续模块在访问 `os.environ` 时都能看到 `.env` 中的变量。`load_dotenv()` 是惰性的——如果环境变量已存在，不会覆盖。

### 环境变量查找函数

```python
# src/qwenpaw/constant.py:12-26
def _get_env(key: str, default: str = "") -> str:
    """Look up an env var with automatic COPAW_ legacy fallback.

    Primary key is always used as-is.  When the primary key starts with
    ``QWENPAW_``, the corresponding ``COPAW_`` variant is transparently
    checked as a fallback so that existing deployments keep working.
    """
    if key in os.environ:
        return os.environ[key]
    if key.startswith("QWENPAW_"):
        legacy_key = "COPAW_" + key[len("QWENPAW_") :]
        if legacy_key in os.environ:
            return os.environ[legacy_key]
    return default
```

**设计要点：** 函数名以 `QWENPAW_` 开头的环境变量，自动回退检查对应的 `COPAW_` 前缀。这确保了从旧版 QwenPaw（曾用名 Copaw）迁移的用户无需修改 `.env` 文件。

### EnvVarLoader 类型安全加载

```python
# src/qwenpaw/constant.py:28-86
class EnvVarLoader:
    """Utility to load and parse environment variables with type safety."""

    @staticmethod
    def get_bool(env_var: str, default: bool = False) -> bool:
        val = _get_env(env_var, str(default)).lower()
        return val in ("true", "1", "yes")

    @staticmethod
    def get_float(
        env_var: str,
        default: float = 0.0,
        min_value: float | None = None,
        max_value: float | None = None,
    ) -> float:
        try:
            value = float(_get_env(env_var, str(default)))
            if min_value is not None and value < min_value:
                return min_value
            if max_value is not None and value > max_value:
                return max_value
            return value
        except (TypeError, ValueError):
            return default

    @staticmethod
    def get_int(
        env_var: str,
        default: int = 0,
        min_value: int | None = None,
        max_value: int | None = None,
    ) -> int:
        # 同上，省略实现细节

    @staticmethod
    def get_str(env_var: str, default: str = "") -> str:
        return _get_env(env_var, default)
```

### WORKING_DIR 的三层解析

```python
# src/qwenpaw/constant.py:88-101
# WORKING_DIR priority:
# 1. QWENPAW_WORKING_DIR / COPAW_WORKING_DIR env var is set → use it
# 2. ~/.copaw exists (legacy installation) → use it as-is
# 3. Default → ~/.qwenpaw
_explicit_working_dir = _get_env("QWENPAW_WORKING_DIR")
if _explicit_working_dir:
    WORKING_DIR = Path(_explicit_working_dir).expanduser().resolve()
else:
    _legacy_copaw_dir = Path("~/.copaw").expanduser()
    if _legacy_copaw_dir.exists():
        WORKING_DIR = _legacy_copaw_dir.resolve()
    else:
        WORKING_DIR = Path("~/.qwenpaw").expanduser().resolve()
```

**设计原因：** `WORKING_DIR` 是整个配置系统的基石——它决定了 `config.json` 的位置、所有 Agent workspace 的根目录、插件目录、媒体目录等。因此它的解析必须极度可靠，采用三层回退策略：显式环境变量 > 旧版目录 > 新版默认目录。

|----------|------|--------|------|

| `QWENPAW_LLM_MAX_RETRIES` | int | `3` | LLM API 调用的最大重试次数 |

| `QWENPAW_LLM_MAX_QPM` | int | `60` | 每分钟最大 LLM 查询数（0=禁用） |

### 渠道过滤的实现

```python
# src/qwenpaw/config/utils.py:426-449
def get_available_channels() -> Tuple[str, ...]:
    """Return channel keys enabled for this run (built-in + entry point
    qwenpaw.channels), filtered by QWENPAW_ENABLED_CHANNELS or
    QWENPAW_DISABLED_CHANNELS when set.
    """
    from ..app.channels.registry import get_channel_registry
    registry = get_channel_registry()
    all_keys = tuple(registry.keys())

    raw_enabled = EnvVarLoader.get_str("QWENPAW_ENABLED_CHANNELS", "").strip()
    if raw_enabled:
        enabled = {ch.strip() for ch in raw_enabled.split(",") if ch.strip()}
        return tuple(k for k in all_keys if k in enabled) or all_keys

    raw_disabled = EnvVarLoader.get_str("QWENPAW_DISABLED_CHANNELS", "").strip()
    if raw_disabled:
        disabled = {ch.strip() for ch in raw_disabled.split(",") if ch.strip()}
        return tuple(k for k in all_keys if k not in disabled) or all_keys

    return all_keys
```

### JSON 读取与自动修复

```python
# src/qwenpaw/config/utils.py:458-475
def _read_config_data(config_path: Path) -> Optional[dict]:
    """Read *config_path* and return parsed dict.

    Uses ``json_repair`` to handle common syntax issues (trailing
    commas, missing quotes, comments, BOM, etc.).  Creates a backup and
    returns ``None`` when the file is unrecoverable.
    """
    try:
        with open(config_path, "r", encoding="utf-8") as file:
            raw = file.read()
    except UnicodeDecodeError:
        _backup_config_file(config_path, "encoding error")
        return None

    try:
        data = json.loads(raw)
    except json.JSONDecodeError:
        data = repair_json(raw, return_objects=True)  # 自动修复
        if not isinstance(data, dict):
            _backup_config_file(config_path, "JSON syntax error, repair failed")
            return None
        logger.warning("Config %s had JSON syntax issues that were auto-repaired.", config_path)

    if not isinstance(data, dict):
        _backup_config_file(config_path, "root value is not a JSON object")
        return None
    return data
```

**json_repair 修复能力：** 能自动处理以下常见 JSON 语法错误：
- 尾部逗号（如 `{ "a": 1, }`）
- 单引号而非双引号
- 注释（`// comment` 或 `/* comment */`）
- BOM（字节顺序标记）
- 裸字符串（未加引号的键或值）

### 完整加载流程

```python
# src/qwenpaw/config/utils.py:491-530
def load_config(config_path: Optional[Path] = None) -> Config:
    """Load config from file. Returns default Config if file is missing."""
    if config_path is None:
        config_path = get_config_path()  # WORKING_DIR / "config.json"
    if not config_path.is_file():
        return Config()  # 完全缺失时返回全默认值

    data = _read_config_data(config_path)  # 含 json_repair 修复
    if data is None:
        return Config()

    data = _normalize_working_dir_bound_paths(data)  # 旧路径兼容

    # 兼容 legacy last_api_host / last_api_port
    if "last_api_host" in data or "last_api_port" in data:
        la = data.setdefault("last_api", {})
        if "host" not in la and "last_api_host" in data:
            la["host"] = data.get("last_api_host")
        if "port" not in la and "last_api_port" in data:
            la["port"] = data.get("last_api_port")

    try:
        return Config.model_validate(data)  # Pydantic 验证
    except ValidationError as exc:
        # 尝试自动修复：移除错误字段后重验证
        fixed_any = False
        for err in exc.errors():
            loc = list(err.get("loc", []))
            if loc and _remove_bad_field(data, loc):
                fixed_any = True
        if not fixed_any:
            _backup_config_file(config_path, "validation error")
            return Config()

    try:
        return Config.model_validate(data)
    except ValidationError:
        _backup_config_file(config_path, "validation error after field removal")
        return Config()
```

**双重验证策略：** 第一次验证失败后，尝试逐个移除错误字段并重新验证。只有当所有字段都被移除仍无法通过验证，或者修复后仍失败时，才备份原文件并回退到全默认值。

### 备份机制

```python
# src/qwenpaw/config/utils.py:437-452
def _backup_config_file(config_path: Path, reason: str) -> Optional[Path]:
    """Backup *config_path* before falling back to defaults."""
    try:
        short_id = uuid.uuid4().hex[:8]
        backup_path = config_path.with_suffix(f".{short_id}.bak")
        shutil.copy2(config_path, backup_path)
        logger.error(
            "Config file %s is unusable (%s). "
            "Original backed up to: %s. "
            "Falling back to default configuration.",
            config_path, reason, backup_path,
        )
        return backup_path
    except OSError as exc:
        logger.error("Failed to backup config file %s: %s", config_path, exc)
        return None
```

备份文件命名为 `<原文件名>.<8位UUID>.bak`，避免覆盖已有的备份。

### Agent ID 验证

```python
# src/qwenpaw/config/config.py:121-145
_AGENT_ID_PATTERN = re.compile(r"^[a-zA-Z0-9][a-zA-Z0-9_-]*[a-zA-Z0-9]$")
_AGENT_ID_MIN_LENGTH = 2
_AGENT_ID_MAX_LENGTH = 64
_RESERVED_AGENT_IDS = frozenset({"default"})

def validate_agent_id(agent_id: str, existing_ids: Set[str]) -> None:
    """Validate a custom agent ID.

    Checks length, character set, reserved words, and uniqueness.
    """
    if len(agent_id) < _AGENT_ID_MIN_LENGTH:
        raise ValueError(f"Agent ID must be at least {_AGENT_ID_MIN_LENGTH} characters")
    if len(agent_id) > _AGENT_ID_MAX_LENGTH:
        raise ValueError(f"Agent ID must be at most {_AGENT_ID_MAX_LENGTH} characters")
    if not _AGENT_ID_PATTERN.match(agent_id):
        raise ValueError(
            f"Agent ID '{agent_id}' contains invalid characters. "
            "Only letters, digits, hyphens, and underscores allowed."
        )
    if agent_id in _RESERVED_AGENT_IDS:
        raise ValueError(f"Agent ID '{agent_id}' is reserved and cannot be used.")
    if agent_id in existing_ids:
        raise ValueError(f"Agent ID '{agent_id}' already exists.")
```

Agent ID 必须以字母或数字开头和结尾，中间可含字母、数字、连字符和下划线，长度 2-64 个字符。

### 加载 Agent 配置

```python
# src/qwenpaw/config/config.py:1508-1550
def load_agent_config(agent_id: str) -> AgentProfileConfig:
    """Load agent's complete configuration from workspace/agent.json."""
    config = load_config()  # 先加载根配置（获取 workspace 路径）

    if agent_id not in config.agents.profiles:
        raise ConfigurationException(
            config_key="agent",
            message=f"Agent '{agent_id}' not found in config",
        )

    agent_ref = config.agents.profiles[agent_id]
    workspace_dir = Path(agent_ref.workspace_dir).expanduser()
    agent_config_path = workspace_dir / "agent.json"

    if not agent_config_path.exists():
        # 不存在时从根配置构建默认配置并写入磁盘
        fallback_config = build_fallback_agent_profile_config(agent_id, config)
        save_agent_config(agent_id, fallback_config)
        return fallback_config

    with open(agent_config_path, "r", encoding="utf-8") as f:
        data = json.load(f)

    # 旧路径兼容：~/.copaw -> ~/.qwenpaw
    try:
        from .utils import _normalize_working_dir_bound_paths
        data = _normalize_working_dir_bound_paths(data)
    except Exception:
        pass

    return AgentProfileConfig(**data)
```

**关键设计：** 如果 `agent.json` 不存在，系统会从根配置自动构建一个默认配置并写入磁盘。这意味着新增 Agent 时只需在 `config.json` 的 `agents.profiles` 中添加引用，`agent.json` 会在首次加载时自动生成。

当检测到变化时，会触发重新加载和相应配置变更的传播。相比直接监听文件系统事件（如 inotify），轮询实现更简单，且在网络文件系统（NFS）上更可靠。

### 2.4 三层设计的设计原因

| 设计要点 | 原因 |
|----------|------|
| 环境变量优先于 JSON | `QWENPAW_WORKING_DIR` 必须提前确定才能找到 `config.json`，这是鸡生蛋蛋生鸡问题，唯一解是在文件系统操作之前就通过环境变量决定路径 |
| Agent 配置独立文件 | 多 Agent 场景下各自配置需要独立版本化，且一个 Agent 配置错误不应影响其他 Agent |
| 热重载 2 秒间隔 | 兼顾响应速度（配置变更 2 秒内生效）和系统开销（避免过高频率的文件 stat 调用） |
| Optional 字段 + 根配置补全 | Agent 配置中的每个子配置都是 Optional，缺失时自动继承根配置，实现"全局默认值 + 局部覆盖"模式 |

### 4.4 模型验证器 @model_validator（before 模式）

**源码：** `src/qwenpaw/config/config.py:1028-1055`

```python
# src/qwenpaw/config/config.py:1028-1055
@model_validator(mode="before")
@classmethod
def _normalize_legacy_fields(cls, data):
    """Normalize common MCP field aliases from third-party examples."""
    if not isinstance(data, dict):
        return data

    payload = dict(data)

    # 兼容旧字段名
    if "isActive" in payload and "enabled" not in payload:
        payload["enabled"] = payload["isActive"]
    if "baseUrl" in payload and "url" not in payload:
        payload["url"] = payload["baseUrl"]
    if "type" in payload and "transport" not in payload:
        payload["transport"] = payload["type"]

    # 自动推断传输类型
    if (
        "transport" not in payload
        and (payload.get("url") or payload.get("baseUrl"))
        and not payload.get("command")
    ):
        payload["transport"] = "streamable_http"

    # 规范化传输类型别名
    raw_transport = payload.get("transport")
    if isinstance(raw_transport, str):
        normalized = raw_transport.strip().lower()
        transport_alias_map = {
            "streamablehttp": "streamable_http",
            "http": "streamable_http",
            "stdio": "stdio",
            "sse": "sse",
        }
        payload["transport"] = transport_alias_map.get(normalized, normalized)

    return payload
```

`mode="before"` 在 Pydantic 解析之前执行，此时 `data` 是原始字典。这允许在类型解析之前进行字段名标准化、默认值推断等预处理。

## 5. 配置验证与容错机制

### 5.1 严格验证模式

**源码：** `src/qwenpaw/config/utils.py:573-603`

```python
# src/qwenpaw/config/utils.py:573-603
def strict_validate_config_file(
    config_path: Optional[Path] = None,
) -> tuple[bool, str]:
    """Validate *config_path* strictly for diagnostics (no auto-repair)."""
    if config_path is None:
        config_path = get_config_path()
    if not config_path.is_file():
        return True, f"(no file) defaults — {config_path}"

    data = _read_config_data(config_path)
    if data is None:
        return False, f"unreadable or invalid JSON — {config_path}"

    data = _normalize_working_dir_bound_paths(data)

    try:
        Config.model_validate(data)
    except ValidationError as exc:
        lines = [f"{config_path}:"]
        for err in exc.errors():
            loc = ".".join(str(x) for x in err.get("loc", ()))
            msg = err.get("msg", "")
            lines.append(f"  {loc}: {msg}")
        return False, "\n".join(lines)
    return True, str(config_path)
```

返回 `(False, 详细错误信息)` 时，错误信息精确到字段级别，格式为 `config.json: channels.discord.enabled: Field required`。

### 5.2 错误字段自动移除

```python
def _remove_bad_field(data: dict, loc: list) -> bool:
    """Try to remove the field at *loc*; fall back to ancestor keys."""
    if _remove_nested_key(data, loc):
```

## 6. 旧路径兼容机制

**源码：** `src/qwenpaw/config/utils.py:26-62`

```python
# src/qwenpaw/config/utils.py:26-62
def _normalize_working_dir_bound_paths(data: object) -> object:
    """Normalize legacy ~/.copaw-bound paths to current WORKING_DIR."""
    legacy_root_tilde = "~/.copaw"
    legacy_root_abs = str(Path(legacy_root_tilde).expanduser().resolve())
    new_root_abs = str(WORKING_DIR)

    def _rewrite_path_value(v: object) -> object:
        if not isinstance(v, str) or not v:
            return v
        if v.startswith(legacy_root_tilde):
            return new_root_abs + v[len(legacy_root_tilde):]
        if v.startswith(legacy_root_abs):
            return new_root_abs + v[len(legacy_root_abs):]
        return v

    def _walk(obj: object, key: str | None = None) -> object:
        if isinstance(obj, dict):
            return {k: _walk(v, str(k)) for k, v in obj.items()}
        if isinstance(obj, list):
            return [_walk(x, key) for x in obj]
        if key in {"workspace_dir", "media_dir"}:  # 只重写已知路径字段
            return _rewrite_path_value(obj)
        return obj

    return _walk(data, None)
```

只重写 `workspace_dir` 和 `media_dir` 两个已知路径字段，避免误重写其他字符串字段。

## 11. 总结

QwenPaw 配置系统的设计体现了以下原则：

1. **分层解耦**：环境变量控制路径，根配置控制全局行为，Agent 配置控制个体差异。三层各司其职，互不干扰，任何一层的错误都不会导致完全无法启动。

2. **静默容错**：配置缺失或损坏时回退到合理默认值，不崩溃、不中断服务。json_repair 自动修复常见 JSON 错误；Pydantic 验证失败后尝试字段移除；备份机制保留原始损坏文件。

3. **Pydantic 驱动**：所有配置都经过类型验证和约束检查。`Field(ge=, le=)` 实现数值范围约束；`@field_validator` 实现字段级转换；`@model_validator(mode="before")` 实现第三方格式兼容；`@model_validator(mode="after")` 实现跨字段验证。

4. **向后兼容**：COPAW_ 环境变量自动映射到 QWENPAW_；~/.copaw 路径自动重写为 WORKING_DIR；`last_api_host/last_api_port` 自动合并为 `last_api` 对象；MCP 配置自动规范化 `isActive`/`baseUrl`/`type` 等别名。

5. **热重载**：Agent 配置变更通过 2 秒轮询自动感知，无需重启进程。mtime + 配置哈希双重检测确保精确变化追踪。

6. **多 Agent 安全**：`contextvars` 确保每个并发 Agent 请求访问到正确的 workspace 路径，不会因异步交错而读取到其他 Agent 的配置。

理解这套架构有助于正确配置渠道、编写插件安全规则、调优 Agent 运行时参数（LLM 重试、并发限制、速率限制等），以及排查配置相关的线上问题。

## ★ Insight ─────────────────────────────────────
**三层配置的鸡生蛋问题**：为什么环境变量层存在？因为 `QWENPAW_WORKING_DIR` 必须在读取 `config.json` 之前确定。没有环境变量，你甚至不知道配置文件在哪——这迫使环境变量层必须存在。

**json_repair 的代价**：自动修复 JSON 语法错误很方便，但也意味着配置文件中的打字错误会被静默修正而非报错。如果 `config.json` 中写成了 `"enabled": "tru"`（字符串而非布尔值），Pydantic 会在验证时捕获，但 json_repair 不会帮你修复这种语义错误。

**Agent 配置 Optional 的设计意图**：几乎所有 Agent 配置的子字段都是 `Optional`，这意味着"空"表示"使用根配置"。这是一个继承模型，而非覆盖模型——Agent 可以只改自己需要的字段，其余全部复用根配置的默认值。

## 12. 如果你来自 Java...

### 12.1 Java 配置文件发展史对比

| 时代 | Java 方案 | QwenPaw 方案 | 理念 |
|------|-----------|--------------|------|
| XML 时代 | `properties` + DOM4J | JSON | 结构化配置 |
| 注解时代 | `@Configuration` + `@Value` | Pydantic `Field()` | 类型驱动 |
| Spring Boot | `application.yml` 分层 | JSON 分层 + `contextvars` | 环境隔离 |
| 云原生 | Spring Cloud Config | 环境变量优先 | 12-Factor |

### 12.2 Spring Environment vs QwenPaw Config

**Spring Boot 配置优先级**（从高到低）：
1. 命令行参数 `--server.port=9000`
2. 系统环境变量 `SERVER_PORT=9000`
3. `application.yml` / `application.properties`
4. `@PropertySource` 加载

**QwenPaw 配置优先级**：
1. 命令行参数（间接通过环境变量）
2. 环境变量 `QWENPAW_*`
3. `config.json`
4. Agent 独立配置
5. 内置默认值（Pydantic）

### 12.3 Spring `@ConfigurationProperties` vs Pydantic Model

**Spring Boot**：
```java
// application.yml
// server:
//   port: 8080
//   servlet:
//     context-path: /api

@Component
@ConfigurationProperties(prefix = "server")
public class ServerProperties {
    private int port = 8080;
    private Servlet servlet = new Servlet();

    public static class Servlet {
        private String contextPath = "/";
    }
}
```

**QwenPaw**：
```python
# config.json
# {
#   "server": {"port": 8080, "servlet": {"contextPath": "/api"}}
# }

class ServerConfig(BaseModel):
    port: int = Field(default=8080)
    servlet: ServletConfig = Field(default_factory=ServletConfig)

class ServletConfig(BaseModel):
    context_path: str = Field(default="/", alias="servlet.context-path")
```

### 12.4 Spring `@Profile` vs QwenPaw Workspace

Spring 的 `@Profile` 允许不同环境加载不同配置：

```java
@Bean
@Profile("dev")
public DataSource devDataSource() { ... }

@Bean
@Profile("prod")
public DataSource prodDataSource() { ... }
```

QwenPaw 通过不同 Workspace 实现类似功能：

```bash
# 开发环境
~/.qwenpaw/workspaces/dev/config.json

# 生产环境
~/.qwenpaw/workspaces/prod/config.json

# 切换 workspace
# 通过修改 config.json 中 agents.active_agent 字段切换
```

### 12.5 Spring Cloud Config vs QwenPaw 分层配置

Spring Cloud Config 提供了集中式配置管理：

```
Config Server (Git/SVN)
       │
       ▼
   ┌─────────────────────────────────────────┐
   │  application.yml (共享配置)              │
   │  order-service.yml (服务特定配置)         │
   │  application-prod.yml (环境特定配置)     │
   └─────────────────────────────────────────┘
```

QwenPaw 的等效方案：

```
~/.qwenpaw/config.json (全局配置)
       │
       ├── channels/ (渠道配置)
       ├── agents/ (Agent 独立配置)
       └── plugins/ (插件配置)
```

## 13. 行业视角：配置系统的演进

### 13.1 12-Factor App 配置理念

现代云原生应用遵循 12-Factor 原则：

| Factor | 说明 | QwenPaw 实现 |
|--------|------|-------------|
| **III. 配置** | 环境存储配置 | `QWENPAW_*` 环境变量 |
| **VI. 进程** | 无状态进程 | Workspace 隔离 |
| **XI. 日志** | 日志作为事件流 | `tail -f ~/.qwenpaw/logs/qwenpaw.log` |

### 13.2 配置校验的演进

| 时代 | 校验方式 | 风险 |
|------|----------|------|
| 早期 | 运行时检查 | 线上才发现错误 |
| 现代 | 启动时校验 | Pydantic `Field(ge=, le=)` |
| 未来 | IDE 即时反馈 | LSP + JSON Schema |

### 13.3 密钥管理的最佳实践

| 方案 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| 明文存储 | 简单 | 安全隐患 | 本地开发 |
| 环境变量 | 部署灵活 | 需要 CI 配置 |容器部署 |
| 密钥管理服务 | 安全 | 复杂度高 | 生产环境 |
| QwenPaw `secret_store` | 加密存储 | 依赖 Keychain | 桌面应用 |

**步骤**：

```python
from qwenpaw.config import load_config

```

### 练习 2：创建一个 Agent 特定配置

**目标**：覆盖全局配置的 LLM 参数

**步骤**：
1. 在 `config.json` 中设置全局 `llm_max_retries: 3`
2. 在 Agent 配置中设置 `llm_max_retries: 5`
3. 启动该 Agent，验证使用 Agent 本地配置

**验证**：
```bash
qwenpaw agents list | grep my_agent
# 应显示 5
```

### 练习 3：配置 JSON Schema 验证

**目标**：使用 IDE 自动补全和验证

**步骤**：
1. 安装 VS Code + JSON Schema 插件
2. 为 `config.json` 添加 `$schema` 引用：

```json
{
  "$schema": "https://raw.githubusercontent.com/agentscope-ai/qwenpaw/main/schema/config.json",

}
```

3. 尝试输入错误类型（如 `"port": "8080"` 字符串而非数字）

### 练习 4：模拟配置故障排查

**场景**：配置不生效，但没有任何错误提示

**步骤**：
1. 故意在 `config.json` 中引入语法错误
2. 启动 QwenPaw，观察行为
3. 检查 `~/.qwenpaw/logs/` 下的日志

**常见问题**：
- JSON 注释（`//` 或 `/* */`）不是有效 JSON
- 尾部逗号 `{"key": "value",}`
- 字符串中未转义的特殊字符

### 练习 5（进阶）：扩展 Pydantic 模型

**目标**：添加一个自定义配置字段

**步骤**：
1. 阅读 `src/qwenpaw/config/config.py` 中的 `AgentProfileConfig`

## 10. Contributor 指南

### 10.1 适合新手修改的文件

| 文件 | 难度 | 原因 |
|------|------|------|
| `config/utils.py` 的路径解析函数 | ⭐ | 独立工具函数，无依赖 |
| `config/timezone.py` 的时区转换 | ⭐ | 纯粹的日期时间逻辑 |
| `config/context.py` 的上下文管理 | ⭐ | 相对独立的功能模块 |

### 10.2 危险区域（绝对不要轻易修改）

| 文件/模块 | 危险原因 |
|-----------|----------|
| `config/config.py` 的 `Config` 根模型 | 错误会影响所有配置加载 |
| `load_config()` 的容错逻辑 | 错误会导致配置文件损坏时无法启动 |
| `EnvVarLoader` 的类型推断 | 错误会导致环境变量无法正确覆盖配置 |

### 10.3 调试方法

**测试配置加载**
```python
from qwenpaw.config import load_config

config = load_config()
print(f"Loaded config with {len(config.agents)} agents")
```

**测试配置验证**
```python
from qwenpaw.config import Config

try:
    config = Config.model_validate({...})
    print("Config is valid")
except ValidationError as e:
    print(f"Config error: {e}")
```

**测试环境变量覆盖**
```python
import os
os.environ["QWENPAW_LLM_MAX_CONCURRENT"] = "10"
from qwenpaw.config import load_config
config = load_config()
print(f"Max concurrent: {config.agents.llm_max_concurrent}")
```

### 10.4 如何避免破坏架构

**配置加载原则**：
- 环境变量必须在 JSON 配置之前加载，避免"鸡生蛋"问题
- 配置变更必须经过 Pydantic 验证，不要跳过验证直接赋值
- 敏感配置（如 API Key）存储在 `secret_store` 中，不要明文存储

**测试要求**：
- 配置解析必须测试有效配置和损坏配置的两种情况
- 环境变量覆盖必须测试边界情况（空值、类型错误）
- 热重载必须测试多 Agent 并发修改场景
