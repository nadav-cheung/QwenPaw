# 模型探测与能力检测

## 概述

QwenPaw 在模型首次使用时探测其多模态能力（图像、视频支持），结果缓存供后续路由决策使用。探测结果与预期能力基线对比，不一致时记录偏差。

`★ Insight ─────────────────────────────────────`
- 探测是**运行时发现**而非静态配置，适配模型能力动态更新的场景
- 探测结果会**持久化到 ModelInfo**，后续请求无需重复探测
- false_negative/false_positive 机制帮助发现**官方文档与实际能力的偏差**
`─────────────────────────────────────────────────`

## 1. 探测流程

**源码路径**: `src/qwenpaw/providers/provider_manager.py:1124`

### 1.1 probe_model_multimodal

```python
async def probe_model_multimodal(
    self,
    provider_id: str,
    model_id: str,
    image_only: bool = False,
) -> dict:
    """Probe a model's multimodal capabilities and persist the result.

    Args:
        provider_id: Provider identifier.
        model_id: Model identifier.
        image_only: When True, skip the video probe for a faster result.
    """
    provider = self.get_provider(provider_id)
    result = await provider.probe_model_multimodal(model_id, image_only=image_only)

    # 更新模型的 capability flags
    for model in provider.models + provider.extra_models:
        if model.id == model_id:
            model.supports_image = result.supports_image
            if not image_only:
                model.supports_video = result.supports_video
                model.supports_multimodal = result.supports_multimodal
            model.probe_source = "probed"
            break

    return {
        "provider_id": provider_id,
        "model_id": model_id,
        "supports_image": result.supports_image,
        "supports_video": result.supports_video,
        "supports_multimodal": result.supports_multimodal,
    }
```

```python
def maybe_probe_multimodal(self, provider_id: str, model_id: str) -> None:
    """Schedule multimodal probing for a Model if capability is unknown."""
    provider = self.get_provider(provider_id)
    # 如果能力未知，自动探测
    for model in provider.models + provider.extra_models:
        if model.id == model_id and model.supports_multimodal is None:
            asyncio.create_task(
                self._auto_probe_multimodal(provider_id, model_id),
            )
            break
```

## 4. 图像探测评估

**源码路径**: `src/qwenpaw/providers/multimodal_prober.py:79`

```python
_IMAGE_PROBE_PROMPT = (
    "What is the single dominant color of this image? "
    "Reply with ONLY the color name, nothing else."
)

_RED_KW = ("red", "scarlet", "crimson", "vermilion", "maroon", "红")

def evaluate_image_probe_answer(
    answer: str,
    model_id: str,
    start_time: float,
    reasoning: str = "",
) -> tuple[bool, str]:
    """评估图像探测答案。

    Returns:
        (supported, message) tuple.
    """
    answer = answer.lower().strip()
    reasoning = reasoning.lower().strip()

    if any(kw in answer for kw in _RED_KW):
        return True, f"Image supported (answer={answer!r})"

    if reasoning and any(kw in reasoning for kw in _RED_KW):
        return True, f"Image supported (reasoning, answer={answer!r})"

    return False, f"Model did not recognise image (answer={answer!r})"
```

### 4.1 评估策略说明

探测使用**红色色块图像**，要求模型仅回复颜色名称。通过关键词匹配判断模型是否真正"看到"了图像内容，而非随机猜测或拒绝回答。

## 6. 探测结果对比

**源码路径**: `src/qwenpaw/providers/capability_baseline.py:330`

```python
def compare_probe_result(
    expected: ExpectedCapability,
    actual_image: bool,
    actual_video: bool,
) -> list[DiscrepancyLog]:
    """对比探测结果与预期能力。

    不一致时生成 DiscrepancyLog：
      - false_negative: expected=True, actual=False
      - false_positive: expected=False, actual=True
    """
    logs: list[DiscrepancyLog] = []
    for field_name, expected_val, actual_val in [
        ("image", expected.expected_image, actual_image),
        ("video", expected.expected_video, actual_video),
    ]:
        if expected_val is None:
            continue
        if expected_val == actual_val:
            continue
        discrepancy_type = (
            "false_negative" if expected_val is True else "false_positive"
        )
        logs.append(DiscrepancyLog(
            provider_id=expected.provider_id,
            model_id=expected.model_id,
            field=field_name,
            expected=expected_val,
            actual=actual_val,
            discrepancy_type=discrepancy_type,
        ))
    return logs
```

### 6.1 偏差类型说明

| 偏差类型 | 含义 | 可能原因 |
|----------|------|----------|
| `false_negative` | 文档说支持，实际不支持 | 模型版本降级、API 配置错误 |
| `false_positive` | 文档说不支持，实际支持 | 模型已升级、文档未更新 |

## 8. 应用场景

### 8.1 动态模型能力发现

当接入新模型或使用第三方 Provider 时，探测机制可以**无需人工配置**自动发现模型的多模态能力：

```python
# 首次使用多模态模型时自动探测
provider_manager.maybe_probe_multimodal("my-provider", "my-model")

# 探测完成后，模型能力已更新
model = provider_manager.get_model("my-provider", "my-model")
print(model.supports_image)  # True 或 False
```

### 8.2 能力偏差告警

在 CI/CD 流程中集成探测结果对比，可以在**模型能力变更时自动告警**：

```python
# 探测结果与基线不一致时告警
discrepancies = compare_probe_result(baseline, actual_image, actual_video)
for d in discrepancies:
    logger.warning(
        f"Capability discrepancy for {d.provider_id}/{d.model_id}: "
        f"{d.field} is {d.discrepancy_type} "
        f"(expected={d.expected}, actual={d.actual})"
    )
```

## 9. 最佳实践

1. **首次探测有延迟**：探测需要实际调用模型，应在后台异步执行，避免阻塞首次请求
2. **结果缓存**：探测结果写入 `ModelInfo`，同一进程内无需重复探测
3. **image_only 加速**：已知只需图像能力时，指定 `image_only=True` 跳过视频探测
4. **基线与探测结合**：优先使用文档基线，探测结果用于验证和偏差告警
5. **日志记录**：探测失败时应记录完整日志，便于排查 Provider API 问题

## 10. 常见问题

### Q1: 探测超时怎么处理？

探测有 30 秒默认超时，超时后 `supports_multimodal` 保持 `None`，后续请求会再次触发探测。建议检查 Provider API 连通性和速率限制。

### Q2: 如何禁用自动探测？

在模型配置中直接设置 `supports_image`/`supports_video`/`supports_multimodal` 值，探测调度会跳过已知的模型：

```python
# 在 provider 配置中
model.supports_multimodal = True  # 跳过探测
model.probe_source = "documentation"
```

### Q3: 探测结果会持久化到磁盘吗？

当前探测结果仅存在内存中的 `ModelInfo` 对象。进程重启后会重新探测，或需要手动设置能力值。

### Q4: false_positive 出现时应该信哪个？

以探测结果（实际测试）为准。探测结果会覆盖 `ModelInfo` 的能力标志，但 `probe_source` 标记为 `"probed"`，便于区分来源。
