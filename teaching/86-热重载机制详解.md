# 热重载机制详解

## 概述

QwenPaw 支持配置文件和 Agent 配置的热重载，通过 mtime 轮询检测变更，配合异步重载实现无需重启的动态更新。热重载机制确保配置变更可以实时生效，同时通过服务复用最大限度减少对正在运行任务的影响。

**核心特性：**
- **异步重载：** 配置变更通过后台任务处理，不阻塞请求响应
- **服务复用：** 可复用服务（如记忆、缓存）无需重建
- **无状态设计：** Workspace 可完全重建，保证状态一致性
- **跨平台支持：** 基于 Polling mtime，不依赖特定文件系统事件

**源码路径：** `src/qwenpaw/app/`

## 1. 热重载触发机制

源码路径：`src/qwenpaw/app/utils.py:17`

### 1.1 schedule_agent_reload 函数

```python
# src/qwenpaw/app/utils.py:17
def schedule_agent_reload(request: "Request", agent_id: str) -> None:
    """在后台调度 Agent 重载（非阻塞）。

    从请求上下文提取 manager 和 agent_id，避免在后台任务中访问
    已结束生命周期的 request/workspace 对象。
    """
    manager = request.app.state.multi_agent_manager

    async def reload_in_background():
        try:
            await manager.reload_agent(agent_id)
        except Exception as e:
            logger.warning(f"Background reload failed: {e}")

    asyncio.create_task(reload_in_background())
```

| 更新 ACP 配置 | `PUT /api/config/acp` | 是 |
| 更新心跳配置 | `PUT /api/config/heartbeat` | 是 |
| 更新安全配置 | `PUT /api/config/security/tool-guard` | 是 |

## 2. MultiAgentManager.reload_agent

源码路径：`src/qwenpaw/app/multi_agent_manager.py`

### 2.1 重载方法详解

```python
# reload_agent 完整流程
async def reload_agent(self, agent_id: str) -> None:
    # 1. 获取当前 agent 的 workspace
    workspace = self._workspaces.get(agent_id)
    if not workspace:
        raise ValueError(f"Agent {agent_id} not found")

    # 2. 获取可复用服务（停止旧 workspace 前）
    old_reusable = workspace.service_manager.get_reusable_services()

    # 3. 停止旧 workspace（非 final 服务）
    # final=True 会完全清理，final=False 保留复用
    await workspace.service_manager.stop_all(final=False)

    # 4. 重新加载配置
    agent_config = load_agent_config(agent_id)

    # 5. 重建 workspace
    new_workspace = await self._create_workspace(agent_id, agent_config)

    # 6. 复用可复用服务
    for name, instance in old_reusable.items():
        await new_workspace.service_manager.set_reusable(name, instance)

    # 7. 启动新 workspace
    await new_workspace.service_manager.start_all()

    # 8. 更新 workspaces 字典
    self._workspaces[agent_id] = new_workspace
```

### 2.2 重载状态机

```
┌─────────────┐
│   IDLE     │ ← 初始状态
└──────┬──────┘
       │ reload_agent()
       ▼
┌─────────────┐
│  STOPPING  │ ← 停止旧服务
└──────┬──────┘
       │ stop_all() 完成
       ▼
┌─────────────┐

       │ start_all() 完成

┌─────────────┐
│   IDLE     │ ← 重载完成
```

## 3. 服务复用机制

源码路径：`src/qwenpaw/app/workspace/service_manager.py:94`

### 3.1 set_reusable 方法

```python
# src/qwenpaw/app/workspace/service_manager.py:94
async def set_reusable(self, name: str, instance: Any) -> None:
    """将服务标记为从旧 workspace 复用。

    如果 descriptor 有 reload_func，会被调用。
    """
    if name not in self.descriptors:
        return

    descriptor = self.descriptors[name]
    if not descriptor.reusable:
        return  # 非可复用服务，不处理

    self.services[name] = instance
    self.reused_services.add(name)

    # 调用 reload_func（如果提供）
    if descriptor.reload_func is not None:
        result = descriptor.reload_func(self.workspace, instance)
        if asyncio.iscoroutine(result):
            await result
```

### 3.2 服务类型对比

| 服务类型 | reusable=True | reusable=False |
|----------|---------------|-----------------|
| MemoryManager | 复用记忆数据 | 重建，丢失未持久化数据 |
| 数据库连接 | 复用连接 | 重建连接 |
| 缓存 | 复用缓存 | 清空缓存 |
| Channel (telegram) | 不适用 | 完全重建 |

### 3.3 reload_func 示例

```python
# 服务描述符示例
ServiceDescriptor(
    name="memory_manager",
    factory=create_memory_manager,
    reusable=True,  # 可复用
    reload_func=lambda ws, instance: instance.reload_config(ws.config)
)
```

## 4. 配置监控

### 4.1 Polling mtime 机制

```python
# 配置文件监控使用 mtime 轮询
import os
import asyncio

async def watch_config(config_path: str, poll_interval: float = 5.0):
    last_mtime = os.path.getmtime(config_path)

    while True:
        await asyncio.sleep(poll_interval)

        try:
            current_mtime = os.path.getmtime(config_path)
        except FileNotFoundError:
            continue

        if current_mtime > last_mtime:
            last_mtime = current_mtime
            logger.info(f"Config changed: {config_path}")
            await reload_config(config_path)
```

### 4.2 Polling vs 事件通知对比

| 方式 | 优点 | 缺点 |
|------|------|------|
| Polling mtime | 简单、跨平台、可靠 | 有延迟（通常 1-5 秒） |
| inotify/FSEvents | 实时通知 | 复杂、跨平台差、需要额外依赖 |
| watchdog 库 | 跨平台抽象 | 增加依赖 |

### 4.3 文件监控触发流程

## 5. 热重载与定时任务

### 5.1 CronManager 重载处理

当 Agent 重载时，CronManager 需要同步更新：

```python
# Agent 重载时
await cron_manager.stop()  # 停止旧的调度器
await cron_manager.start()  # 重新启动（加载新配置）
```

### 5.2 热重载对定时任务的影响

| 场景 | 影响 | 处理方式 |
|------|------|----------|
| 修改 cron 表达式 | 下次执行时生效 | 任务队列保持不变 |
| 删除定时任务 | 立即停止 | 从调度器移除 |
| 添加定时任务 | 立即开始调度 | 加入调度器 |

## 6. 应用场景

### 场景 1: Telegram Bot Token 轮换

**问题：** Telegram Bot Token 过期，需要更新但不中断服务

**解决方案：**
```bash
# 更新配置
curl -X PUT http://localhost:8000/api/config/channels/telegram \
  -H "Content-Type: application/json" \
  -d '{"token": "new-bot-token"}'

# 热重载自动：
# 1. 停止旧的 Telegram Channel
# 2. 用新 Token 创建新 Channel
# 3. 启动新 Channel
# 4. 记忆等可复用服务保持不变
```

### 场景 2: 调整记忆压缩阈值

**问题：** 发现上下文耗尽，需要调高压缩阈值

**解决方案：**
```bash
# 更新配置
curl -X PUT http://localhost:8000/api/config/memory \
  -H "Content-Type: application/json" \
  -d '{"compact_threshold": 120000}'

# 热重载自动：
# MemoryManager 复用（reusable=True）
# 新阈值在下一次压缩时生效
```

### 场景 3: 启用新渠道

**问题：** 需要添加新的 Slack 渠道不停机

**解决方案：**

## 7. 最佳实践

### 7.1 热重载安全建议

| 实践 | 说明 |
|------|------|
| 验证配置语法 | 重载前验证 JSON/YAML 格式 |
| 渐进式更新 | 先禁用再启用，避免配置错误 |
| 回滚准备 | 保留旧配置以便快速回滚 |
| 监控重载 | 记录重载成功/失败日志 |

### 7.2 服务设计建议

```python
# 设计服务时考虑可复用性
class MyService:
    def __init__(self, config):
        self.config = config
        # 不依赖具体 workspace

    def reload_config(self, new_config):
        """热重载时更新配置，不重建实例"""
        self.config = new_config
        # 刷新内部状态
        self._refresh()

# 注册为可复用服务
ServiceDescriptor(
    name="my_service",
    factory=create_my_service,
    reusable=True,
    reload_func=lambda ws, inst: inst.reload_config(ws.config)
)
```

## 8. 常见问题

### Q1: 热重载失败，服务不可用

**原因：**
- 新配置语法错误
- 依赖的外部服务不可用
- 重建 workspace 时异常

**排查步骤：**
```python
# 1. 查看重载日志
logger.warning(f"Background reload failed: {e}")

# 2. 检查配置文件
cat .qwenpaw/config.yaml | python -c "import sys, yaml; yaml.safe_load(sys.stdin)"

# 3. 手动重试重载
curl -X POST http://localhost:8000/api/agent/reload

# 4. 如无法恢复，回滚配置
cp .qwenpaw/config.yaml.bak .qwenpaw/config.yaml
```

### Q2: 记忆数据在重载后丢失

**原因：**
- MemoryManager 未标记为 reusable
- 重建时未持久化

**解决方案：**
```python
# 检查服务描述符
service_descriptor = service_manager.descriptors.get("memory_manager")
print(f"reusable: {service_descriptor.reusable}")

# 确保正确配置
ServiceDescriptor(
    name="memory_manager",
    reusable=True,  # 必须为 True
    # ...
)
```

### Q3: 重载卡住无响应

**原因：**
- stop_all() 阻塞
- 旧服务未正确关闭

**解决方案：**
```python
# 设置超时
async def stop_with_timeout(service, timeout=5.0):
    try:
        await asyncio.wait_for(service.stop(), timeout=timeout)
    except asyncio.TimeoutError:
        logger.warning(f"Service stop timeout, forcing")
        service.force_stop()
```

### Q4: 配置文件监控不生效

**原因：**
- 文件写入但 mtime 未更新
- 监控轮询间隔过长

**解决方案：**
```bash
# 手动更新 mtime
touch .qwenpaw/config.yaml

# 或缩短轮询间隔
watch_config(poll_interval=1.0)  # 1 秒
```

## 10. 总结

**核心要点：**

1. **异步触发：** `schedule_agent_reload()` 创建后台任务，不阻塞 API 响应
2. **Workspace 重建：** 旧 Workspace 停止（保留可复用服务），新 Workspace 创建并启动
3. **服务复用：** `reusable=True` 的服务（记忆、缓存）通过 `set_reusable()` 复用
4. **配置监控：** 基于 mtime 轮询，跨平台可靠
5. **状态机：** IDLE → STOPPING → CREATING → REUSING → STARTING → IDLE

**可复用服务示例：**
- MemoryManager（记忆数据）
- 数据库连接
- 缓存实例

**不可复用服务：**
- Channel（Telegram、Slack 等）
- 需要重建的服务

**最佳实践：**
- 设计服务时考虑 `reload_func`
- 配置更新前验证语法
- 保留旧配置以便回滚
- 监控重载成功/失败
