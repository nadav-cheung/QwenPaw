# 消息渠道

## 概述

QwenPaw 支持多种即时通讯渠道，可以将智能体连接到不同的平台。

## 支持的渠道（16 个内置渠道）

| 渠道 | 目录 | 说明 | 协议/特点 |
|------|------|------|-----------|
| DingTalk | dingtalk/ | 钉钉 | Stream SDK |
| Feishu | feishu/ | 飞书/Lark | WebSocket |
| WeChat | weixin/ | 微信 iLink | - |
| WeCom | wecom/ | 企业微信 | - |
| QQ | qq/ | QQ | OneBot 协议 |
| Discord | discord_/ | Discord | Gateway |
| Telegram | telegram/ | Telegram | Polling |
| iMessage | imessage/ | Apple Messages | - |
| Matrix | matrix/ | Matrix | - |
| Mattermost | mattermost/ | Mattermost | - |
| MQTT | mqtt/ | MQTT | 物联网协议 |
| OneBot | onebot/ | 通用 OneBot v11 | WebSocket |
| Voice | voice/ | Twilio 语音 | - |
| Console | console/ | Web Console | Debug |
| XiaoYi | xiaoyi/ | 华为小艺 | - |

## 配置渠道

### 通过 CLI 配置

```bash
# 列出所有已安装的渠道
qwenpaw channels list

# 配置渠道参数
qwenpaw channels config dingtalk

# 安装新渠道
qwenpaw channels install dingtalk --from-path ./my-dingtalk

# 从 URL 安装
qwenpaw channels install my_channel --from-url https://example.com/channel.zip

# 移除渠道
qwenpaw channels remove dingtalk

# 发送测试消息
qwenpaw channels send dingtalk --message "Hello"
```

### 配置文件

渠道配置通过统一的 `~/.qwenpaw/config.json` 管理，无需单独 YAML 文件。每个渠道有对应的 Pydantic 配置模型：

```json
{
  "channels": {
    "dingtalk": {
      "enabled": true,
      "app_key": "your_app_key",
      "app_secret": "your_app_secret"
    },
    "telegram": {
      "enabled": true,
      "bot_token": "your_bot_token"
    }
  }
}
```

> **注意：** QwenPaw 使用 `~/.qwenpaw/config.json` 作为统一配置中心，不使用 `~/.qwenpaw/channels/` 目录存放独立配置文件。

## 渠道工作原理

```
┌─────────┐    Webhook     ┌──────────────┐
│  DingTalk│ ────────────→ │  Channel     │
│  Server  │               │  Handler     │
└─────────┘                └──────┬───────┘
                                  │
                                  ▼
                           ┌──────────────┐
                           │    Agent     │
                           └──────┬───────┘
                                  │
                                  ▼
                           ┌──────────────┐
                           │   Response   │
                           └──────────────┘
```

## BaseChannel 基类

所有渠道继承 `BaseChannel`，核心方法：

```python
class BaseChannel(ABC):
    channel: ChannelType  # 渠道类型标识

    @classmethod
    def from_env(cls, process, on_reply_sent) -> BaseChannel
    @classmethod
    def from_config(cls, process, config, **kwargs) -> BaseChannel
    async def consume_one(self, request: AgentRequest) -> None
    async def _consume_one_request(self, payload: Any) -> None
```

## 消息防抖机制

渠道可以缓冲消息并在延迟后批量发送：

```python
_debounce_seconds: float  # 例如钉钉设置为 0.3s
_pending_content_by_session: Dict[str, List[Any]]  # 待处理内容
```

## 渠道策略

| 策略 | 说明 |
|------|------|
| `dm_policy` | 私聊策略：`open`（开放）或 `allowlist`（白名单） |
| `group_policy` | 群聊策略：`open`（开放）或 `allowlist`（白名单） |
| `require_mention` | 是否需要 @ 机器人 |
| `filter_tool_messages` | 是否过滤工具调用消息 |
| `filter_thinking` | 是否过滤思考过程 |

## 消息格式

不同渠道的消息格式会被统一转换为内部格式：

```python
{
    "channel": "dingtalk",
    "user_id": "user123",
    "content": "用户消息",
    "timestamp": "2024-01-01T12:00:00Z"
}
```

## 注册自定义渠道

如需添加平台支持，可开发自定义渠道并放置于 `~/.qwenpaw/custom_channels/` 目录。

参考 `src/qwenpaw/app/channels/base.py` 实现：

1. 继承 `BaseChannel`
2. 实现 `consume_one()` 方法
3. 在 `registry.py` 中注册渠道
