```python
class MemoryCompactionHook:
    """Hook for automatic memory compaction when context is full.

    当上下文窗口接近限制时自动压缩记忆，
    保留系统提示词和最近消息，总结旧对话历史。
    """
```

### 1.2 压缩触发条件

```python
# src/qwenpaw/agents/hooks/memory_compaction.py:93
# 触发阈值 = memory_compact_threshold - (system_prompt + compressed_summary) tokens
left_compact_threshold = (
    running_config.memory_compact_threshold - str_token_count
)

if left_compact_threshold <= 0:
    logger.warning("memory_compact_threshold 设置过低")
    return None
```

### 1.3 内存结构

```
[System Prompt (保留)] + [可压缩区 (计入 token)] + [最近消息 (保留)]
     ↑                        ↑                              ↑
   始终保留              历史对话摘要                    最近 N 条
```

### 1.4 压缩流程

```python
# src/qwenpaw/agents/hooks/memory_compaction.py:130
# 1. 提取消息
messages = await memory.get_memory(prepend_summary=False)

# 2. 压缩工具结果
if trc.enabled:
    await self.memory_manager.compact_tool_result(
        messages=messages,
        recent_n=trc.recent_n,           # 最近 N 条保留
        old_max_bytes=trc.old_max_bytes,   # 旧消息最大字节
        recent_max_bytes=trc.recent_max_bytes,
        retention_days=trc.retention_days,
    )

# 3. 检查上下文是否超限
messages_to_compact, _, is_valid = await self.memory_manager.check_context(...)

# 4. 生成摘要
if running_config.memory_summary.memory_summary_enabled:
    self.memory_manager.add_async_summary_task(messages_to_compact)

# 5. 执行压缩
if running_config.context_compact.context_compact_enabled:
    compact_content = await self.memory_manager.compact_memory(...)
```

## 2. 并发服务启动

源码路径：`src/qwenpaw/app/workspace/service_manager.py:173`

### 2.1 start_all 方法

```python
# src/qwenpaw/app/workspace/service_manager.py:173
async def start_all(self) -> None:
    """按优先级启动所有服务。

    相同优先级的服务如果允许则并发启动。
    优先级组之间会让出事件循环，以便 HTTP 请求可以被处理。
    """
```

### 2.2 按优先级分组

```python
# src/qwenpaw/app/workspace/service_manager.py:156
def _group_by_priority(self) -> Dict[int, List[ServiceDescriptor]]:
    """按优先级分组"""
    groups: Dict[int, List[ServiceDescriptor]] = {}
    for descriptor in self.descriptors.values():
        if descriptor.priority not in groups:
            groups[descriptor.priority] = []
        groups[descriptor.priority].append(descriptor)
    return groups
```

### 2.3 并发启动逻辑

```python
# src/qwenpaw/app/workspace/service_manager.py:180
for priority in sorted(priority_groups.keys()):
    descriptors = priority_groups[priority]

    # 分离并发和顺序服务
    concurrent = [d for d in descriptors if d.concurrent_init]
    sequential = [d for d in descriptors if not d.concurrent_init]

    # 并发启动
    if concurrent:
        await asyncio.gather(
            *[self._start_service(desc) for desc in concurrent],
        )

    # 顺序启动
    for desc in sequential:
        await self._start_service(desc)

    # 优先级组之间让出事件循环
    await asyncio.sleep(0)
```

### 2.4 ServiceDescriptor 字段

```python
# src/qwenpaw/app/workspace/service_manager.py:29
@dataclass
class ServiceDescriptor:
    name: str                           # 服务唯一标识
    service_class: Optional[type]        # 要实例化的类
    init_args: Optional[Callable]       # 返回初始化参数的 callable
    post_init: Optional[Callable]       # 创建后的钩子
    start_method: Optional[str]         # 启动方法名
    stop_method: Optional[str]           # 关闭方法名
    reusable: bool = False               # 是否可复用
    reload_func: Optional[Callable]      # 复用时的钩子
    dependencies: List[str] = field(default_factory=list)  # 依赖服务
    priority: int = 100                 # 启动优先级（越小越早）
    concurrent_init: bool = True        # 是否可并发初始化
```

### 2.5 线程池 offload


## 6. 常见问题

### 6.1 上下文压缩触发过于频繁

**问题**：压缩钩子频繁触发，影响响应速度。

**原因**：`memory_compact_threshold` 设置过低。

**解决**：调高阈值或减少触发检查频率：
```json
{
  "memory_compact_threshold": 0.85,
  "compact_check_interval": 10
}
```

### 6.2 并发启动时服务依赖缺失

**问题**：服务 A 启动时服务 B 尚未就绪。

**原因**：`concurrent_init=True` 允许同优先级服务并发，但未声明依赖。

**解决**：使用 `dependencies` 字段显式声明依赖：
```python
ServiceDescriptor(
    name="channel_manager",
    dependencies=["runner", "memory_manager"],
    priority=30,
    concurrent_init=False,  # 依赖其他服务，确保顺序
)
```

### 6.3 梦境合并导致信息丢失

**问题**：合并梦境后重要细节丢失。

**原因**：梦境内容被过度压缩。

**解决**：设置 `max_tokens_per_dream` 足够大，或增加 `max_dreams` 数量。

## 练习题

### 基础练习

1. **上下文压缩触发条件**
   `MemoryCompactionHook` 的压缩触发公式为：`left_compact_threshold = memory_compact_threshold - str_token_count`。假设 `memory_compact_threshold` 设为 0.75（即上下文窗口的 75%），`str_token_count` 为 96000，上下文窗口大小为 128000，此时 `left_compact_threshold` 为多少？压缩会被触发吗？

2. **并发启动的优先级分组**
   `ServiceManager` 的 `_group_by_priority` 方法将服务按 `priority` 分组，数值越小优先级越高。请分析：若同时有三个服务 A（priority=10, concurrent_init=True）、B（priority=10, concurrent_init=False）、C（priority=50, concurrent_init=True），它们的启动顺序是什么？每组之间为什么要执行 `await asyncio.sleep(0)`？

3. **重入保护机制**
   `MemoryCompactionHook` 使用 `_REENTRANCY_ATTR = "_memory_compact_hook_running"` 来防止重复执行。请描述：在什么场景下可能出现重复执行？为什么多层 MRO 包装会导致这个问题？

### 进阶练习

1. **梦境合并策略设计**
   当前梦境合并策略包括时间接近、主题相关和大小限制三种。假设有四个梦境片段：DreamA（主题=金融，时间=T1）、DreamB（主题=金融，时间=T2）、DreamC（主题=医疗，时间=T3）、DreamD（主题=金融，时间=T4），T1<T2<T3<T4 且大小均未超过限制。请问按当前策略，哪些梦境会被优先合并？合并顺序是什么？

2. **mtime Polling 与事件通知的选择**
   QwenPaw 选择 mtime Polling 而非 inotify/FSEvents 进行配置文件监控。请从跨平台兼容性、实现复杂度和实时性三个维度，分析两种方案的优劣，并说明为什么 Polling 更适合 QwenPaw 的场景。

### 实战练习

- **ServiceDescriptor 依赖声明**
  在 QwenPaw 中，`ServiceDescriptor` 的 `dependencies` 字段用于声明服务依赖关系，但当前的 `start_all` 实现并未自动解析依赖顺序。请参考 `src/qwenpaw/app/workspace/service_manager.py:173` 的 `start_all` 方法，分析：如果服务 A 声明依赖服务 B，但两者 `priority` 值相同且 `concurrent_init` 都为 True，会出现什么问题？请设计一个解决方案（例如调整 priority 或 concurrent_init），并写出修改后的 `ServiceDescriptor` 配置示例。
