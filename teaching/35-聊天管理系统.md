# 聊天管理系统

## 概述

ChatManager 管理聊天会话规范，支持聊天 CRUD 操作和 JSON 文件持久化。每个 Workspace 有独立的 `chats.json` 文件，实现与其他 Agent 的完全隔离。

## 2. get_or_create_chat 模式

源码路径：`src/qwenpaw/app/runner/manager.py:80`

### 2.1 核心实现

```python
# src/qwenpaw/app/runner/manager.py:80
async def get_or_create_chat(
    self,
    session_id: str,
    user_id: str,
    channel: str = DEFAULT_CHANNEL,
    name: str = "New Chat",
) -> ChatSpec:
    """获取现有聊天或创建新聊天。

    用于来自渠道的聊天自动注册。
    """
    async with self._lock:
        # 尝试通过 session_id 查找现有
        existing = await self._repo.get_chat_by_id(
            session_id, user_id, channel,
        )
        if existing:
            return existing

        # 创建新的
        spec = ChatSpec(
            session_id=session_id,
            user_id=user_id,
            channel=channel,
            name=name,
        )
        await self._repo.upsert_chat(spec)
        return spec
```

## 4. 持久化

### 4.1 BaseChatRepository

```python
class BaseChatRepository(ABC):
    @abstractmethod
    async def load(self) -> ChatsFile:
        raise NotImplementedError

    @abstractmethod
    async def save(self, chats_file: ChatsFile) -> None:
        raise NotImplementedError
```

### 4.2 JsonChatRepository

```python
# src/qwenpaw/app/runner/repo/json_repo.py:13
class JsonChatRepository(BaseChatRepository):
    """chats.json 仓库（单文件存储）"""

    async def save(self, chats_file: ChatsFile) -> None:
        """原子保存到 JSON 文件"""
        tmp_path = self._path.with_suffix(self._path.suffix + ".tmp")
        payload = chats_file.model_dump(mode="json")
        tmp_path.write_text(
            json.dumps(payload, ensure_ascii=False, indent=2, sort_keys=True),
        )
        shutil.move(str(tmp_path), str(self._path))  # 原子替换
```

### 4.3 会话状态（独立于 ChatSpec）

```python
# src/qwenpaw/app/runner/session.py:78
class SafeJSONSession(SessionBase):
    """带文件名清理和异步文件 I/O 的 SessionBase 子类"""

    def _get_save_path(self, session_id: str, user_id: str) -> str:
        safe_sid = sanitize_filename(session_id)
        safe_uid = sanitize_filename(user_id) if user_id else ""
        file_path = f"{safe_uid}_{safe_sid}.json"
        return os.path.join(self.save_dir, file_path)
```

会话文件：`chats.json` 存储在 workspace 目录（如 `~/.qwenpaw/agents/<agent_id>/chats.json`）

## 7. 聊天生命周期

```
1. 渠道接收消息
         ↓
2. Channel._consume_with_tracker() 调用 chat_manager.get_or_create_chat()
         ↓
3. ChatManager 检查仓库中现有聊天
   - 找到：返回现有 ChatSpec
   - 未找到：创建新 ChatSpec（带 UUID）
         ↓
4. TaskTracker.attach_or_start() 链接任务到 chat.id
         ↓
5. Runner 从 SafeJSONSession 加载会话状态
   - 文件：{user_id}_{session_id}.json
         ↓
6. 智能体处理消息，记忆更新
         ↓
7. Runner 保存会话状态到 SafeJSONSession
         ↓
8. Runner 调用 chat_manager.touch_chat() 更新时间戳
```

## 9. 应用场景

### 9.1 渠道会话管理

**场景**：Telegram 用户与 Bot 开始新对话。

**流程**：
1. 用户发送消息到 Telegram Bot
2. `session_id = telegram:<chat_id>`
3. `get_or_create_chat(session_id, user_id, "telegram")` 返回或创建 ChatSpec
4. 消息处理完成后，`touch_chat()` 更新时间戳

### 9.2 聊天列表展示

**场景**：前端显示用户的所有聊天记录。

**API 调用**：
```bash
GET /api/chats?user_id=xxx&channel=telegram
```

返回按 `updated_at` 排序的聊天列表。

### 9.3 聊天状态跟踪

**场景**：显示聊天是否正在处理中。

**状态字段**：
- `status: "idle"` — 空闲
- `status: "running"` — 处理中

### 9.4 聊天置顶

**场景**：用户置顶重要聊天。

**API 调用**：
```bash
PUT /api/chats/{chat_id}
{"pinned": true}
```

## 11. 常见问题

### Q1: chats.json 损坏？

**可能原因**：写入时被强制终止。

**解决方案**：使用原子写入（先写 `.tmp` 再 `move`），可恢复旧文件。

### Q2: 聊天未找到？

**排查**：
1. 确认 `session_id` 格式正确
2. 确认 `user_id` 匹配
3. 确认 `channel` 正确

### Q3: 多实例共享 chats.json？

**问题**：可能导致数据竞争。

**说明**：每个 Workspace 独立文件，不共享。不支持多实例共享同一 Workspace。

### Q4: 如何清理旧聊天？

**方式**：
1. 手动删除：`DELETE /api/chats/{chat_id}`
2. 批量删除：`POST /api/chats/batch-delete`
3. 只删除 ChatSpec，不删除会话文件

### Q5: 会话文件与聊天不同步？

**说明**：这是预期行为。ChatSpec 管理聊天元数据，会话文件管理记忆历史。删除聊天不会自动删除会话文件。
