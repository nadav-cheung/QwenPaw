## 概述

QwenPaw 的架构设计体现多个核心原则：模块化、可扩展性、安全性和开发者体验的平衡。通过 Workspace 隔离、ServiceManager 统一生命周期管理和两阶段启动，实现单进程多 Agent 的高效运行。

## 3. 核心架构模式

### 3.1 声明式服务定义

**源码路径**: `src/qwenpaw/app/workspace/service_manager.py:36`

所有 Workspace 组件通过 `ServiceDescriptor` 声明式定义：

```python
ServiceDescriptor(
    name="cron_manager",
    service_class=CronManager,
    init_args=lambda ws: {
        "repo": JsonJobRepository(
            str(ws.workspace_dir / "jobs.json"),
        ),
        "runner": ws._service_manager.services["runner"],
        "channel_manager": ws._service_manager.services.get("channel_manager"),
        "timezone": load_config().user_timezone or "UTC",
        "agent_id": ws.agent_id,
    },
    start_method="start",
    stop_method="stop",
    priority=40,
    concurrent_init=False,
)
```

**优势**:
1. 服务依赖显式声明（priority + dependencies）
2. 支持可复用组件热重载
3. 统一的生命周期管理
4. 便于测试和替换

### 3.2 热重载机制

**源码路径**: `src/qwenpaw/app/workspace/workspace.py:280`

```
旧 Workspace 停止
    │
    ├── 标记可复用组件（memory_manager, chat_manager）
    │
    ▼
新 Workspace 创建
    │
    ├── set_reusable_components() 注入旧组件
    │
    ▼
新 Workspace 启动
    │
    └── 跳过已复用组件的初始化
```

### 3.3 并发初始化

**源码路径**: `src/qwenpaw/app/workspace/service_manager.py:180`

```python
async def start_all(self) -> None:
    """启动所有服务，按优先级排序。

    concurrent_init=True 的服务会并发初始化，
    提高启动速度。
    """
    # 按 priority 分组
    groups = defaultdict(list)
    for name, desc in self.descriptors.items():
        groups[desc.priority].append(desc)

    # 按优先级顺序启动
    for priority in sorted(groups.keys()):
        descriptors = groups[priority]
        if all(d.concurrent_init for d in descriptors):
            # 并发启动同优先级的服务
            await asyncio.gather(*[
                self._start_service(desc) for desc in descriptors
            ])
        else:
            # 串行启动
            for desc in descriptors:
                await self._start_service(desc)
```

## 7. 设计思维总结

### 7.1 模块化设计

每个模块有明确的职责边界：
- Workspace 管理单个 Agent 的运行时
- ServiceManager 统一管理生命周期
- ChannelManager 管理多渠道通信
- ProviderManager 管理多 LLM 提供商

### 7.2 声明式优于命令式

通过 `ServiceDescriptor` 声明服务依赖和优先级，而不是在代码中硬编码启动顺序，使系统更易于理解和修改。

### 7.3 安全性默认启用

ToolGuard 默认启用，敏感路径默认保护，认证可选但推荐启用。
