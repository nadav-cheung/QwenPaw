## 概述

QwenPaw 支持将消息从任一渠道路由到其他渠道，实现跨渠道的统一消息管理和会话桥接，支持主动发送和被动接收两种模式。

`★ Insight ─────────────────────────────────────`
- 跨渠道消息路由的核心是**渠道抽象**：所有渠道实现统一的 `send()` 接口，路由层无需关心底层协议差异
- `channel + user_id` 的会话聚合实现了**跨渠道身份统一**：同一用户在不同渠道的消息汇聚到同一会话
- 主动发送（Proactive）和被动接收（Passive）的区分是**交互模式**的抽象：前者由 Agent 驱动，后者由外部事件驱动
`─────────────────────────────────────────────────`

## 1. 消息路由 API

源码路径：`src/qwenpaw/app/routers/messages.py`

### 1.1 SendMessageRequest

```python
# src/qwenpaw/app/routers/messages.py:40
class SendMessageRequest(BaseModel):
    channel: str           # 目标渠道 (console, dingtalk, feishu, discord)
    target_user: str      # 目标用户 ID
    target_session: str   # 目标会话 ID
    text: str             # 消息内容
```

### 1.2 API 端点

```python
# src/qwenpaw/app/routers/messages.py:77
@router.post("/send", response_model=SendMessageResponse)
async def send_message(
    request: SendMessageRequest,
    http_request: Request,
    x_agent_id: Optional[str] = Header(None, alias="X-Agent-Id"),
) -> SendMessageResponse:
    """向渠道发送文本消息"""
    # 1. 获取 MultiAgentManager
    manager = _get_multi_agent_manager(http_request)

    # 2. 获取 agent
    agent = manager.get_agent(x_agent_id)

    # 3. 通过 channel_manager 发送
    await agent.workspace.channel_manager.send_text(
        channel=request.channel,
        user_id=request.target_user,
        session_id=request.target_session,
        text=request.text,
    )

    return SendMessageResponse(success=True, message="Message sent successfully")
```

## 2. 路由流程

### 2.1 发送流程

```

    ↓
workspace.channel_manager.send_text()
    ↓
BaseChannel.send() 实现
    ↓

```

### 2.2 获取 Manager

```python
# src/qwenpaw/app/routers/messages.py:19
def _get_multi_agent_manager(request: Request):
    """从 app state 获取 MultiAgentManager"""
    if not hasattr(request.app.state, "multi_agent_manager"):
        raise HTTPException(status_code=500, detail="MultiAgentManager not initialized")
    return request.app.state.multi_agent_manager
```

async def send_text(
    channel: str,
    user_id: str,
    session_id: str,

import httpx

async def send_message():

## 7. 错误处理

### 7.1 错误码

| 状态码 | 原因 | HTTPException detail |
|--------|------|----------------------|
| 400 | 请求参数缺失 | "field required" |
| 404 | Agent 不存在 | `Agent not found: {agent_id}` |
| 404 | 渠道不存在 | `Channel not found: {channel}` |
| 500 | ChannelManager 未初始化 | `Channel manager not initialized` |
| 500 | 发送失败 | `Failed to send message: {error}` |

### 7.2 异常处理

```python
# src/qwenpaw/app/routers/messages.py:120
try:
    await channel_manager.send_text(...)
except KeyError as e:
    raise HTTPException(status_code=404, detail=f"Channel not found: {channel}")
except AttributeError as e:
    raise HTTPException(status_code=500, detail="Channel manager not initialized")
except Exception as e:
    raise HTTPException(status_code=500, detail=f"Failed to send message: {str(e)}")
```

## 10. 最佳实践

1. **session_id 规范化**：使用 `hash(channel + user_id)` 确保同一用户跨渠道会话关联
2. **渠道能力检查**：发送前检查渠道是否支持 `send()` 方法，避免运行时错误
3. **错误处理**：渠道发送失败时应记录日志并返回明确错误信息
4. **消息脱敏**：日志中避免记录敏感消息内容
5. **渠道隔离**：不同渠道的错误不应相互影响，使用 try/except 独立处理

## 来自 Java 的你

### 核心概念对照

| Java | Python / QwenPaw | 说明 |
|------|-------------------|------|
| Spring Integration Router | `ChannelRouter` / `ChannelManager.send_text()` | Spring Integration 用 `<router>` XML 或 `@Router` 注解做消息路由，QwenPaw 通过 channel 字符串查找渠道实例 |
| Content-Based Router (EIP) | 渠道选择器 (`channel` 参数) | EIP 模式中的内容路由器根据消息内容决定目标，QwenPaw 根据 `channel` 字段分发到不同渠道实现 |
| `MessageChannel` (Spring Integration) | `BaseChannel` 基类 | Spring Integration 的 MessageChannel 是消息端点接口，BaseChannel 定义了统一的 `send()` 抽象 |
| Aggregator (EIP) | 会话聚合 (`hash(channel + user_id)`) | Spring Integration Aggregator 聚合相关消息，QwenPaw 通过 channel+user_id 哈希实现跨渠道会话归一 |
| `@Router` 注解 | routing logic (API 路由) | Spring 用 `@Router` 注解标记路由方法，QwenPaw 在 API 端点中通过 `channel_manager.send_text()` 执行路由逻辑 |

### 关键差异

Spring Integration 是完整的 EIP（企业集成模式）实现，提供消息通道、路由器、聚合器、过滤器等完整组件链；QwenPaw 的跨渠道路由更轻量，核心只是一个字符串到渠道实例的映射查找。Java 开发者需要注意：这里没有消息队列（MQ），路由是同步的直接调用，不像 Spring Integration 默认使用 `DirectChannel` 或 `QueueChannel` 做消息缓冲。

## 11. 常见问题

### Q1: 如何添加新渠道？

1. 在 `src/qwenpaw/app/channels/` 下创建新渠道目录
2. 实现 `BaseChannel` 接口的 `send()` 方法
3. 在 `ChannelManager` 中注册新渠道

```python
class BaseChannel(ABC):
    @abstractmethod
    async def send(self, to_handle: str, text: str, meta: Optional[dict]) -> None:
        ...
```

### Q2: 渠道发送失败会重试吗？

当前不自动重试。发送失败后抛出异常，由调用方决定是否重试。建议上层实现重试逻辑（如指数退避）。

### Q3: 如何跟踪消息发送状态？

消息发送是同步的，成功即送达。但部分渠道（如 Telegram）可能有回执机制，需渠道实现方支持。

### Q4: Console 渠道的 `send()` 和 `send_content_parts()` 区别？

- `send()`：发送纯文本消息
- `send_content_parts()`：发送结构化内容（图片、视频、文件等）
