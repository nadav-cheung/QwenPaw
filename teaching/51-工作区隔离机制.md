本章节详细解析 Workspace 核心组件、服务注册与生命周期管理、多智能体调度机制，以及异步上下文隔离的实现原理。

## 1. Workspace 核心

源码路径：`src/qwenpaw/app/workspace/workspace.py`

### 1.1 Workspace 类

```python
# src/qwenpaw/app/workspace/workspace.py:49
class Workspace:
    """单个智能体工作区，拥有独立运行时组件。

    每个 Workspace 包含：
    - Runner: 处理智能体请求
    - ChannelManager: 管理通信渠道
    - BaseMemoryManager: 管理对话记忆
    - MCPClientManager: 管理 MCP 客户端
    - CronManager: 管理定时任务
    """
    def __init__(self, agent_id: str, workspace_dir: str):
        self.agent_id = agent_id
        self.workspace_dir = Path(workspace_dir).expanduser()
        self._service_manager = ServiceManager(self)
        self._task_tracker = TaskTracker()
```

**核心职责：**
- Workspace 是 QwenPaw 的**per-agent 隔离单元**
- 每个 Workspace 拥有独立的文件系统路径、配置、服务实例
- 通过组合模式聚合多个服务组件（Runner、ChannelManager 等）

### 1.2 服务注册

```python
# src/qwenpaw/app/workspace/workspace.py:141
def _register_services(self) -> None:
    sm.register(ServiceDescriptor(
        name="runner",
        service_class=AgentRunner,
        init_args=lambda ws: {...},
        stop_method="stop",
        priority=10,
        concurrent_init=False,
    ))
```

**注册流程：**
1. 按优先级（priority）排序所有服务
2. 同一优先级的服务按 `concurrent_init` 标志决定并发或顺序启动
3. 高优先级服务（如 runner）先启动，确保依赖服务就绪

### 1.3 优先级顺序

| 优先级 | 服务 | 并发初始化 | 依赖说明 |
|--------|------|----------|----------|
| 10 | runner | No | 最基础服务，其他服务可能依赖 Runner |
| 20 | memory_manager, mcp_manager, chat_manager | Yes | 相互无依赖，可并发初始化 |
| 25 | runner_start | No | 依赖 runner 已完全启动 |
| 30 | channel_manager | No | 可能依赖 runner 初始化完成 |
| 40 | cron_manager | No | 定时任务调度器 |
| 50 | agent_config_watcher | No | 配置热重载监听 |

## 2. ServiceDescriptor 声明式配置

源码路径：`src/qwenpaw/app/workspace/service_manager.py:32`

```python
# src/qwenpaw/app/workspace/service_manager.py:32
@dataclass
class ServiceDescriptor:
    name: str                              # 唯一标识
    service_class: Optional[type]          # 实例化类
    init_args: Optional[Callable]         # 初始化参数
    post_init: Optional[Callable]         # 创建后钩子
    start_method: Optional[str]            # 启动方法名
    stop_method: Optional[str]             # 停止方法名
    reusable: bool = False                # 是否可复用
    priority: int = 100                  # 启动优先级

```

### 2.1 字段详解

| 字段 | 类型 | 说明 |
|------|------|------|
| `name` | str | 服务唯一标识，用于日志和调试 |
| `service_class` | type | 服务的类定义，实例化时调用 |
| `init_args` | Callable | 接收 Workspace 返回初始化参数的函数 |
| `post_init` | Callable | 实例创建后立即执行的钩子 |
| `start_method` | str | 启动方法名（默认 `start`） |
| `stop_method` | str | 停止方法名（默认 `stop`） |
| `reusable` | bool | True 时重载不重建，保留状态 |
| `priority` | int | 启动顺序，数字越小越先启动 |
| `concurrent_init` | bool | 同优先级是否并发初始化 |

## 3. ServiceManager 生命周期

源码路径：`src/qwenpaw/app/workspace/service_manager.py`

### 3.1 启动

```python
# src/qwenpaw/app/workspace/service_manager.py:153
async def start_all(self) -> None:
    # 按优先级分组启动
    for priority in sorted(priority_groups.keys()):
        group = priority_groups[priority]
        concurrent = [d for d in group if d.concurrent_init]
        sequential = [d for d in group if not d.concurrent_init]

        # 1. 并发启动允许并发的服务
        if concurrent:
            await asyncio.gather(*[self._start_service(d) for d in concurrent])

        # 2. 顺序启动非并发服务
        for desc in sequential:
            await self._start_service(desc)

        # 3. 让出事件循环，避免长时间阻塞
        await asyncio.sleep(0)
```

**启动策略：**
- **优先级分组**：同优先级的服务一起考虑
- **并发初始化**：无依赖的服务并发启动，加速整体启动
- **顺序启动**：有依赖链的服务按声明顺序串行启动
- **事件循环让出**：每批次启动后让出控制权，支持高并发场景

### 3.2 停止

```python
# src/qwenpaw/app/workspace/service_manager.py:275
async def stop_all(self, final: bool = False) -> None:
    # 逆优先级顺序停止
    for priority in sorted(priority_groups.keys(), reverse=True):
        descriptors = priority_groups[priority]
        await asyncio.gather(*[self._stop_service(d) for d in descriptors])
```

**停止策略：**
- **逆序停止**：后启动的服务先停止（如 channel_manager 在 runner 之前停止）
- **并发停止**：同优先级的服务并发停止，提高停止效率
- **final 标志**：标识是否为最终关闭，影响某些服务的清理行为

## 4. MultiAgentManager

源码路径：`src/qwenpaw/app/multi_agent_manager.py`

### 4.1 惰性加载

```python
# src/qwenpaw/app/multi_agent_manager.py:41
async def get_agent(self, agent_id: str) -> Workspace:
    """惰性加载 + 去重"""
    if agent_id in self.agents:
        return self.agents[agent_id]

    async with self._lock:
        # 双重检查锁定（DCLP）
        if agent_id in self.agents:
            return self.agents[agent_id]

        # 创建新实例（锁外进行，支持并行）
        instance = Workspace(agent_id=agent_id, workspace_dir=...)
        await instance.start()
        self.agents[agent_id] = instance
        return instance
```

**去重机制：**
- **第一次检查**（无锁）：快速路径，已加载的 Agent 直接返回
- **第二次检查**（有锁）：多协程并发时防止重复创建
- **锁外初始化**：`instance.start()` 在锁外执行，不阻塞其他 Agent 启动

### 4.2 零停机重载

```python
# src/qwenpaw/app/multi_agent_manager.py:165
async def reload_agent(self, agent_id: str) -> bool:
    # 1. 创建新工作区（锁外进行，耗时长）
    new_instance = Workspace(agent_id=agent_id, workspace_dir=...)
    await new_instance.start()

    # 2. 原子替换旧实例
    async with self._lock:
        old_instance = self.agents.get(agent_id)
        self.agents[agent_id] = new_instance

    # 3. 延迟停止旧实例（确保新实例已接管）
    if old_instance:
        await asyncio.sleep(0)  # 让出控制权
        await old_instance.stop()

    return True
```

**零停机原理：**
- 新旧实例短暂共存，新实例先接管请求
- 旧实例在无活跃请求后优雅关闭
- 用户感知不到重载中断

## 5. ContextVar 异步隔离

源码路径：`src/qwenpaw/app/agent_context.py`

### 5.1 核心定义

```python
# src/qwenpaw/app/agent_context.py
_current_agent_id: ContextVar[Optional[str]] = ContextVar("current_agent_id", default=None)
_current_session_id: ContextVar[Optional[str]] = ContextVar("current_session_id", default=None)
```

**ContextVar 的优势：**
- **协程安全**：每个协程有独立的值副本
- **自动传递**：在 `async with` 块中自动继承外层值
- **无锁开销**：比 threading.local 更轻量

### 5.2 AgentContextMiddleware

```python
# src/qwenpaw/app/routers/agent_scoped.py:14
class AgentContextMiddleware(BaseHTTPMiddleware):
    async def dispatch(self, request: Request, call_next):
        agent_id = None

        # 优先级 1: 路径提取 /api/agents/{agentId}/...
        path_parts = request.url.path.split("/")
        if len(path_parts) >= 4 and path_parts[2] == "agents":
            agent_id = path_parts[3]

        # 优先级 2: X-Agent-Id header
        if not agent_id:
            agent_id = request.headers.get("X-Agent-Id")

        # 优先级 3: 查询参数
        if not agent_id:
            agent_id = request.query_params.get("agent_id")

        # 设置上下文变量
        token = set_current_agent_id(agent_id)
        try:
            response = await call_next(request)
        finally:
            reset_current_agent_id(token)

        return response
```

**多层回退机制：**
1. URL 路径（如 `/api/agents/agent-123/chats`）
2. HTTP Header（`X-Agent-Id`）
3. 查询参数（`?agent_id=agent-123`）

## 8. 设计模式

### 8.1 声明式服务注册

```python
# 替代硬编码初始化，声明式更灵活
sm.register(ServiceDescriptor(
    name="runner",
    priority=10,
    concurrent_init=False,
    ...
))
```

**优势：**
- 配置与代码分离，调整启动顺序无需修改业务逻辑
- 易于单元测试：可注册 mock 服务替代真实实现
- 支持动态增删服务

### 8.2 锁外并行初始化

```python
# 快速释放锁，允许其他 Agent 并行启动
instance = Workspace(...)      # 锁外：创建实例
await instance.start()        # 锁外：初始化（可能耗时）
async with self._lock:        # 锁内：快速交换
    self.agents[agent_id] = instance
```

**性能收益：**
- 多个 Agent 同时启动时，初始化并行化
- 锁只保护字典写操作，持有时间极短

### 8.3 可复用服务

```python
# reusable=True 的服务在重载时保留
reusable=True  # memory_manager, chat_manager 保留状态
reusable=False  # runner, mcp_manager 每次重建
```

**重载场景：**
- 只改配置时：复用服务，保留内存状态
- 配置变更不影响时：避免不必要的服务重启

## 9. 应用场景

### 9.1 多租户 SaaS 平台

**场景：** 企业级 SaaS 需要为每个租户提供隔离的 AI 智能体服务。

**实现：**
```python
# 为每个租户创建独立 Workspace
async def provision_tenant(tenant_id: str):
    workspace = await agent_manager.get_agent(f"tenant-{tenant_id}")
    # 租户间完全隔离，数据不泄露
```

**隔离保证：**
- 文件系统隔离：租户 A 无法读写租户 B 的工作区文件
- 内存隔离：ContextVar 确保请求路由到正确的租户上下文
- 配置隔离：每个租户有独立的 agent.json

### 9.2 开发/生产环境分离

**场景：** 同一进程运行多个环境，避免互相干扰。

**实现：**
```bash
# 启动两个 Workspace
qwenpaw agents --agent dev --port 8081
qwenpaw agents --agent prod --port 8082
```

### 9.3 热重载配置不丢失会话

**场景：** 更新 Agent 提示词或工具配置时，保持现有用户会话。

**实现：**
```python
# reload_agent 只重建 runner，不重建 memory_manager
# 用户会话历史保留
await agent_manager.reload_agent("my-agent")
```

## 10. 常见问题

### Q1: Agent 启动失败如何排查？

**排查步骤：**
1. 检查日志中的 `ServiceManager` 启动顺序
2. 确认依赖服务是否先于依赖方启动
3. 检查 Workspace 目录权限
4. 查看 `agent.json` 配置是否有效

**常见错误：**
```
ServiceNotFoundError: Service 'runner' not found
→ 检查 _register_services() 是否正确注册
```

### Q2: 如何解决 ContextVar 值丢失问题？

**原因：** 中间件未正确设置上下文，或异步调用链断裂。

**解决：**
```python
# 确保所有入口都通过 AgentContextMiddleware
app.add_middleware(AgentContextMiddleware)

# 手动传递 context（如果需要跨线程）
token = set_current_agent_id(agent_id)
# ... 在同一协程内使用
reset_current_agent_id(token)
```

### Q3: 重载后内存占用增加如何处理？

**原因：** 旧 Workspace 实例未完全释放。

**解决：**
```python
# 确保 stop() 被调用且无引用
import gc
gc.collect()  # 强制垃圾回收
```

### Q4: 多个 Agent 并发启动时性能下降？

**原因：** 锁竞争严重，或服务初始化串行化。

**优化：**
```python
# 确保同类服务使用 concurrent_init=True
sm.register(ServiceDescriptor(
    name="mcp_manager",
    concurrent_init=True,  # 允许多个 MCP Manager 并发初始化
    ...
))
```

# A 启动后，B 在更高优先级时启动

## 12. 总结

### 核心要点

| 要点 | 说明 |
|------|------|
| **隔离单元** | Workspace 是 per-agent 隔离实体，拥有独立服务组合 |
| **声明式注册** | ServiceDescriptor 替代硬编码，支持灵活配置启动顺序 |
| **优先级驱动** | 数字越小越先启动，支持并发/顺序两种模式 |
| **惰性加载** | 首次访问时才创建实例，减少启动开销 |
| **零停机重载** | 新旧实例短暂共存，原子替换保证服务连续性 |
| **ContextVar 隔离** | 协程级别的请求上下文隔离，无需锁 |
| **可复用服务** | 重载时保留无状态或状态需保留的服务 |

### 架构优势

1. **多租户安全**：文件系统 + 内存双重隔离
2. **高性能**：锁外并行初始化，加速大规模部署
3. **高可用**：零停机重载，支持配置变更不中断服务
4. **可测试**：声明式注册便于注入 mock 服务
