## 概述

QwenPaw 支持多种部署方式，包括 pip 安装、Docker 容器、本地模型（Ollama/LM Studio）和阿里云 ECS。本教程详细介绍各种部署方式、配置选项、运维工具和故障排查。

## 1. 部署方式概览

| 方式 | 适用场景 | 优点 | 缺点 |
|------|---------|------|------|
| pip 安装 | 个人用户 | 简单，快速 | 需要手动管理依赖 |
| Docker | 服务器部署 | 环境隔离，可移植 | 资源占用较高 |
| 桌面应用 | 非技术用户 | 零配置 | 功能受限 |
| 阿里云 ECS | 云端部署 | 一键部署，可扩展 | 需要云账号 |

## 2. pip 安装

### 2.1 基本安装

```bash
# 安装
pip install qwenpaw

# 初始化（交互式）
qwenpaw init

# 初始化（使用默认配置）
qwenpaw init --defaults

# 启动
qwenpaw app
```

### 2.2 从源码安装

```bash
# 克隆仓库
git clone https://github.com/agentscope-ai/QwenPaw.git
cd QwenPaw

# 构建前端
cd console && npm ci && npm run build
cd ..

# 复制前端构建产物
mkdir -p src/qwenpaw/console
cp -R console/dist/. src/qwenpaw/console/

# 安装 Python 包
pip install -e .

# 开发模式（包含测试依赖）
pip install -e ".[dev,full]"
```

### 2.3 安装选项

```bash
# 安装指定版本
pip install qwenpaw==1.1.2

# 升级
pip install --upgrade qwenpaw

# 卸载
pip uninstall qwenpaw
```

## 3. Docker 部署

### 3.1 基本使用

```bash
# 拉取镜像
docker pull agentscope/qwenpaw:latest

# 运行容器
docker run -p 127.0.0.1:8088:8088 \
  -v qwenpaw-data:/app/working \
  -v qwenpaw-secrets:/app/working.secret \
  -v qwenpaw-backups:/app/working.backups \
  agentscope/qwenpaw:latest
```

### 3.2 国内镜像

```bash
# 阿里云 ACR
docker pull agentscope-registry.ap-southeast-1.cr.aliyuncs.com/agentscope/qwenpaw:latest
```

### 3.3 Docker Compose

```yaml
# docker-compose.yml
version: '3.8'

services:
  qwenpaw:
    image: agentscope/qwenpaw:latest
    ports:
      - "127.0.0.1:8088:8088"
    volumes:
      - qwenpaw-data:/app/working
      - qwenpaw-secrets:/app/working.secret
      - qwenpaw-backups:/app/working.backups
    environment:
      - DASHSCOPE_API_KEY=${DASHSCOPE_API_KEY}
    restart: unless-stopped

volumes:
  qwenpaw-data:
  qwenpaw-secrets:
  qwenpaw-backups:
```

### 3.4 连接本地 Ollama

```bash
# 方式 A：使用 host.docker.internal（通用）
docker run -p 127.0.0.1:8088:8088 \
  --add-host=host.docker.internal:host-gateway \
  -v qwenpaw-data:/app/working \
  agentscope/qwenpaw:latest

# 然后在 QwenPaw 设置中配置：
# Ollama Base URL: http://host.docker.internal:11434

# 方式 B：使用主机网络（仅 Linux）
docker run --network=host \
  -v qwenpaw-data:/app/working \
  agentscope/qwenpaw:latest
```

### 3.5 自定义构建

```bash
# 构建镜像
cd QwenPaw
docker build -t my-qwenpaw:latest .

# 推送
docker push my-registry/my-qwenpaw:latest
```

## 6. 系统配置

### 6.1 环境变量架构

**源码路径**: `src/qwenpaw/envs/`

**两层持久化架构**:
```
┌─────────────────────────────────────────┐
│  envs.json (SECRET_DIR/envs.json)      │ ← 加密持久化
├─────────────────────────────────────────┤
│  os.environ                            │ ← 当前进程注入
└─────────────────────────────────────────┘
```

**核心函数** (store.py):

| 函数 | 行号 | 功能 |
|------|------|------|
| `load_envs()` | 124-161 | 加载并解密envs.json |
| `save_envs()` | 168-197 | 加密写入envs.json并同步到os.environ |
| `set_env_var()` | 199-204 | 设置单个环境变量 |
| `delete_env_var()` | 206-211 | 删除单个环境变量 |
| `load_envs_into_environ()` | 213-231 | 加载envs并注入os.environ |

**启动流程**:
```
qwenpaw/__init__.py
    │
    ▼
load_envs_into_environ()
    │
    ▼
load_envs() → 解密 envs.json
    │
    ▼
_apply_to_environ() (排除保护键)
    │
    ▼
os.environ 获得所有env vars
```

**Legacy CoPAW支持** (constant.py:16-24):
- 自动回退到 `COPAW_*` 前缀的变量名
- 例如: `QWENPAW_WORKING_DIR` 不存在时检查 `COPAW_WORKING_DIR`

**保护引导键** (store.py:70-77):
```python
_PROTECTED_BOOTSTRAP_KEYS = frozenset({
    "QWENPAW_WORKING_DIR",
    "QWENPAW_SECRET_DIR",
})
```
这些键排除在os.environ注入之外，因为必须从进程/系统环境获取才能定位密钥目录。

## 7. 运维命令

### 7.1 诊断命令 (Doctor System)

**源码路径**: `src/qwenpaw/cli/doctor*.py`

**核心模块**:

| 文件 | 功能 |
|------|------|
| `doctor_cmd.py` | CLI入口和检查编排 |
| `doctor_checks.py` | 核心健康检查函数 |
| `doctor_connectivity.py` | 深度网络连通性探测 |
| `doctor_fix_runner.py` | 保守文件系统修复 |
| `doctor_registry.py` | 可扩展插件钩子系统 |

**检查类别**:

| 类别 | 检查内容 |
|------|----------|
| **环境** | Python版本/平台/sqlite版本/磁盘空间 |
| **配置** | config.json schema验证/未知键扫描 |
| **Agent** | workspace目录/agent.json有效性 |
| **渠道凭证** | 15种渠道的静态凭证检查 |
| **MCP客户端** | stdio命令存在性/HTTP URL验证 |
| **模型连接** | 每个Agent的模型连通性测试 |
| **浏览器** | Playwright包/DISPLAY环境变量 |
| **安全基线** | tool_guard/skill_scanner/file_guard启用状态 |
| **记忆/嵌入** | force_memory_search的嵌入API密钥 |
| **工作空间卫生** | 大文件/过多tool_result/全局内存树 |
| **Cron jobs** | jobs.json schema验证 |

**深度连通性探测** (`--deep` 标志):

| 渠道 | 探测方法 |
|------|----------|
| mqtt | TCP socket到host:port |
| mattermost | HTTP GET api/v4/system/ping |
| telegram | HTTP GET api.telegram.org |
| feishu/dingtalk | HTTP GET 各自API根URL |
| discord | HTTP GET gateway URL |
| voice (Twilio) | HTTP GET api.twilio.com |

**修复系统** (`qwenpaw doctor fix`):

| 风险级别 | 修复ID |
|----------|--------|
| 安全 | `ensure-working-dir`, `ensure-workspace-dirs` |
| 只读 | `validate-all-jobs-json` |
| 同步 | `reconcile-workspace-skills` |
| 风险 | `seed-missing-agent-json`, `reset-invalid-agent-json` |

**扩展系统**: 插件可通过 `qwenpaw.doctor` 入口点注册贡献

```bash
# 系统诊断
qwenpaw doctor

# 深度检查(含渠道连通性)
qwenpaw doctor --deep

# 修复问题
qwenpaw doctor fix
```

### 7.2 日志管理

**源码路径**: `src/qwenpaw/utils/logging.py`

### 7.2.1 日志配置

**常量定义**:

| 常量 | 值 | 说明 |
|------|-----|------|
| `_LOG_MAX_BYTES` | `5 * 1024 * 1024` | RotatingFileHandler 单文件最大 5MiB |
| `_LOG_BACKUP_COUNT` | `3` | 保留 3 个备份文件 |
| `LOG_FILE_BASENAME` | `{project_name}.log` | 日志文件名 |
| `LOG_NAMESPACE` | `qwenpaw` | 顶层 logger 名称 |

### 7.2.2 日志格式化器

| 类 | 行号 | 功能 |
|----|------|------|
| `ColorFormatter` | 第52行 | ANSI 彩色格式化器，根据日志级别着色 (DEBUG蓝/INFO绿/WARNING黄/ERROR红) |
| `PlainFormatter` | 第76行 | 纯文本格式化器，格式: `timestamp | level | filepath:lineno | message` |
| `SuppressPathAccessLogFilter` | 第90行 | 过滤指定路径的 uvicorn 访问日志 |

**ColorFormatter 颜色映射**:

| 日志级别 | ANSI 代码 | 颜色 |
|----------|----------|------|
| DEBUG | `\033[34m` | 蓝色 |
| INFO | `\033[32m` | 绿色 |
| WARNING | `\033[33m` | 黄色 |
| ERROR | `\033[31m` | 红色 |
| CRITICAL | `\033[41m\033[97m` | 红底白字 |

**注意**: 非 TTY 输出 (管道/重定向) 自动禁用颜色。

### 7.2.3 核心函数

| 函数 | 行号 | 功能 |
|------|------|------|
| `setup_logger()` | 第111行 | 配置日志，仅输出项目命名空间的日志，抑制第三方日志 |
| `add_project_file_handler()` | 第139行 | 添加文件处理器，macOS 使用 RotatingFileHandler，Windows/Linux 使用普通 FileHandler |

**setup_logger 行为**:
- 抑制第三方 handler (level 设为 WARNING)
- 设置 `logger.propagate = False` 防止重复输出
- 直接写入 `sys.stderr` 避免测试缓冲问题

**add_project_file_handler 幂等性**:
- 检查是否已存在同路径的 handler，避免重复添加

### 7.2.4 Windows ANSI 支持

`_enable_windows_ansi()` (第36行): 通过 `ctypes` 调用 `kernel32.dll` 启用 Windows 10+ 的 ANSI 转义码支持，模块导入时自动调用。

### 7.2.5 日志查看

日志文件位于 `~/.qwenpaw/logs/`，使用 `tail` 命令查看：

```bash
# 查看日志
tail -f ~/.qwenpaw/logs/qwenpaw.log

```

## 10. 故障排查

### 10.1 常见问题

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 端口被占用 | 8088 端口已使用 | 使用 `--port` 换端口 |
| 权限错误 | 目录权限不足 | `chmod -R 755 ~/.qwenpaw` |
| 模型连接失败 | API Key 错误 | 检查配置，重新设置 |
| 前端加载慢 | 网络问题 | 使用本地构建 |
| Docker 内存不足 | 容器资源限制 | 增加内存限制 |

### 10.2 日志分析

```bash
# 查找错误
grep -i error ~/.qwenpaw/logs/qwenpaw.log

# 查找特定模块
grep -i "provider" ~/.qwenpaw/logs/qwenpaw.log

# 实时错误跟踪
tail -f ~/.qwenpaw/logs/qwenpaw.log | grep -i error
```

### 10.3 网络问题

```bash
# 检查端口
lsof -i :8088

# 检查网络连接
curl -v http://127.0.0.1:8088/api/health

# 检查代理设置
echo $HTTP_PROXY
echo $HTTPS_PROXY
```

## 13. Tunnel 系统 (Cloudflare Quick Tunnel)

**源码路径**: `src/qwenpaw/tunnel/`

### 13.1 概述

Tunnel 模块通过 Cloudflare Quick Tunnel 将本地服务暴露到互联网，主要用于 Voice 渠道的 Twilio webhook 回调。

### 13.2 核心组件

| 组件 | 文件 | 说明 |
|------|------|------|
| `CloudflareTunnelDriver` | `cloudflare.py` | Tunnel 驱动程序 |
| `TunnelInfo` | `cloudflare.py` 第25行 | 隧道信息数据类 |
| `BinaryManager` | `binary_manager.py` | cloudflared 二进制自动下载 |

### 13.3 TunnelInfo 数据类

```python
@dataclass
class TunnelInfo:
    public_url: str       # "https://abc123.trycloudflare.com"
    public_wss_url: str   # "wss://abc123.trycloudflare.com"
    started_at: datetime
    pid: Optional[int] = None
```

### 13.4 CloudflareTunnelDriver 方法表

| 方法 | 行号 | 功能 |
|------|------|------|
| `start(local_port)` | 第49行 | 启动隧道，阻塞直到获取 URL |

| `health_check()` | 第104行 | 检查隧道进程是否运行 |
| `get_public_url()` | 第108行 | 获取当前公共 URL |
| `get_info()` | 第112行 | 获取完整 TunnelInfo |
| `_wait_for_url()` | 第116行 | 读取 stderr 直到检测到 URL |
| `_monitor()` | 第158行 | 监控进程退出，清理信息 |

### 13.5 BinaryManager

**源码路径**: `src/qwenpaw/tunnel/binary_manager.py`

| 方法 | 行号 | 功能 |

**Java (Spring Backup)：**

```java
// Java - 备份服务
@Service
public class BackupService {
    public void createBackup(Path target) {
        // 1. 序列化配置
        String config = objectMapper.writeValueAsString(appConfig);

        // 2. 压缩
        try (ZipOutputStream zos = new ZipOutputStream(
                new FileOutputStream(target.toFile()))) {
            zos.putNextEntry(new ZipEntry("config.json"));
            zos.write(config.getBytes());
        }
    }
}
```

**等价 QwenPaw：**
```python
# Python - QwenPaw 备份
result = await backup_manager.create_backup(
    scope=BackupScope(
        include_agents=True,
        include_global_config=True,
        include_skill_pool=True
    )
)
```

### 16.8 关键差异

1. **启动方式**：Java 需要先编译后运行，QwenPaw 直接 `pip install` 可用
2. **诊断系统**：QwenPaw 有统一的 `qwenpaw doctor`，Java 需要组合 Actuator + Admin
3. **加密存储**：QwenPaw 内置 Fernet 加密，Java 需要 Jasypt 或 Vault
4. **容器支持**：QwenPaw 有 `QWENPAW_RUNNING_IN_CONTAINER` 标识，Java 用 `/proc/1/cgroup`
