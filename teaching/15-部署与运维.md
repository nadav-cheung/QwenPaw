## 概述

QwenPaw 支持多种部署方式，包括 pip 安装、Docker 容器、本地模型（Ollama/LM Studio）和阿里云 ECS。本教程详细介绍各种部署方式、配置选项、运维工具和故障排查。

## 1. 部署方式概览

| 方式 | 适用场景 | 优点 | 缺点 |
|------|---------|------|------|
| pip 安装 | 个人用户 | 简单，快速 | 需要手动管理依赖 |

| 阿里云 ECS | 云端部署 | 一键部署，可扩展 | 需要云账号 |

## 2. pip 安装

### 2.1 基本安装

```bash
# 安装
pip install qwenpaw

# 初始化（交互式）
qwenpaw init

# 初始化（使用默认配置）
qwenpaw init --defaults

# 启动
qwenpaw app
```

### 2.2 从源码安装

```bash
# 克隆仓库
git clone https://github.com/agentscope-ai/QwenPaw.git
cd QwenPaw

# 构建前端
cd console && npm ci && npm run build
cd ..

# 复制前端构建产物
mkdir -p src/qwenpaw/console
cp -R console/dist/. src/qwenpaw/console/

# 安装 Python 包
pip install -e .

# 开发模式（包含测试依赖）
pip install -e ".[dev,full]"
```

### 2.3 安装选项

```bash
# 安装指定版本
pip install qwenpaw==1.1.2

# 升级
pip install --upgrade qwenpaw

# 卸载
pip uninstall qwenpaw
```

## 3. Docker 部署

Docker 部署是服务器场景的推荐方式，提供环境隔离和可移植性。

**核心命令**：
```bash
# 拉取并运行
docker pull agentscope/qwenpaw:latest
docker run -p 127.0.0.1:8088:8088 \
  -v qwenpaw-data:/app/working \
  -v qwenpaw-secrets:/app/working.secret \
  -v qwenpaw-backups:/app/working.backups \
  agentscope/qwenpaw:latest
```

**三个数据卷说明**：
- `qwenpaw-data`：工作目录（配置、工作空间、技能池）
- `qwenpaw-secrets`：密钥目录（加密的 API Key 等）
- `qwenpaw-backups`：备份目录

**其他部署选项**：Docker Compose 编排、国内阿里云 ACR 镜像加速、连接宿主机 Ollama/LM Studio、自定义镜像构建等。

> 详见 [99-部署与运维指南](./99-部署与运维指南.md)，包含完整的 Docker Compose 配置、Ollama 联通方案、自定义 Dockerfile 构建和生产环境 Docker 最佳实践。

## 6. 系统配置

### 6.1 环境变量架构

**源码路径**: `src/qwenpaw/envs/`

QwenPaw 采用两层持久化架构：`envs.json`（加密持久化）+ `os.environ`（当前进程注入）。启动时通过 `load_envs_into_environ()` 加载并解密 `envs.json`，注入到进程环境变量。支持 Legacy CoPAW 前缀变量名的自动回退。

**保护引导键**：`QWENPAW_WORKING_DIR` 和 `QWENPAW_SECRET_DIR` 排除在自动注入之外，必须从进程/系统环境获取。

> 详见 [99-部署与运维指南](./99-部署与运维指南.md)，包含完整的环境变量一览表（路径配置、LLM 配置、认证配置、内存配置等 30+ 个变量）。

### 6.2 核心环境变量速查

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `QWENPAW_WORKING_DIR` | `~/.qwenpaw` | 工作目录 |
| `QWENPAW_SECRET_DIR` | `{WORKING_DIR}/.secret` | 密钥目录 |
| `QWENPAW_BACKUP_DIR` | `{WORKING_DIR}/.backups` | 备份目录 |
| `QWENPAW_LOG_LEVEL` | `info` | 日志级别 |
| `QWENPAW_RUNNING_IN_CONTAINER` | `false` | 容器环境标识 |
| `QWENPAW_AUTH_ENABLED` | (empty) | 启用Web认证 |
| `QWENPAW_LLM_MAX_CONCURRENT` | `10` | 最大并发数 |

完整列表见 [99-部署与运维指南](./99-部署与运维指南.md)。

### 6.3 工作目录结构

```
~/.qwenpaw/
├── config.json          # 主配置
├── skill_pool/         # 技能池
├── custom_channels/    # 自定义渠道
├── plugins/            # 插件
├── workspaces/         # 工作空间
│   └── default/        # 默认智能体
│       ├── skills/
│       ├── memory/
│       └── ...
├── memory/            # 全局记忆
├── backups/           # 备份
├── .secret/           # 密钥
│   └── .master_key    # 主密钥
└── logs/              # 日志
```

## 7. 运维命令

### 7.1 诊断命令 (Doctor System)

**源码路径**: `src/qwenpaw/cli/doctor*.py`

QwenPaw 内置 Doctor 诊断系统，覆盖 15 种检查类别（环境、配置、Agent、渠道凭证、MCP、模型连接、安全基线等），支持 `--deep` 深度连通性探测和 `fix` 自动修复。

**核心 CLI 命令**：
```bash
qwenpaw doctor                        # 系统诊断
qwenpaw doctor --check models         # 检查特定组件（示例命令）
qwenpaw doctor --deep                 # 深度检查（含渠道连通性）
qwenpaw doctor fix                    # 自动修复问题
```

**修复系统**：按风险级别分类（安全/只读/同步/风险），支持插件通过 `qwenpaw.doctor` 入口点注册自定义检查。

> 详见 [99-部署与运维指南](./99-部署与运维指南.md)，包含完整的检查类别列表、深度连通性探测方法表、修复系统风险分级和定时健康检查配置。

### 7.2 日志管理

QwenPaw 日志系统支持彩色控制台输出和文件轮转。

**核心配置**：单文件最大 5MiB，保留 3 个备份文件，日志文件位于 `~/.qwenpaw/logs/`。双格式化器：`ColorFormatter`（ANSI 彩色，TTY 自动启用）和 `PlainFormatter`（纯文本，格式为 `timestamp | level | filepath:lineno | message`）。

**CLI 命令**：
```bash
qwenpaw daemon logs                  # 查看日志
qwenpaw daemon logs --follow         # 实时跟踪
qwenpaw daemon logs --level debug    # 指定级别
```

> 详见 [99-部署与运维指南](./99-部署与运维指南.md)，包含日志系统完整源码解析（ColorFormatter 颜色映射、RotatingFileHandler 配置、Windows ANSI 支持和幂等 handler 管理）。

### 7.3 备份与恢复

QwenPaw 内置备份恢复系统，支持选择性备份（智能体、全局配置、密钥、技能池）和 3 阶段原子恢复协议（Crash-Safe Protocol），确保恢复过程即使崩溃也不会损坏数据。

**核心 API 端点**：
```bash
# 备份操作通过 API 端点完成
# POST /api/backup/create              # 创建备份
# GET  /api/backup/list                # 列出备份
# GET  /api/backup/{backup_id}/info    # 查看备份详情
# POST /api/backup/{backup_id}/restore # 恢复备份
# DELETE /api/backup/{backup_id}       # 删除备份
# POST /api/backup/{backup_id}/export  # 导出备份
# POST /api/backup/import              # 导入备份
```

**恢复模式**：`full`（完全替换）和 `custom`（选择性合并）。恢复过程包含 Zip Slip 保护、Master Key 冲突处理和后台智能体预加载。

> 详见 [99-部署与运维指南](./99-部署与运维指南.md)，包含备份系统完整架构（数据模型、SSE 流式创建、3 阶段原子恢复协议源码解析）和自动备份定时配置。

### 7.4 清理命令

## 10. 故障排查

### 10.1 常见问题

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 端口被占用 | 8088 端口已使用 | 使用 `--port` 换端口 |
| 权限错误 | 目录权限不足 | `chmod -R 755 ~/.qwenpaw` |
| 模型连接失败 | API Key 错误 | 检查配置，重新设置 |
| 前端加载慢 | 网络问题 | 使用本地构建 |
| Docker 内存不足 | 容器资源限制 | 增加内存限制 |

### 10.2 日志分析

```bash
# 查找错误
qwenpaw daemon logs | grep -i error

# 查找特定模块
qwenpaw daemon logs | grep -i "provider"

# 实时错误跟踪
qwenpaw daemon logs --follow | grep -i error
```

### 10.3 网络问题

```bash
# 检查端口
lsof -i :8088

# 检查网络连接
curl -v http://127.0.0.1:8088/api/health

# 检查代理设置
echo $HTTP_PROXY
echo $HTTPS_PROXY
```

## 13. Tunnel 系统 (Cloudflare Quick Tunnel)

**源码路径**: `src/qwenpaw/tunnel/`

Tunnel 模块通过 Cloudflare Quick Tunnel 将本地服务暴露到互联网，主要用于 Voice 渠道的 Twilio webhook 回调。核心组件包括 `CloudflareTunnelDriver`（隧道驱动）、`BinaryManager`（cloudflared 二进制自动下载，支持 macOS/Linux/Windows，固定版本 2026.2.0）和 `TunnelInfo` 数据类。

Voice 渠道启动时自动创建隧道，为 Twilio webhooks 提供公共 HTTPS URL，WebSocket 通过 `wss://` URL 构建。

> 详见 [99-部署与运维指南](./99-部署与运维指南.md)，包含 Tunnel 系统完整的方法表、BinaryManager 下载校验机制和使用场景详解。

    ├─► 验证备份完整性: unzip -t <backup>.zip

    └─► 检查磁盘空间: df -h

FROM maven:3.9-eclipse-temurin-21 AS build

FROM eclipse-temurin:21-jre-alpine

```dockerfile

WORKDIR /app
COPY . .
RUN pip install qwenpaw
EXPOSE 8088
CMD ["qwenpaw", "app"]
```

### 16.7 备份恢复对比

**Java (Spring Backup)：**
```java
// Java - 备份服务
@Service
public class BackupService {
    public void createBackup(Path target) {
        // 1. 序列化配置
        String config = objectMapper.writeValueAsString(appConfig);

        // 2. 压缩
        try (ZipOutputStream zos = new ZipOutputStream(
                new FileOutputStream(target.toFile()))) {
            zos.putNextEntry(new ZipEntry("config.json"));
            zos.write(config.getBytes());
        }
    }
}
```

**等价 QwenPaw：**
```python
# Python - QwenPaw 备份
result = await backup_manager.create_backup(
    scope=BackupScope(
        include_agents=True,
        include_global_config=True,
        include_skill_pool=True
    )
)
```

### 16.8 关键差异

1. **启动方式**：Java 需要先编译后运行，QwenPaw 直接 `pip install` 可用
2. **诊断系统**：QwenPaw 有统一的 `qwenpaw doctor`，Java 需要组合 Actuator + Admin
3. **加密存储**：QwenPaw 内置 Fernet 加密，Java 需要 Jasypt 或 Vault
4. **容器支持**：QwenPaw 有 `QWENPAW_RUNNING_IN_CONTAINER` 标识，Java 用 `/proc/1/cgroup`
