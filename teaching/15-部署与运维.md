# 部署与运维

## 概述

QwenPaw 支持多种部署方式，包括 pip 安装、Docker 容器、本地模型（Ollama/LM Studio）和阿里云 ECS。本教程详细介绍各种部署方式、配置选项、运维工具和故障排查。

---

## 1. 部署方式概览

| 方式 | 适用场景 | 优点 | 缺点 |
|------|---------|------|------|
| pip 安装 | 个人用户 | 简单，快速 | 需要手动管理依赖 |
| Docker | 服务器部署 | 环境隔离，可移植 | 资源占用较高 |
| 桌面应用 | 非技术用户 | 零配置 | 功能受限 |
| 阿里云 ECS | 云端部署 | 一键部署，可扩展 | 需要云账号 |

## 2. pip 安装

### 2.1 基本安装

```bash
# 安装
pip install qwenpaw

# 初始化（交互式）
qwenpaw init

# 初始化（使用默认配置）
qwenpaw init --defaults

# 启动
qwenpaw app
```

### 2.2 从源码安装

```bash
# 克隆仓库
git clone https://github.com/agentscope-ai/QwenPaw.git
cd QwenPaw

# 构建前端
cd console && npm ci && npm run build
cd ..

# 复制前端构建产物
mkdir -p src/qwenpaw/console
cp -R console/dist/. src/qwenpaw/console/

# 安装 Python 包
pip install -e .

# 开发模式（包含测试依赖）
pip install -e ".[dev,full]"
```

### 2.3 安装选项

```bash
# 安装指定版本
pip install qwenpaw==1.1.2

# 升级
pip install --upgrade qwenpaw

# 卸载
pip uninstall qwenpaw
```

## 3. Docker 部署

### 3.1 基本使用

```bash
# 拉取镜像
docker pull agentscope/qwenpaw:latest

# 运行容器
docker run -p 127.0.0.1:8088:8088 \
  -v qwenpaw-data:/app/working \
  -v qwenpaw-secrets:/app/working.secret \
  -v qwenpaw-backups:/app/working.backups \
  agentscope/qwenpaw:latest
```

### 3.2 国内镜像

```bash
# 阿里云 ACR
docker pull agentscope-registry.ap-southeast-1.cr.aliyuncs.com/agentscope/qwenpaw:latest
```

### 3.3 Docker Compose

```yaml
# docker-compose.yml
version: '3.8'

services:
  qwenpaw:
    image: agentscope/qwenpaw:latest
    ports:
      - "127.0.0.1:8088:8088"
    volumes:
      - qwenpaw-data:/app/working
      - qwenpaw-secrets:/app/working.secret
      - qwenpaw-backups:/app/working.backups
    environment:
      - DASHSCOPE_API_KEY=${DASHSCOPE_API_KEY}
    restart: unless-stopped

volumes:
  qwenpaw-data:
  qwenpaw-secrets:
  qwenpaw-backups:
```

### 3.4 连接本地 Ollama

```bash
# 方式 A：使用 host.docker.internal（通用）
docker run -p 127.0.0.1:8088:8088 \
  --add-host=host.docker.internal:host-gateway \
  -v qwenpaw-data:/app/working \
  agentscope/qwenpaw:latest

# 然后在 QwenPaw 设置中配置：
# Ollama Base URL: http://host.docker.internal:11434

# 方式 B：使用主机网络（仅 Linux）
docker run --network=host \
  -v qwenpaw-data:/app/working \
  agentscope/qwenpaw:latest
```

### 3.5 自定义构建

```bash
# 构建镜像
cd QwenPaw
docker build -t my-qwenpaw:latest .

# 推送
docker push my-registry/my-qwenpaw:latest
```

## 6. 系统配置

### 6.1 环境变量架构

**源码路径**: `src/qwenpaw/envs/`

**两层持久化架构**:
```
┌─────────────────────────────────────────┐
│  envs.json (SECRET_DIR/envs.json)      │ ← 加密持久化
├─────────────────────────────────────────┤
│  os.environ                            │ ← 当前进程注入
└─────────────────────────────────────────┘
```

**核心函数** (store.py):

| 函数 | 行号 | 功能 |
|------|------|------|
| `load_envs()` | 124-161 | 加载并解密envs.json |
| `save_envs()` | 168-197 | 加密写入envs.json并同步到os.environ |
| `set_env_var()` | 199-204 | 设置单个环境变量 |
| `delete_env_var()` | 206-211 | 删除单个环境变量 |
| `load_envs_into_environ()` | 213-231 | 加载envs并注入os.environ |

**启动流程**:
```
qwenpaw/__init__.py
    │
    ▼
load_envs_into_environ()
    │
    ▼
load_envs() → 解密 envs.json
    │
    ▼
_apply_to_environ() (排除保护键)
    │
    ▼
os.environ 获得所有env vars
```

**Legacy CoPAW支持** (constant.py:16-24):
- 自动回退到 `COPAW_*` 前缀的变量名
- 例如: `QWENPAW_WORKING_DIR` 不存在时检查 `COPAW_WORKING_DIR`

**保护引导键** (store.py:70-77):
```python
_PROTECTED_BOOTSTRAP_KEYS = frozenset({
    "QWENPAW_WORKING_DIR",
    "QWENPAW_SECRET_DIR",
})
```
这些键排除在os.environ注入之外，因为必须从进程/系统环境获取才能定位密钥目录。

#### 7.3.3 备份创建流程

**create_stream()** (_ops/create.py:26-81):

```
1. 创建BackupMeta，生成唯一ID
         │
         ▼
2. 在后台线程运行压缩(asyncio.to_thread)
         │
         ▼
3. 使用asyncio.Queue + loop.call_soon_threadsafe非阻塞进度事件
         │
         ▼
4. 先写入.tmp文件，成功后原子替换.zip
```

**SSE事件类型**:

| 事件 | 进度 | 说明 |
|------|------|------|
| `start` | 0% | 开始，包含total_agents数量 |
| `agent` | 10-85% | 每个智能体处理进度 |
| `saving` | 90% | 写入meta.json |
| `done` | 100% | 完成 |
| `error` | - | 失败 |

**Zip包结构**:

```
meta.json                           # BackupMeta JSON格式
data/config.json                   # 全局配置
data/workspaces/{agent_id}/*      # 智能体工作空间
data/secrets/*                     # 密钥目录
data/skill_pool/*                  # 技能池
```

#### 7.3.4 恢复流程 (Crash-Safe Protocol)

**safe_swap.py** 3阶段原子恢复:

| 阶段 | 目录 | 说明 |
|------|------|------|
| Phase 1 | `.restore_tmp` | 解压zip条目，受Zip Slip保护 |
| Phase 2 | 原子交换 | old → `.restore_old`, tmp → dst |
| Phase 3 | 清理 | 删除`.restore_old` |

**execute_restore()** (orchestration.py:38-104):

```
1. 停止受影响的智能体
         │
         ▼
2. 获取恢复锁(asyncio.Lock)序列化并发恢复
         │
         ▼
3. 验证备份版本(_SUPPORTED_BACKUP_VERSIONS = {"1"})
         │
         ▼
4. Phase 1: 解压到.restore_tmp
         │
         ▼
5. Phase 2: 原子目录交换
         │
         ▼
6. Phase 3: 清理.old目录
         │
         ▼
7. 重载主密钥(如恢复密钥)
         │
         ▼
8. 注册新智能体到配置
         │
         ▼
9. 调度后台预加载已停止的智能体
```

**两种恢复模式**:

| 模式 | 说明 |
|------|------|
| `full` | 完全替换 - config.json原样复制 |
| `custom` | 选择性合并 - 顶级键从备份合并，但agents.profiles从本地状态重建 |

#### 7.3.5 关键安全机制

**Master Key冲突处理** (restore_helpers.py:94-130):
- 如果备份的主密钥与当前不同，备份现有密钥到`BACKUP_DIR/_pre_restore_keys/{timestamp}.master_key.bak`
- 保存旧密钥用于解密恢复前的凭据

**Zip Slip保护** (safe_swap.py:134-140):
- 验证每个解压路径保持在目标目录内
- 跳过可疑的路径(穿越到外部目录)

## 13. Tunnel 系统 (Cloudflare Quick Tunnel)

**源码路径**: `src/qwenpaw/tunnel/`

### 13.1 概述

Tunnel 模块通过 Cloudflare Quick Tunnel 将本地服务暴露到互联网，主要用于 Voice 渠道的 Twilio webhook 回调。

### 13.2 核心组件

| 组件 | 文件 | 说明 |
|------|------|------|
| `CloudflareTunnelDriver` | `cloudflare.py` | Tunnel 驱动程序 |
| `TunnelInfo` | `cloudflare.py` 第25行 | 隧道信息数据类 |
| `BinaryManager` | `binary_manager.py` | cloudflared 二进制自动下载 |

### 13.3 TunnelInfo 数据类

```python
@dataclass
class TunnelInfo:
    public_url: str       # "https://abc123.trycloudflare.com"
    public_wss_url: str   # "wss://abc123.trycloudflare.com"
    started_at: datetime
    pid: Optional[int] = None
```

### 13.4 CloudflareTunnelDriver 方法表

| 方法 | 行号 | 功能 |
|------|------|------|
| `start(local_port)` | 第49行 | 启动隧道，阻塞直到获取 URL |
| `stop()` | 第82行 | 优雅终止隧道子进程 |
| `health_check()` | 第104行 | 检查隧道进程是否运行 |
| `get_public_url()` | 第108行 | 获取当前公共 URL |
| `get_info()` | 第112行 | 获取完整 TunnelInfo |
| `_wait_for_url()` | 第116行 | 读取 stderr 直到检测到 URL |
| `_monitor()` | 第158行 | 监控进程退出，清理信息 |

### 13.5 BinaryManager

**源码路径**: `src/qwenpaw/tunnel/binary_manager.py`

| 方法 | 行号 | 功能 |
|------|------|------|
| `get_binary_path()` | 第46行 | 获取 cloudflared 路径，必要时下载 |
| `_verify_checksum()` | 第60行 | SHA256 校验下载文件 |
| `_download()` | 第75行 | 为当前平台下载并解压 cloudflared |

**支持的平台**:
- Darwin x86_64 / arm64
- Linux x86_64 / aarch64
- Windows AMD64

**固定版本**: `2026.2.0` (第30行)

### 13.6 使用场景

Voice 渠道使用 Tunnel 为 Twilio webhooks 提供公共 HTTPS URL:

```python
# VoiceChannel.start() 中的使用 (channel.py 第121-157行)
tunnel_mgr = CloudflareTunnelDriver()
tunnel_info = await tunnel_mgr.start(local_port=voice_port)
# Twilio 调用 https://*.trycloudflare.com/voice/incoming
```

**WebSocket URL 构建**:
```python
wss_url = voice_ch.get_tunnel_wss_url()
ws_url = f"{wss_url}/voice/ws?token={token}"
```

## 14. 总结

### 核心要点

1. **多种部署方式**: pip 安装适合个人用户，Docker 适合服务器部署，阿里云 ECS 适合一键云端部署
2. **Doctor 诊断系统**: 15 种检查类别，覆盖环境、配置、渠道、MCP、模型等全方位诊断
3. **日志系统**: ColorFormatter + PlainFormatter 双格式，支持日志轮转和彩色输出
4. **备份恢复**: 3 阶段原子恢复协议 + Zip Slip 保护，支持选择性恢复
5. **Tunnel 系统**: Cloudflare Quick Tunnel 自动暴露本地服务，支持 Voice 渠道 webhook

### 关键配置

| 配置项 | 说明 |
|--------|------|
| `~/.qwenpaw/config.json` | 主配置文件 |
| `~/.qwenpaw/.secret/` | 加密密钥目录 |
| `QWENPAW_LOG_LEVEL` | 日志级别 |
| `QWENPAW_RUNNING_IN_CONTAINER` | 容器环境标识 |

### 故障排查流程

```
QwenPaw 无法启动
    │
    ├─► 检查端口占用: lsof -i :8088
    │
    ├─► 运行诊断: qwenpaw doctor
    │
    ├─► 检查日志: qwenpaw logs
    │
    └─► 验证配置: qwenpaw doctor --verbose

Docker 部署问题
    │
    ├─► 检查镜像版本: docker images | grep qwenpaw

    │

备份恢复失败
    │
    ├─► 检查备份文件: qwenpaw backup list
    │
    ├─► 验证备份完整性: unzip -t <backup>.zip

    └─► 检查磁盘空间: df -h
```
