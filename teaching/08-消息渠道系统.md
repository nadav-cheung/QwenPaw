# 消息渠道系统

## 概述

QwenPaw 的消息渠道系统是连接智能体与各个即时通讯平台的桥梁。本教程深入剖析其内部架构，帮助你理解消息如何从外部渠道流入、被处理、并最终通过渠道回复用户。

## 1. Channel 系统架构

### 1.1 核心组件

```

├── base.py              # BaseChannel 抽象基类
├── manager.py           # ChannelManager 生命周期管理
```

### 1.2 BaseChannel 抽象基类

所有渠道都继承自 `BaseChannel`（`channels/base.py`），它定义了渠道的通用接口：

```python
class BaseChannel(ABC):
    channel: ChannelType  # 渠道标识符，如 "dingtalk", "telegram"
    uses_manager_queue: bool = True  # 是否使用管理器队列

    # 必需的抽象方法
    @classmethod
    def from_env(cls, process, on_reply_sent=None) -> "BaseChannel": ...

    @classmethod
    def from_config(cls, process, config, on_reply_sent=None, ...) -> "BaseChannel": ...

    async def start(self) -> None: ...
    async def stop(self) -> None: ...
    async def send(self, to_handle: str, text: str, meta: Optional[Dict] = None) -> None: ...
```

```python
        # 优雅关闭所有渠道和队列
```

## 2. 消息流转机制

### 2.1 三元组队列键（QueueKey）

消息队列使用 `(channel_id, session_id, priority_level)` 三元组作为键：

```python
# channels/unified_queue_manager.py
QueueKey = Tuple[str, str, int]  # (channel_id, session_id, priority_level)
```

这确保了：
- **跨会话并发**：不同用户的会话互不阻塞
- **同会话按优先级串行**：同一用户的不同优先级消息有序处理
- **动态队列创建**：按需创建，无固定 worker 池限制

### 2.2 消息优先级

`CommandRegistry` 管理命令优先级：

```python
class CommandRegistry:
    # 优先级定义
    PRIORITY_CRITICAL = 0   # 紧急控制命令
    PRIORITY_HIGH = 10      # 高优先级查询
    PRIORITY_NORMAL = 20    # 普通消息（默认）
    PRIORITY_LOW = 30       # 低优先级批处理

    def get_priority_level(self, query: str) -> int:
        """根据消息内容确定优先级"""
        if query.startswith("/stop"):
            return 0  # 紧急停止
        if query.startswith("/status") or query.startswith("/daemon"):
            return 10
        return 20  # 默认普通消息
```

## 3. Webhook 处理机制

### 3.1 不同渠道的 Webhook 模式

QwenPaw 支持多种 Webhook 接入方式：

| 渠道 | Webhook 模式 | 特点 |
|------|-------------|------|
| DingTalk | Stream 长连接 | SDK 内置自动重连、心跳 |
| Feishu | WebSocket | `lark_oapi` 库支持 |
| Telegram | Polling | Bot API 轮询模式 |
| Discord | WebSocket Gateway | Discord.py 库 |
| 自定义 | REST Webhook | `/api/custom` 路由 |

### 3.2 DingTalk Stream 处理详解

以 DingTalk 为例，深入理解 Webhook 处理：

```python
# channels/dingtalk/handler.py
class DingTalkChannelHandler(dingtalk_stream.ChatbotHandler):
    """继承钉钉 SDK 的 ChatbotHandler"""

    async def process(self, callback: CallbackMessage) -> tuple[int, str]:
        # 1. 解析消息
        incoming_message = ChatbotMessage.from_dict(callback.data)

        # 2. 提取消息内容
        content_parts = self._parse_message_content(incoming_message)

        # 3. 权限检查
        allowed, error_msg = self._check_allowlist(sender, is_group)

        # 4. 创建回复 Future（用于异步回复）
        reply_future = loop.create_future()

        # 5. 构建 native payload
        native = {
            "channel_id": "dingtalk",
            "sender_id": sender,
            "content_parts": content_parts,
            "meta": {
                "incoming_message": incoming_message,
                "reply_future": reply_future,
                "conversation_type": conversation_type,
                "session_webhook": session_webhook,  # 用于主动发送
            }
        }

        # 6. 入队（线程安全）
        self._emit_native_threadsafe(native)

        # 7. 等待回复
        response_text = await reply_future

        # 8. 发送回复
        self.reply_text(response_text, incoming_message)

        return dingtalk_stream.AckMessage.STACK_OK, "ok"
```

## 5. 具体渠道实现分析

### 5.1 DingTalk 渠道实现

DingTalk 是最复杂的渠道之一，完整实现位于 `channels/dingtalk/channel.py`：

```python
class DingTalkChannel(BaseChannel):
    channel = "dingtalk"

    async def start(self) -> None:
        """启动 Stream 连接"""
        # 1. 创建 EventDispatcher
        self._dispatcher = EventDispatcher(
            self._client_id,
            self._client_secret,
            self._handler,  # DingTalkChannelHandler
        )
        # 2. 启动连接（自动重连）
        await self._dispatcher.start()

    async def send(self, to_handle: str, text: str, meta: Dict) -> None:
        """通过 sessionWebhook 发送消息"""
        session_webhook = meta.get("session_webhook")
        if session_webhook:
            # 使用 sessionWebhook 发送
            await self._send_via_webhook(session_webhook, text)
        else:
            # 使用 Open API 发送
            await self._send_via_open_api(to_handle, text)
```

## 6. 进阶主题

### 6.1 消息去重

渠道处理器支持基于 `message_id` 的去重：

```python
class DingTalkChannelHandler(dingtalk_stream.ChatbotHandler):
    def __init__(self, ..., try_accept_message=None):
        self._try_accept_message = try_accept_message

    async def process(self, callback):
        raw_msg_id = callback.data.get("msgId")
        if self._try_accept_message and not self._try_accept_message(raw_msg_id):
            return  # 忽略重复消息
```

## 7. 总结

QwenPaw 的消息渠道系统采用了清晰的分层架构：

| 层次 | 职责 | 核心类 |
|------|------|--------|
| 抽象层 | 统一接口定义 | `BaseChannel` |
| 管理层 | 生命周期、队列路由 | `ChannelManager`, `UnifiedQueueManager` |
| 注册层 | 渠道发现、加载 | `get_channel_registry()` |
| 实现层 | 渠道特定逻辑 | `DingTalkChannel`, `FeishuChannel` 等 |
| 处理层 | 消息解析、回复 | `DingTalkChannelHandler` 等 |

理解这些层次后，你可以：
- 快速定位问题（通过日志区分层次）
- 扩展新渠道（遵循 BaseChannel 接口）
- 深度定制现有渠道（重写特定方法）
