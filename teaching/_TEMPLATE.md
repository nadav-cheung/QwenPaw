## 教案规范说明

### 学习目标编写规范（Bloom's Taxonomy）

使用可观测的行为动词描述学习目标：

| 层级 | 动词示例 | 适用场景 |
|------|----------|----------|
| **记忆** | 列举、定义、识别 | 基础概念介绍 |
| **理解** | 解释、归纳、对比 | 概念深入 |
| **应用** | 使用、实现、配置 | 动手实践 |
| **分析** | 分析、比较、推导 | 架构理解 |
| **评价** | 评估、选择、优化 | 最佳实践 |
| **创造** | 设计、构建、扩展 | 综合实战 |

### 难度等级定义

| 等级 | 定位 | 适合人群 |
|------|------|----------|
| ⭐ | 入门概念 | 完全新手 |
| ⭐⭐ | 基础理解 | 有基础编程经验 |
| ⭐⭐⭐ | 核心掌握 | 熟悉项目基本概念 |
| ⭐⭐⭐⭐ | 深入理解 | 需要扩展和定制 |
| ⭐⭐⭐⭐⭐ | 架构精通 | 系统设计和优化 |

### 代码引用规范

1. 代码片段不超过 **50 行**，关键设计处可适当延长
2. 每段代码前标注 **源码路径和行号**
3. 用注释说明 **设计意图**（Why），而非代码逻辑（What）
4. 完整源码引导读者自行阅读，教案中只展示精华

### "来自 Java 的你"编写规范

1. 放在相关概念之后，不独立成大节
2. 使用表格对比，每行一个概念
3. 对比要 **精准**，避免表面类比
4. 重点解释 **思维差异**，而非语法差异
