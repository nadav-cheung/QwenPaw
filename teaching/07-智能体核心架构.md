## 1. AgentScope 框架介绍

### 1.1 什么是 AgentScope

AgentScope 是 QwenPaw 依赖的基础多智能体框架，提供了智能体的核心抽象和运行时环境。

**源码路径**: `agentscope/`

### 1.2 核心组件

```
AgentScope
├── Agent (智能体基类)
├── Memory (记忆管理)
├── Model (模型封装)
├── Toolkit (工具集合)
└── Formatter (消息格式化)
```

### 1.3 ReActAgent 架构

QwenPawAgent 继承自 AgentScope 的 `ReActAgent`，采用 ReAct (Reasoning + Acting) 模式：

```
用户输入 → 推理(Reasoning) → 决策(Acting) → 工具执行 → 响应
                ↓
           循环迭代直到任务完成
```

**关键方法**:
- `_reasoning()`: 推理阶段，模型决定下一步行动
- `_acting()`: 执行阶段，调用工具执行具体操作
- `reply()`: 主入口，协调推理和执行循环

**决策逻辑** (`_decide_guard_action` 方法，第346-400行):

```python
async def _decide_guard_action(self, tool_call: dict[str, Any]) -> "_GuardAction | None":
    """决定守卫动作（锁保护下运行）"""
    engine = self._tool_guard_engine
    tool_name = str(tool_call.get("name", ""))
    tool_input = tool_call.get("input", {})
    
    # 1. 检查是否在拒绝列表 → 自动拒绝
    if engine.is_denied(tool_name):
        return _GuardAction("auto_denied", tool_name, tool_input)

    # 2. 检查是否在保护范围且已预批准
    guarded = engine.is_guarded(tool_name)
    if guarded and await self._consume_preapproval(tool_name, tool_input):
        return _GuardAction("preapproved", tool_name, tool_input)

    # 3. 运行所有守护者检查
    guard_result = engine.guard(tool_name, tool_input, only_always_run=not guarded)
    if guard_result.findings and self._should_require_approval():
        return _GuardAction("needs_approval", tool_name, tool_input, guard_result)
    return None
```

**守卫决策流程**:
```
工具调用 → 是否在拒绝列表? → 自动拒绝
              ↓ 否
         是否在守卫范围? → 检查预审批 → 已预审批 → 执行
              ↓ 否               ↓ 否
         运行守卫规则 → 发现问题? → 需要用户审批
              ↓ 否
         正常执行
```

### 2.8 进阶能力：中断、压缩与恢复

#### interrupt() -- 外部中断回复任务

**源码路径**: `src/qwenpaw/agents/react_agent.py:1217`

当用户需要在智能体执行过程中打断当前回复时（例如用户切换话题或取消操作），`interrupt()` 提供了安全的中断机制：

```python
async def interrupt(self, msg: Msg | list[Msg] | None = None) -> None:
    """Interrupt the current reply process and wait for cleanup."""
    if self._reply_task and not self._reply_task.done():
        task = self._reply_task
        task.cancel(msg)
        try:
            await task  # 等待任务清理完成
        except asyncio.CancelledError:
            if not task.cancelled():
                raise
        except Exception:
            logger.warning(
                "Exception occurred during interrupt cleanup",
                exc_info=True,
            )
```

核心逻辑：通过 `task.cancel()` 发送取消请求，然后 `await task` 等待任务优雅退出。捕获 `CancelledError` 以区分正常取消和异常中断。

#### MCP 客户端恢复机制

**源码路径**: `src/qwenpaw/agents/react_agent.py:546`

MCP 客户端在长时间运行中可能断开连接。系统提供了三层递进恢复策略：

```
_recover_mcp_client()          (L546) 恢复入口
    │
    ├─→ _reconnect_mcp_client() (L596) 尝试重连现有客户端
    │       │
    │       ├─→ client.close()   → 关闭旧连接
    │       └─→ client.connect() → 重新建立连接（60s 超时）
    │
    └─→ _rebuild_mcp_client()   (L625) 从配置元数据重建客户端
            │
            ├─→ 读取 _qwenpaw_rebuild_info 元数据
            ├─→ 按 transport 类型重建（stdio / sse / streamable-http）
            └─→ _reuse_shared_client_reference() 保持引用稳定
```

```python
async def _recover_mcp_client(self, client: Any) -> Any | None:
    """Recover MCP client with reconnect → rebuild escalation."""
    # 第一层：尝试重连
    if await self._reconnect_mcp_client(client):
        return client
    # 第二层：从配置重建
    rebuilt_client = self._rebuild_mcp_client(client)
    if rebuilt_client is None:
        return None
    # 第三层：重连重建后的客户端
    if await self._reconnect_mcp_client(rebuilt_client):
        return self._reuse_shared_client_reference(
            original_client=client, rebuilt_client=rebuilt_client,
        )
    return None
```

`_reuse_shared_client_reference()` 将重建客户端的 `__dict__` 复制到原客户端，保持所有持有旧引用的地方无需更新。

### 来自 Java 的你

#### Agent vs Spring Bean

QwenPaw 的 Agent 与 Java Spring 框架的 Bean 在架构设计上有相似之处：

| QwenPaw Agent | Spring Bean | 说明 |
|---------------|-------------|------|
| `QwenPawAgent` | `@Component` 或 `@Service` | 智能体注册为组件 |
| `ToolGuardMixin` | AOP 切面 (`@Aspect`) | 安全拦截类似 Spring AOP |
| `_reasoning()` / `_acting()` | `@PostConstruct` / 业务方法 | 生命周期方法 |
| `asyncio.Lock()` (per-agent) | `synchronized` 或 `ReentrantLock` | 保护并发访问 |
| `AgentScope` 框架 | Spring Framework | 基础框架 |
| `Toolkit` (工具集合) | `@Autowired` 注入多个服务 | 依赖注入集合 |
| `Memory` | HttpSession / `@Scope("session")` | 状态存储 |
| `@property` | Lombok `@Getter` | 自动生成访问器 |
| `super().__init__()` | `extends BaseClass` + `@Autowired` | 继承与注入组合 |
| 异步初始化 | `@Async` + `ApplicationRunner` | 启动时异步准备 |

**ToolGuardMixin 的设计模式**：
- Python 的 MRO（方法解析顺序）混入模式 ≈ Java 的 `@Aspect` 切面 + `@Around` 注解
- `async with lock:` 在 Python 中自动释放锁，类似 Java 的 `try-with-resources`
- 延迟初始化 `_tool_guard_lock` 在首次访问时才创建，类似 Java 的 `@Lazy` 延迟加载

#### 异步模式对比

| QwenPaw / Python | Java 等价 | 说明 |
|-------------------|-----------|------|
| `async def _acting()` | `CompletableFuture.supplyAsync()` | 异步工具执行入口 |
| `await super()._acting()` | `future.get()` 或 `thenApply()` | 调用父类异步方法 |
| `asyncio.Lock()` | `ReentrantLock` 或 `synchronized` | 保护共享状态的互斥锁 |
| `async with self._lock:` | `lock.lock(); try { ... } finally { lock.unlock(); }` | 异步上下文管理器自动释放锁 |
| `self._tool_guard_lock = asyncio.Lock()` | `private final ReentrantLock lock = new ReentrantLock();` | 延迟初始化锁 |
| `asyncio.create_task()` | `executor.submit(Runnable)` | 创建后台异步任务 |
| `await asyncio.gather(t1, t2)` | `CompletableFuture.allOf(f1, f2)` | 并发等待多个任务 |
| `async with AsyncExitStack() as stack:` | `try (var stack = new ContextStack()) { ... }` | 异步上下文管理器栈 |

### 2.7 多模态媒体处理

三层媒体块处理机制：

1. **主动层**: 模型不支持多模态时，在调用前移除媒体块
2. **被动层**: 调用失败时移除媒体块并重试
3. **自动继续层**: 文本响应时自动继续推理

```python
_media_block_types = {"image", "audio", "video"}

def _strip_media_blocks_from_memory(self) -> int:
    """从记忆中移除媒体块并返回移除数量"""
    for msg, _marks in self.memory.content:
        if not isinstance(msg.content, list):
            continue
        new_content = []
        for block in msg.content:
            if block.get("type") in self._media_block_types:
                total_stripped += 1
                continue  # 跳过媒体块
            new_content.append(block)
        msg.content = new_content
    return total_stripped
```

QwenPaw 的智能体架构具有以下特点：

## 实战演练

### 基础练习（⭐）
**目标**: 在源码中找到 `_create_toolkit` 方法，列出它注册了哪些内置工具
**提示**: 在 `src/qwenpaw/agents/react_agent.py` 中搜索 `_create_toolkit`，关注 `tool_functions` 字典的键
**参考思路**: `_create_toolkit` 方法内部维护了一个 `tool_functions` 映射表，将工具名称（如 `execute_shell_command`、`read_file`、`write_file`）与对应的函数对象绑定。逐一阅读这些工具的源码（在 `src/qwenpaw/agents/tools/` 目录下），理解每个工具的参数和返回值格式。

### 进阶练习（⭐⭐⭐）
**目标**: 追踪一次完整的工具调用：从 LLM 返回 `tool_use` 到工具执行完成返回结果的流程
**提示**: 从 `ReActAgent.reply()` → `_reasoning()` 返回包含 `tool_use` 的消息 → `_acting()` 接收 `tool_call` 并执行
**参考思路**: 在 `_reasoning()` 中，LLM 返回的消息可能包含 `tool_use` 类型的 content block。`reply()` 方法的循环检测到工具调用后进入 `_acting()`。在 `_acting()` 中，`ToolGuardMixin` 会先进行安全检查（`_decide_guard_action`），通过后才调用 `toolkit.call_tool()` 执行实际工具函数。追踪时注意 `Msg` 对象的 `content` 字段结构变化。

### 挑战练习（⭐⭐⭐⭐⭐）
**目标**: 分析 `ToolGuardMixin` 的 MRO 拦截机制，解释为什么它能在不修改 Agent 代码的情况下插入安全检查
**提示**: 理解 Python 的 C3 线性化算法如何决定 `QwenPawAgent → ToolGuardMixin → ReActAgent` 的方法解析顺序
**参考思路**: `ToolGuardMixin` 重写了 `_acting()` 方法。当 `QwenPawAgent` 实例调用 `_acting()` 时，由于 MRO 的顺序，Python 会先找到 `ToolGuardMixin._acting()` 而非 `ReActAgent._acting()`。`ToolGuardMixin._acting()` 执行安全检查后，通过 `await super()._acting()` 将调用传递给 MRO 中的下一个类（即 `ReActAgent`）。这与 Java Spring AOP 的 `@Around` 通知本质相同——通过方法拦截插入横切逻辑，而无需修改被拦截类的代码。
