## 1. AgentScope 框架介绍

### 1.1 什么是 AgentScope

AgentScope 是 QwenPaw 依赖的基础多智能体框架，提供了智能体的核心抽象和运行时环境。

**源码路径**: `agentscope/`

### 1.2 核心组件

```
AgentScope
├── Agent (智能体基类)
├── Memory (记忆管理)
├── Model (模型封装)
├── Toolkit (工具集合)
└── Formatter (消息格式化)
```

### 1.3 ReActAgent 架构

QwenPawAgent 继承自 AgentScope 的 `ReActAgent`，采用 ReAct (Reasoning + Acting) 模式：

```
用户输入 → 推理(Reasoning) → 决策(Acting) → 工具执行 → 响应
                ↓
           循环迭代直到任务完成
```

**关键方法**:
- `_reasoning()`: 推理阶段，模型决定下一步行动
- `_acting()`: 执行阶段，调用工具执行具体操作
- `reply()`: 主入口，协调推理和执行循环

### 2.4 重写的方法

#### `_reasoning()` - 推理覆盖

```python
async def _reasoning(self, tool_choice=None) -> Msg:
    """带有多模态过滤的推理方法"""
    # 1. 主动过滤层：模型不支持多模态时提前移除媒体块
    if not get_active_model_supports_multimodal():
        self._proactive_strip_media_blocks()
    
    # 2. 被动回退层：模型调用失败时移除媒体块并重试
    try:
        msg = await super()._reasoning(tool_choice=tool_choice)
    except Exception as e:
        if self._is_bad_request_or_media_error(e):
            self._set_formatter_media_strip(True)
            msg = await super()._reasoning(tool_choice=tool_choice)
    
    # 3. 自动继续：文本响应但任务未完成时继续推理
    return await self._auto_continue_if_text_only(msg, tool_choice)
```

### 2.5 工具安全守卫 (ToolGuardMixin)

```python
class ToolGuardMixin:
    """工具安全守卫混入类，通过 MRO 与 ReActAgent 结合"""

        from qwenpaw.app.approvals import get_approval_service
        self._tool_guard_engine = get_guard_engine()
        self._tool_guard_approval_service = get_approval_service()
        self._tool_guard_pending_info: dict | None = None
        self._tool_guard_lock = asyncio.Lock()
```

**拦截入口** (`_acting` 方法，第291-344行):

```python
async def _acting(self, tool_call) -> dict | None:
    """拦截敏感工具调用"""
    # 1. 检查是否在拒绝列表
    if engine.is_denied(tool_name):
        return await self._acting_auto_denied(...)

    # 2. 检查是否需要审批
    guard_result = engine.guard(tool_name, tool_input)
    if guard_result.findings:
        return await self._acting_with_approval(...)

    # 3. 正常执行
    return await super()._acting(tool_call)
```

**决策逻辑** (`_decide_guard_action` 方法，第346-400行):

```python
async def _decide_guard_action(self, tool_call: dict[str, Any]) -> "_GuardAction | None":
    """决定守卫动作（锁保护下运行）"""
    engine = self._tool_guard_engine
    tool_name = str(tool_call.get("name", ""))
    tool_input = tool_call.get("input", {})
    
    # 1. 检查是否在拒绝列表 → 自动拒绝
    if engine.is_denied(tool_name):
        return _GuardAction("auto_denied", tool_name, tool_input)

    # 2. 检查是否在保护范围且已预批准
    guarded = engine.is_guarded(tool_name)
    if guarded and await self._consume_preapproval(tool_name, tool_input):
        return _GuardAction("preapproved", tool_name, tool_input)

    # 3. 运行所有守护者检查
    guard_result = engine.guard(tool_name, tool_input, only_always_run=not guarded)
    if guard_result.findings and self._should_require_approval():
        return _GuardAction("needs_approval", tool_name, tool_input, guard_result)
    return None
```

**守卫决策流程**:
```
工具调用 → 是否在拒绝列表? → 自动拒绝
              ↓ 否
         是否在守卫范围? → 检查预审批 → 已预审批 → 执行
              ↓ 否               ↓ 否
         运行守卫规则 → 发现问题? → 需要用户审批
              ↓ 否
         正常执行
```

### 来自 Java 的你

#### Agent vs Spring Bean

QwenPaw 的 Agent 与 Java Spring 框架的 Bean 在架构设计上有相似之处：

| QwenPaw Agent | Spring Bean | 说明 |
|---------------|-------------|------|
| `QwenPawAgent` | `@Component` 或 `@Service` | 智能体注册为组件 |
| `ToolGuardMixin` | AOP 切面 (`@Aspect`) | 安全拦截类似 Spring AOP |
| `_reasoning()` / `_acting()` | `@PostConstruct` / 业务方法 | 生命周期方法 |
| `asyncio.Lock()` (per-agent) | `synchronized` 或 `ReentrantLock` | 保护并发访问 |
| `AgentScope` 框架 | Spring Framework | 基础框架 |
| `Toolkit` (工具集合) | `@Autowired` 注入多个服务 | 依赖注入集合 |
| `Memory` | HttpSession / `@Scope("session")` | 状态存储 |
| `@property` | Lombok `@Getter` | 自动生成访问器 |
| `super().__init__()` | `extends BaseClass` + `@Autowired` | 继承与注入组合 |
| 异步初始化 | `@Async` + `ApplicationRunner` | 启动时异步准备 |

**ToolGuardMixin 的设计模式**：
- Python 的 MRO（方法解析顺序）混入模式 ≈ Java 的 `@Aspect` 切面 + `@Around` 注解
- `async with lock:` 在 Python 中自动释放锁，类似 Java 的 `try-with-resources`
- 延迟初始化 `_tool_guard_lock` 在首次访问时才创建，类似 Java 的 `@Lazy` 延迟加载

#### 异步模式对比

| QwenPaw / Python | Java 等价 | 说明 |
|-------------------|-----------|------|
| `async def _acting()` | `CompletableFuture.supplyAsync()` | 异步工具执行入口 |
| `await super()._acting()` | `future.get()` 或 `thenApply()` | 调用父类异步方法 |
| `asyncio.Lock()` | `ReentrantLock` 或 `synchronized` | 保护共享状态的互斥锁 |
| `async with self._lock:` | `lock.lock(); try { ... } finally { lock.unlock(); }` | 异步上下文管理器自动释放锁 |
| `self._tool_guard_lock = asyncio.Lock()` | `private final ReentrantLock lock = new ReentrantLock();` | 延迟初始化锁 |
| `asyncio.create_task()` | `executor.submit(Runnable)` | 创建后台异步任务 |
| `await asyncio.gather(t1, t2)` | `CompletableFuture.allOf(f1, f2)` | 并发等待多个任务 |
| `async with AsyncExitStack() as stack:` | `try (var stack = new ContextStack()) { ... }` | 异步上下文管理器栈 |

### 2.6 自动继续机制 (Auto-Continue)

当模型仅返回文本但任务未完成时，自动继续推理：

```python
_auto_continue_max_extra = 2  # 最多额外 2 次推理
_auto_continue_hint = "上轮助手仅文字、未调工具..."

async def _auto_continue_if_text_only(self, msg, tool_choice):
    if msg.has_content_blocks("tool_use"):
        return msg  # 有工具调用，正常返回

    # 注入提示并重新推理
    hint_msg = Msg("user", self._auto_continue_hint, "user")
    await self.memory.add(hint_msg, marks=_MemoryMark.HINT)
    return await super()._reasoning(tool_choice=tool_choice)
```

### 2.7 多模态媒体处理

三层媒体块处理机制：

1. **主动层**: 模型不支持多模态时，在调用前移除媒体块
2. **被动层**: 调用失败时移除媒体块并重试
3. **自动继续层**: 文本响应时自动继续推理

```python
_media_block_types = {"image", "audio", "video"}

def _strip_media_blocks_from_memory(self) -> int:
    """从记忆中移除媒体块并返回移除数量"""
    for msg, _marks in self.memory.content:
        if not isinstance(msg.content, list):
            continue
        new_content = []
        for block in msg.content:
            if block.get("type") in self._media_block_types:
                total_stripped += 1
                continue  # 跳过媒体块
            new_content.append(block)
        msg.content = new_content
    return total_stripped
```

## 5. 小结

QwenPaw 的智能体架构具有以下特点：

1. **模块化设计**: 各组件职责清晰，易于扩展和维护
