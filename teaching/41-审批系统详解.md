# 审批系统详解

## 概述

QwenPaw 的审批系统与 tool_guard 深度集成，当工具调用触发安全发现时，智能体暂停等待用户通过 `/approve` 命令审批。审批服务管理待审批记录的生命周期。

**核心设计理念**：工具执行前的最后一道安全防线，采用异步 Future 模式实现非阻塞等待，支持超时自动拒绝和垃圾回收清理。

### 1.3 关键方法详解

**get_all_pending_by_session** — 获取会话所有待审批：

```python
# src/qwenpaw/app/approvals/service.py:169-180
async def get_all_pending_by_session(
    self,
    session_id: str,
) -> list[PendingApproval]:
    """返回 session_id 的所有待审批（FIFO 顺序）"""
    async with self._lock:
        return [
            p
            for p in self._pending.values()
            if p.session_id == session_id and p.status == "pending"
        ]
```

**cancel_stale_pending_for_tool_call** — 防止孤儿记录：

```python
# src/qwenpaw/app/approvals/service.py:183-217
async def cancel_stale_pending_for_tool_call(
    self,
    session_id: str,
    tool_call_id: str,
) -> int:
    """取消 tool_call_id 匹配的旧待审批

    当工具调用被重放时（如 /approve 触发同级重放），
    守卫可能创建新的待审批。本方法先取消旧的，
    防止孤儿记录积累。
    """
    now = time.time()
    cancelled = 0
    async with self._lock:
        to_cancel = [
            k
            for k, p in self._pending.items()
            if p.session_id == session_id
            and p.status == "pending"
            and isinstance(p.extra.get("tool_call"), dict)
            and p.extra["tool_call"].get("id") == tool_call_id
        ]
        for k in to_cancel:
            pending = self._pending.pop(k)
            if not pending.future.done():
                pending.future.set_result(ApprovalDecision.TIMEOUT)
            pending.status = "superseded"
            pending.resolved_at = now
            self._completed[k] = pending
            cancelled += 1
    return cancelled
```

## 2. 工具批准流程

### 2.1 ToolGuardMixin 集成

```python
# src/qwenpaw/agents/tool_guard_mixin.py:291
async def _acting(self, tool_call) -> dict | None:
    """拦截敏感工具调用在执行前"""
    # 1. 如果工具在 denied_tools 中 → 自动拒绝
    # 2. 如果工具在 guarded scope → 运行守护
    # 3. 如果有发现 → 进入审批流程
    # 4. 否则委托给 super()._acting()
```

**决策流程**：
```
_tool_call
    ↓
is_denied(tool_name)? → YES → auto_denied
    ↓ NO
consume_preapproval()? → YES → preapproved
    ↓ NO
guard(tool_name, tool_input)?
    ├── findings == 0 → super()._acting() 正常执行
    └── findings > 0
            ↓
        should_require_approval()? → YES → needs_approval
            → NO → 执行（带警告）
```

### 2.2 _decide_guard_action

```python
# src/qwenpaw/agents/tool_guard_mixin.py:346
async def _decide_guard_action(self, tool_call) -> "_GuardAction | None":
    # 显式拒绝
    if engine.is_denied(tool_name):
        return _GuardAction("auto_denied", ...)

    # 预批准检查
    if guarded and await self._consume_preapproval(tool_name, tool_input):
        return _GuardAction("preapproved", ...)

    # 运行所有守护
    guard_result = engine.guard(tool_name, tool_input, ...)
    if guard_result.findings:
        if self._should_require_approval():
            return _GuardAction("needs_approval", ...)
```

## 3. 完整审批流程

```
1. 用户发送带工具调用的查询
         ↓
2. Runner.query_handler() 接收查询
         ↓
3. Runner._resolve_pending_approval(session_id, query)
         ↓
4. ToolGuardMixin._acting(tool_call)
         ↓
5. ToolGuardEngine 运行所有守护
         ↓
6. 如果有发现 → ApprovalService.create_pending()
         ↓
7. 用户收到"等待批准"消息
         ↓
8. 用户输入 /approve
         ↓
9. Runner._resolve_pending_approval() → resolve_request(APPROVED)
         ↓
10. 工具通过 _emit_forced_tool_use() 执行
```

**关键点**：
- 步骤 6-7 之间智能体处于暂停状态，不消耗资源
- Future 模式实现异步通知，避免轮询
- 支持多会话并发审批

```python
# src/qwenpaw/app/runner/daemon_commands.py:189
async def run_daemon_approve(context: DaemonContext, session_id: str = "") -> str:
    svc = get_approval_service()
    pending = await svc.get_pending_by_session(session_id)
    if pending is None:
        return "**No pending approval**..."

    await svc.resolve_request(pending.request_id, ApprovalDecision.APPROVED)
    return f"**Tool execution approved**..."
```

## 5. 垃圾回收

```python
# src/qwenpaw/app/approvals/service.py:259
_GC_MAX_AGE_SECONDS = 3600.0        # 完成记录 1 小时后过期
_GC_MAX_COMPLETED = 500              # 最多 500 条完成记录
_GC_PENDING_MAX_AGE_SECONDS = 1800.0 # 待审批 30 分钟后过期
_GC_MAX_PENDING = 200               # 最多 200 条待审批
```

**GC 策略**：
- 待审批记录：30 分钟超时或超过 200 条时清理
- 完成记录：1 小时后清理或超过 500 条时清理
- 采用 FIFO 策略，优先清理最旧的记录

## 6. 设计模式

### 6.1 一次性预批准

```python
# 消耗后立即删除，防止重放
approval = await svc.consume_approval(tool_name, tool_input)
if approval:
    return _GuardAction("preapproved", ...)
```

**适用场景**：用户明确授权的敏感操作（如文件删除）。

### 6.2 异步 Future 模式

```python
# 创建待审批时获取 Future
future: asyncio.Future[ApprovalDecision] = asyncio.get_event_loop().create_future()
pending = PendingApproval(future=future, ...)

# 批准时解析 Future
pending.future.set_result(ApprovalDecision.APPROVED)
```

**优势**：非阻塞等待，节省资源，支持超时自动清理。

### 6.3 FIFO 队列

```python
# 按创建时间顺序返回待审批
pending = await svc.get_pending_by_session(session_id)
```

## 9. 常见问题

### Q1: 审批请求卡住没有响应？

**原因**：GC 未触发或 Future 未正确解析。

**排查步骤**：
```bash
# 1. 检查是否有待审批记录
curl http://localhost:8080/api/approvals/pending

# 2. 检查 GC 日志
grep "GC" logs/qwenpaw.log

# 3. 重启服务清除卡住的 Future
```

### Q2: 如何批量批准多个请求？

**方案**：当前版本需逐个批准，可通过脚本实现：

```python
# 批量批准脚本
for request_id in pending_ids:
    await svc.resolve_request(request_id, ApprovalDecision.APPROVED)
```

### Q3: 工具被自动拒绝但不应该？

**排查**：
1. 检查 `denied_tools` 配置
2. 查看 `tool_guard` 规则的优先级
3. 确认 `should_require_approval()` 返回值

### Q4: 审批后工具未执行？

**可能原因**：
- 工具调用已被消费（一次性批准）
- 会话 ID 不匹配
- Future 结果未正确传递

## 10. 总结

**核心要点**：

| 要点 | 说明 |
|------|------|
| 异步 Future 模式 | 非阻塞等待，节省资源 |
| 一次性预批准 | 防止审批结果重放 |
| FIFO 队列 | 保证审批顺序公平 |
| 自动垃圾回收 | 防止内存泄漏 |
| 多渠道支持 | 统一的审批体验 |

**进阶主题**：
