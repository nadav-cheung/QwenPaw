## 概述

QwenPaw 的安全系统由三大模块构成：

| 模块 | 路径 | 职责 |
|------|------|------|
| `tool_guard` | `security/tool_guard/` | 工具调用前的安全审查 |
| `secret_store` | `security/secret_store.py` | 敏感数据（API Key、JWT Secret）的加密存储 |
| `skill_scanner` | `security/skill_scanner/` | 技能文件的安全扫描 |

这三个模块相互独立但共享安全设计原则。本章通过源码逐行解析，揭示 QwenPaw 安全架构的设计思路。

## 1. 密钥加密存储 — secret_store.py

secret_store 模块负责 API Key、JWT Secret、环境变量等敏感数据的加密存储，确保即使攻击者拿到磁盘文件也无法解密。

**核心设计**：
- **加密算法**：Fernet（AES-128-CBC + HMAC-SHA256），提供认证加密（AEAD），同时保证机密性和完整性
- **分层密钥管理**：主密钥通过四层递进获取 —— 进程缓存 → OS Keychain → 文件 → 自动生成，采用双重检查锁定保证线程安全
- **优雅降级**：macOS/Linux GUI 环境优先使用 OS Keychain，无 GUI 的 Linux 服务器、Docker 容器、CI 环境降级到文件存储（`0o600` 权限）
- **字段级加密**：通过 `encrypt_dict_fields()` 对字典中的指定字段（如 `api_key`、`jwt_secret`）透明加密，`ENC:` 前缀标识密文，解密失败返回原值而非崩溃

**主要使用方**：Provider Manager（加密 `api_key`）、Auth（加密 `jwt_secret`）、Env Store（加密环境变量）、Backup Restore（恢复后重载密钥）。

> 详见 [39-密钥存储加密系统](./39-密钥存储加密系统.md)，包含 Fernet 算法选型分析、主密钥获取的四层递进源码解析、密钥轮换策略和跨环境部署注意事项。

## 2. 工具守卫系统 — tool_guard

tool_guard 是 QwenPaw 的核心安全防线，在 AI 智能体调用工具**执行前**审查工具名称和参数，发现威胁则拦截。其设计遵循零信任、分层防御和可审计三大原则。

### 2.1 三层守卫架构总览

```
ToolGuardMixin._acting()           # 拦截点（react_agent.py:76 混入 QwenPawAgent）
        │
        ▼
ToolGuardEngine.guard()           # 编排器（engine.py:177）
        │
        ├─► FilePathToolGuardian    (always_run=True)  # 路径守卫，所有工具都跑
        ├─► RuleBasedToolGuardian   (always_run=False) # 正则规则守卫
        └─► ShellEvasionGuardian    (always_run=False) # 混淆检测守卫
        │
        ▼
ToolGuardResult  ──► is_safe? ──► [放行 | 拦截+审批]
```

**三层守卫职责概述**：

| 层级 | 守卫 | 职责 | 绕过难度 |
|------|------|------|----------|
| 第 1 层 | `FilePathToolGuardian` | 阻止访问密钥目录、配置文件等敏感路径（`always_run=True`，对所有工具生效） | 低 |
| 第 2 层 | `RuleBasedToolGuardian` | 用 YAML 定义的 20+ 条正则规则匹配危险命令模式（如 `rm -rf /`、反向 Shell、提权命令） | 中 |
| 第 3 层 | `ShellEvasionGuardian` | 检测引号逃逸、注释注入、换行混淆等绕过正则的结构性攻击（7 种检测模式） | 高 |

**Agent 集成方式**：通过 `ToolGuardMixin` 混入 `QwenPawAgent`，拦截 `_acting()` 方法在工具执行前触发守卫检查。被拦截的调用进入审批流程，用户可通过 `/approve` 命令手动放行。

**安全结果模型**：`ToolGuardResult` 聚合所有守卫的 `GuardFinding`，当存在 CRITICAL 或 HIGH 级别发现时判定为不安全。

> 详见 [38-工具Guard安全系统](./38-工具Guard安全系统.md)，包含每层守卫的逐行源码解析、内置正则规则完整列表、Shell 混淆检测的 7 种攻击场景、审批流程的完整链路和自定义守卫开发指南。

## 3. 技能安全扫描 — skill_scanner

### 3.1 设计目标

用户安装的技能（Skill）可能是第三方来源，代码中可能藏有恶意逻辑。skill_scanner 在技能**安装前**扫描代码，发现威胁后阻止安装或发出警告。

**三种模式**：
- `block`：发现威胁则阻止安装
- `warn`：发现威胁仅警告，不阻止
- `off`：关闭扫描

### 3.2 扫描器核心

源码路径：`src/qwenpaw/security/skill_scanner/scanner.py:319`

```python
class SkillScanner:
    """技能安全扫描器 — 编排文件发现、规则匹配、报告生成"""

    def __init__(self, policy: ScanPolicy):
        self.policy = policy
        self._analyzers: list[BaseAnalyzer] = [
            PatternAnalyzer(policy),   # 正则模式分析器
            # 未来可扩展：LLMAnalyzer（LLM 语义分析）、ASTAnalyzer（AST 分析）
        ]

    async def scan(self, skill_path: Path) -> ScanResult:
        """扫描技能目录，返回完整报告"""
        # 1. 验证路径边界（防止 symlink 逃逸）
        resolved = skill_path.resolve()
        if not self._is_within_allowed_dir(resolved):
            return ScanResult(blocked=True, reason="path_traversal")

        # 2. 枚举所有文件（跳过隐藏文件和 policy 排除项）
        files = self._discover_files(skill_path)

        # 3. 对每个分析器运行检查
        all_findings: list[Finding] = []
        for analyzer in self._analyzers:
            findings = await analyzer.analyze(skill_path, files)
            all_findings.extend(findings)

        # 4. 与白名单比对（可信技能跳过）
        if self._is_whitelisted(skill_path, all_findings):
            return ScanResult(whitelisted=True)

        return ScanResult(findings=all_findings, blocked=has_blocking)
```

### 3.4 内容哈希与白名单

源码路径：`src/qwenpaw/security/skill_scanner/__init__.py:122`

```python
# src/qwenpaw/security/skill_scanner/__init__.py:122
def compute_skill_content_hash(skill_dir: Path) -> str:
    """计算 skill_dir 中所有常规文件内容的 SHA-256 哈希（排序后）。"""
    h = hashlib.sha256()
    try:
        for p in sorted(skill_dir.rglob("*")):
            if p.is_file() and not p.is_symlink():
                try:
                    h.update(p.read_bytes())
                except OSError:
                    pass
    except OSError:
        pass
    return h.hexdigest()
```

**白名单验证**：当白名单条目有非空 `content_hash` 时，必须与当前目录内容匹配才生效。

```python
# src/qwenpaw/security/skill_scanner/__init__.py:142
def is_skill_whitelisted(skill_name, skill_dir=None, *, cfg=None) -> bool:
    """如果 skill_name 在白名单中则返回 True。"""
    if cfg is None:
        cfg = _load_scanner_config()
    for entry in cfg.whitelist:
        if entry.skill_name != skill_name:
            continue
        if not entry.content_hash:
            return True
        if skill_dir is not None:
            current_hash = compute_skill_content_hash(skill_dir)
            if current_hash == entry.content_hash:
                return True
    return False
```

### 3.6 扫描结果缓存

源码路径：`src/qwenpaw/security/skill_scanner/__init__.py:335`

```python
# 最大缓存条目数
_MAX_CACHE_ENTRIES = 64
_scan_cache: dict[str, tuple[float, ScanResult]] = {}

def _get_cached_result(skill_dir: Path) -> ScanResult | None:
    """如果目录未更改则返回缓存的 ScanResult。"""
    key = str(skill_dir)
    entry = _scan_cache.get(key)
    if entry is None:
        return None
    cached_mtime, cached_result = entry
    current_mtime = _get_dir_mtime(skill_dir)
    if current_mtime == cached_mtime:
        return cached_result
    return None

def _store_cached_result(skill_dir: Path, result: ScanResult) -> None:
    """存储扫描结果到缓存（LRU 驱逐）。"""
    key = str(skill_dir)
    mtime = _get_dir_mtime(skill_dir)
    _scan_cache[key] = (mtime, result)
    while len(_scan_cache) > _MAX_CACHE_ENTRIES:
        oldest = next(iter(_scan_cache))
        del _scan_cache[oldest]
```

**缓存策略**：基于 mtime 的缓存，同一目录在文件未修改时返回缓存结果，最多 64 个条目。

### 3.8 扫描模式优先级

源码路径：`src/qwenpaw/security/skill_scanner/__init__.py:96`

```python
# 有效模式
_VALID_MODES = {"block", "warn", "off"}

def _get_scan_mode(cfg=None) -> str:
    """返回有效扫描模式：block、warn 或 off。

    优先级：env QWENPAW_SKILL_SCAN_MODE > config > 默认 warn
    """
    env = EnvVarLoader.get_str("QWENPAW_SKILL_SCAN_MODE") or None
    if env is not None:
        val = env.lower().strip()
        if val in _VALID_MODES:
            return val
    if cfg is None:
        cfg = _load_scanner_config()
    return cfg.mode if cfg is not None else "warn"
```

## 4. 安全系统的架构设计思维

### 4.1 纵深防御（Defense in Depth）

tool_guard 的三层守卫体现了纵深防御思想 —— 每层独立拦截常见攻击，层间互补。详细分析见 [38-工具Guard安全系统](./38-工具Guard安全系统.md)。

### 4.2 插件化架构（Plugin Architecture）

BaseToolGuardian 定义了最小接口协议（`guard()` 方法），支持未来热插拔新型守卫（如 LLM 判断守卫、AST 分析守卫、网络监控守卫）。详细设计见 [38-工具Guard安全系统](./38-工具Guard安全系统.md)。

### 4.3 认证加密优于普通加密

secret_store 使用 Fernet（AEAD）而非原始 AES，加密和完整性校验一步完成。详细分析见 [39-密钥存储加密系统](./39-密钥存储加密系统.md)。

### 4.4 零信任工具调用

tool_guard 不信任任何工具调用，即便工具名称看起来无害。这是"最小权限"原则的体现 —— 默认拒绝，只放行明确安全的调用。

### 4.5 优雅降级

secret_store 在 macOS（Keychain）、Linux GUI（Keychain）、Linux 服务器（文件 0o600）、Docker 容器、CI 环境下均有 fallback 路径。详细策略见 [39-密钥存储加密系统](./39-密钥存储加密系统.md)。

## 7. 常见问题

### 7.1 工具守卫问题

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 合法操作被拦截 | 规则过于严格 | 调整规则或禁用特定规则 |
| 危险操作未拦截 | 规则未覆盖 | 添加自定义规则或使用 disabled_rules |
| 误报频繁 | 规则阈值问题 | 调高 min_score 或调整规则 |

### 7.2 密钥问题

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 解密失败 | 密钥丢失或变更 | 恢复备份的密钥文件 |
| Keychain 不可用 | Linux 无 GUI | 使用文件存储（0o600 权限） |
| Docker 中密钥失效 | 容器共享密钥问题 | 配置 QWENPAW_SECRET_DIR 指向挂载目录 |

## 8. 总结

### 核心要点

1. **secret_store 密钥加密**: Fernet 对称加密（AEAD）+ 四层主密钥获取 + OS Keychain 优先 → 详见 [39-密钥存储加密系统](./39-密钥存储加密系统.md)
2. **tool_guard 三层守卫**: FilePathToolGuardian + RuleBasedToolGuardian + ShellEvasionGuardian → 详见 [38-工具Guard安全系统](./38-工具Guard安全系统.md)
3. **skill_scanner 技能扫描**: block/warn/off 三种模式 + PatternAnalyzer 正则分析（本章完整覆盖）
4. **纵深防御**: 每层独立拦截，层间互补，不过度依赖单一安全层
5. **认证加密**: Fernet = AES-128-CBC + HMAC-SHA256，提供机密性和完整性

### 9.3 工具调用安全对比

**Java（Spring Security Filter Chain）：**
```java
// Java - 工具调用的安全检查
@Component
public class ToolSecurityFilter extends OncePerRequestFilter {
    @Override
    protected void doFilterInternal(HttpServletRequest request,
                                    HttpServletResponse response,
                                    FilterChain chain)
            throws ServletException, IOException {

        String toolName = request.getParameter("tool");
        String params = request.getParameter("params");

        // 检查工具是否在白名单
        if (!securityConfig.isAllowedTool(toolName)) {
            throw new AccessDeniedException("Tool not allowed: " + toolName);
        }

        // 检查参数是否有危险模式
        if (dangerDetector.containsDangerousPattern(params)) {
            throw new AccessDeniedException("Dangerous pattern detected");
        }

        chain.doFilter(request, response);
    }
}
```

### 9.5 认证加密对比

**Java（Spring Crypto）：**
```java
// Java - 标准 AES 加密（无认证）
Cipher cipher = Cipher.getInstance("AES/CBC/PKCS5Padding");
cipher.init(Cipher.ENCRYPT_MODE, secretKey, iv);
byte[] encrypted = cipher.doFinal plaintext;

// Java - HMAC 完整性校验（需单独做）
Mac mac = Mac.getInstance("HmacSHA256");
mac.init(macKey);
byte[] hmac = mac.doFinal(encrypted);
// 单独传输 encrypted + hmac
```

**Python（Fernet - AEAD）：**
```python
# Python - Fernet = AES-128-CBC + HMAC-SHA256 一次性完成
from cryptography.fernet import Fernet

fernet = Fernet(key)  # key 包含加密密钥和签名密钥

# 加密并签名（一步完成）
token = fernet.encrypt(b"secret data")
# 输出包含 IV + 密文 + HMAC

# 解密并验证（一步完成）
plaintext = fernet.decrypt(token)  # 验证失败抛异常
```

### 9.7 关键差异总结

1. **密钥管理**：Java 常用集中式密钥管理（Vault），QwenPaw 用本地 Keychain + 文件
2. **工具安全**：Java 用 Filter Chain 拦截请求，QwenPaw 在 AI 推理前拦截工具调用
3. **加密算法**：Java 需要手动组合 AES + HMAC，QwenPaw 直接用 Fernet（AEAD）
4. **代码扫描**：Java 扫描依赖项漏洞，QwenPaw 扫描技能代码恶意逻辑
5. **设计哲学**：Java 安全是企业级（集中管控），QwenPaw 是开发者友好（本地优先）
