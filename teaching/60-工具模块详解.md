## 2. command_runner — 进程执行

源码路径：`src/qwenpaw/utils/command_runner.py`

### 2.1 核心类型

```python
# src/qwenpaw/utils/command_runner.py
@dataclass(frozen=True)
class CommandResult:
    """命令执行结果"""
    command: list[str]               # 执行命令
    returncode: int                  # 退出码
    stdout: str                      # 标准输出
    stderr: str                      # 错误输出

    @property
    def combined_output(self) -> str:
        """合并 stdout 和 stderr（去除空行）"""
        parts = [
            part.strip() for part in (self.stdout, self.stderr) if part.strip()
        ]
        return "\n".join(parts)

    @property
    def stdout_lines(self) -> list[str]:
        """标准输出按行分割"""
        return self.stdout.splitlines()

    @property
    def stderr_lines(self) -> list[str]:
        """错误输出按行分割"""
        return self.stderr.splitlines()

@dataclass(frozen=True)
class ShutdownResult:
    """进程关闭结果"""
    command: list[str]                  # 执行命令
    pid: int                            # 进程 ID
    exited: bool                        # 进程是否已退出
    terminated_gracefully: bool         # 是否优雅终止 (SIGTERM)
    killed: bool                        # 是否强制杀死 (SIGKILL)
    timed_out: bool                     # 是否超时
    returncode: int | None              # 退出码
```

### 2.2 主要函数

| 函数 | 签名 | 用途 |
|------|------|------|
| `run_command()` | `(cmd, timeout, cwd) → CommandResult` | 同步命令执行（带超时） |
| `run_command_async()` | `(cmd, timeout, cwd) → CommandResult` | 异步命令执行 |
| `start_command_async()` | `(cmd, cwd) → (proc, pid)` | 启动长期运行命令 |
| `shutdown_process()` | `(pid, timeout) → ShutdownResult` | 优雅终止（SIGTERM→SIGKILL） |

### 2.3 使用示例

```python
# 同步执行
result = run_command(
    cmd=["python", "-c", "print('hello')"],
    timeout=10,
    cwd="/project"
)
print(result.stdout)

# 异步执行
result = await run_command_async(
    cmd=["npm", "run", "build"],
    timeout=300,
)

# 启动长期进程
proc, pid = await start_command_async(
    cmd=["python", "server.py"],
    cwd="/project"
)

# 优雅关闭
shutdown_result = await shutdown_process(pid, timeout=30)
print(f"优雅终止: {shutdown_result.terminated_gracefully}")
```

## 5. stdio — 标准流保护

源码路径：`src/qwenpaw/utils/stdio.py`

### 5.1 标准流保护

```python
# src/qwenpaw/utils/stdio.py
def ensure_standard_streams() -> None:
    """用 /dev/null 替换损坏的 stdout/stderr

    场景：
    - 标准输出被重定向到不存在的管道
    - 流被关闭但仍有写入
    - 写入时触发 BrokenPipeError

    解决方案：
    - 检测流是否损坏
    - 替换为 /dev/null 或 StringIO
    """
```

**问题场景：**

```
场景 1: 输出重定向到已关闭的管道
$ python app.py | head -n 1
# head 关闭管道后，app.py 继续输出会 BrokenPipe

场景 2: 标准流被意外关闭
import sys
sys.stdout.close()  # 之后所有 print() 失败
```

### 5.2 使用场景

```python
# 在应用启动时调用
ensure_standard_streams()

# 之后所有 print() 和 logging 不会因流损坏而崩溃
print("This will never fail even if stdout is broken")
```

### 7.2 收集的数据

```python
# src/qwenpaw/utils/telemetry.py
def collect_and_upload_telemetry() -> None:
    """收集并上传匿名使用信息

    收集内容：
    - install_id: 匿名安装 ID (UUID)
    - version: QwenPaw 版本
```

```python
    elif sys.platform == "darwin":
```

## 10. 常见问题

### Q1: print() 在某些环境下崩溃？

**原因：** 标准输出被重定向到损坏的管道。

**解决：**

```python
from qwenpaw.utils.stdio import ensure_standard_streams
ensure_standard_streams()
```

### Q2: 遥测收集影响性能？

**原因：** 网络请求可能阻塞。

**解决：**

```python
# 遥测在后台线程中收集
import threading
threading.Thread(target=collect_and_upload_telemetry, daemon=True).start()
```

### Q3: 控制台静态资源找不到？

**排查：**

```python
from qwenpaw.utils.console_static import resolve_console_static_dir
path = resolve_console_static_dir()
print(f"Console dir: {path}")
print(f"Exists: {path.exists()}")
```

### Q4: system_info 在某些平台上获取失败？

**原因：** 平台特定 API 不可用。

**解决：**

```python
from qwenpaw.utils.system_info import get_system_info

try:
    info = get_system_info()
except Exception as e:
    # 返回默认值
    info = {"error": str(e)}
```

## 13. 练习题

### 知识检查

1. **进程执行管理**：`CommandResult` 数据类提供了 `combined_output` 属性来合并 stdout 和 stderr。在什么场景下 stderr 包含有用信息而非错误？`shutdown_process()` 的 SIGTERM 到 SIGKILL 两级终止策略为什么要设置 grace period？

2. **静态资源解析**：`resolve_console_static_dir()` 使用四级优先级查找控制台资源。为什么环境变量 `QWENPAW_CONSOLE_STATIC_DIR` 的优先级最高？这解决了什么部署场景的问题？

3. **标准流保护**：`ensure_standard_streams()` 在应用启动时用 `/dev/null` 替换损坏的 stdout/stderr。请描述在 `python app.py | head -n 1` 场景下，如果不调用此函数会发生什么。

```python
# 练习: 实现跨平台配置路径解析
```

## 14. 如果你来自 Java...

### Java 开发者对照表

| Java 概念 | Python/QwenPaw 实现 | 说明 |
|-----------|---------------------|------|
| `ProcessBuilder` | `command_runner.run_command()` | 进程执行管理 |
| `System.getenv()` | `os.environ` / `EnvVarLoader` | 环境变量访问 |
| `java.util.logging` | `logging.py` | 日志框架 |
| `Files.walk()` | `pathlib.Path` | 文件系统操作 |
| `System.exit()` | `shutdown_process()` | 进程终止 |

### 关键差异

**1. 进程执行**

```java
// Java: ProcessBuilder
ProcessBuilder pb = new ProcessBuilder("ls", "-la");
pb.directory(new File("/path"));
Process p = pb.start();
int exitCode = p.waitFor();
```

```python
# Python: command_runner
from qwenpaw.utils.command_runner import run_command

result = run_command(
    cmd=["ls", "-la"],
    cwd="/path",
    timeout=30
)
print(result.returncode)  # 返回码
```

**2. 环境变量**

```java
// Java
String home = System.getenv("HOME");
System.setProperty("key", "value");  // 设置系统属性
```

```python
# Python
import os
home = os.environ.get("HOME")
os.environ["key"] = "value"  # 设置环境变量
# 或使用 QwenPaw 的类型安全访问
from qwenpaw.constant import EnvVarLoader
value = EnvVarLoader.get_str("KEY", "default")
```

**3. 日志配置**

```java
// Java: java.util.logging
Logger logger = Logger.getLogger(MyClass.class.getName());
Handler handler = new ConsoleHandler();
logger.addHandler(handler);
logger.setLevel(Level.INFO);
```

```python
# Python: QwenPaw logging
from qwenpaw.utils.logging import setup_logger
setup_logger("info")  # 简洁的日志配置
```

**4. 跨平台系统信息**

```java
// Java: 跨平台需要第三方库如 oshi
OsHardwareInfo info = oshi.getHardware();
System.out.println("Memory: " + info.getMemory());
```

```python
# Python: QwenPaw system_info
from qwenpaw.utils.system_info import get_system_info
info = get_system_info()  # 统一的跨平台 API
```

### Java 开发者注意事项

1. **Python 的 GIL 限制**: Python 多线程不能真正并行执行 CPU 密集型任务，但 I/O 密集型任务可通过 `asyncio` 高效处理。

2. **subprocess vs ProcessBuilder**: QwenPaw 的 `command_runner` 是对 `subprocess` 的封装，提供了更简洁的 API 和超时控制。

3. **环境变量是进程级**: 设置 `os.environ` 只影响当前进程及其子进程，不会影响系统环境。

4. **路径处理**: 始终使用 `pathlib.Path` 而不是字符串拼接，它能自动处理不同操作系统的路径分隔符。
