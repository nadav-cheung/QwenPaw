## 2. 核心模块详解

### 2.1 Agents 模块

**路径**: `src/qwenpaw/agents/`

智能体核心模块，是 QwenPaw 的"大脑"。

| 子模块 | 功能 |
|--------|------|
| `react_agent.py` | QwenPawAgent 核心类，ReAct 模式实现 |
| `tool_guard_mixin.py` | 工具安全拦截 |
| `model_factory.py` | 模型创建工厂 |
| `skills_manager.py` | 技能管理器 |
| `skills_hub.py` | 技能中心 |
| `multi_agent_manager.py` | 多智能体管理 |
| `memory/` | 记忆系统 |
| `mission/` | Mission 模式 |
| `hooks/` | 生命周期钩子 |
| `tools/` | 内置工具 |

**核心类**: `QwenPawAgent`

```python
class QwenPawAgent(ToolGuardMixin, ReActAgent):
    """
    QwenPaw 智能体核心类

    MRO (方法解析顺序):
    QwenPawAgent → ToolGuardMixin → ReActAgent → Agent
    """
```

### 2.2 App 模块

**路径**: `src/qwenpaw/app/`

应用系统模块，是 QwenPaw 的"躯干"。

| 子模块 | 功能 |
|--------|------|
| `server.py` | FastAPI 服务器 |
| `runner/` | 请求处理器 |
| `channels/` | 消息渠道 (钉钉/飞书/微信等) |
| `routers/` | API 路由 |
| `acp/` | ACP 协议 |
| `workspace/` | 工作区隔离 |

### 2.3 Providers 模块

**路径**: `src/qwenpaw/providers/`

LLM 提供商模块，是 QwenPaw 的"能源"。

| Provider | 说明 |
|----------|------|
| `openai_provider.py` | OpenAI GPT 系列 |
| `ollama_provider.py` | Ollama 本地模型 |
| `anthropic_provider.py` | Anthropic Claude |
| `gemini_provider.py` | Google Gemini |
| `lmstudio_provider.py` | LM Studio |
| `openrouter_provider.py` | OpenRouter 聚合 |

### 2.4 Security 模块

**路径**: `src/qwenpaw/security/`

安全系统模块，是 QwenPaw 的"免疫系统"。

| 子模块 | 功能 |
|--------|------|
| `tool_guard/` | 工具调用安全守卫 |
| `skill_scanner/` | 技能安全扫描 |
| `secret_store.py` | 密钥加密存储 |

## 3. 架构分层

### 3.1 分层架构图

```
┌─────────────────────────────────────────────────────────────┐
│                      Presentation Layer                     │
│                        (用户界面层)                            │
├─────────────────────────────────────────────────────────────┤
│  CLI (命令行)  │  Console (Web界面)  │  Channels (消息渠道)  │
├─────────────────────────────────────────────────────────────┤
│                      Application Layer                       │
│                        (应用层)                              │
├─────────────────────────────────────────────────────────────┤
│    Server (FastAPI)  │  Runner (请求处理)  │  Routers (路由)  │
├─────────────────────────────────────────────────────────────┤
│                       Domain Layer                          │
│                        (领域层)                              │
├─────────────────────────────────────────────────────────────┤
│   Agents (智能体)  │  Providers (模型)  │  Security (安全)   │
├─────────────────────────────────────────────────────────────┤
│                    Infrastructure Layer                      │
│                        (基础设施层)                          │
├─────────────────────────────────────────────────────────────┤
│     Config (配置)  │  Plugins (插件)  │  Utils (工具函数)     │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 各层职责

| 层级 | 职责 | 示例 |
|------|------|------|
| **Presentation** | 用户交互 | CLI 命令、Web 界面、消息渠道 |
| **Application** | 请求调度 | FastAPI 服务器、请求路由 |
| **Domain** | 核心业务 | 智能体推理、工具执行、记忆管理 |
| **Infrastructure** | 基础支持 | 配置加载、插件加载、日志记录 |

## 4. 核心数据流

### 4.1 请求处理流程

```
用户消息
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│                     Channels (消息渠道)                      │
│         钉钉/飞书/微信/Discord/Telegram/Console              │
└─────────────────────────┬───────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐
│                    Server (FastAPI)                         │
│                      API 入口                                │
└─────────────────────────┬───────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐
│                    Runner (请求处理器)                       │
│              session.py → task_tracker.py                   │
└─────────────────────────┬───────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐
│                 QwenPawAgent (智能体)                        │
│                                                             │
│  ┌───────────┐    ┌───────────┐    ┌───────────┐           │
│  │ Reasoning │───▶│  Acting   │───▶│  Tools    │           │
│  └───────────┘    └───────────┘    └───────────┘           │
│       │                                  │                   │
│       │◀─────────────────────────────────┘                   │
│       │              (循环直到完成)                             │
└───────┼─────────────────────────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────────────────────────────────┐
│                     Memory (记忆)                            │
│              agent_md_manager.py                            │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 工具调用流程

```
Agent 决定调用工具
        │
        ▼
┌─────────────────────────────────────────────────────────────┐
│                   ToolGuard (安全守卫)                       │
│         检查工具调用是否安全、是否有权限                       │
└─────────────────────────┬───────────────────────────────────┘
        │                 │
        │ 安全             │ 不安全
        ▼                 ▼
┌───────────────┐   ┌─────────────────────────────────────────┐
│  执行工具      │   │  拦截并返回安全警告                       │
│  (Tools)      │   │  不执行危险操作                          │
└───────┬───────┘   └─────────────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────────────────────────────────┐
│                    工具结果返回                              │
│         记忆存储 → 下一次推理输入                             │
└─────────────────────────────────────────────────────────────┘
```

## 7. 架构设计原则

### 7.1 模块化

每个模块都有明确的职责边界：

```
好设计：
┌─────────┐    ┌─────────┐    ┌─────────┐
│  CLI    │───▶│  App    │───▶│ Agents  │
└─────────┘    └─────────┘    └─────────┘
      │              │              │
      ▼              ▼              ▼
   独立职责      独立职责        独立职责

坏设计：
┌─────────────────────────────────────────┐
│              一切皆有可能                  │
│   (模块间直接耦合，难以维护和测试)           │
└─────────────────────────────────────────┘
```

### 7.2 可扩展性

通过插件和技能系统实现扩展：

```
内置功能 (不可修改)
    │
    ├── Tools (内置工具)
    ├── Skills (内置技能)
    └── Providers (内置模型)

可扩展功能 (可以添加)
    │
    ├── Plugins (插件)
    ├── Custom Skills (自定义技能)
    └── Custom Providers (自定义模型)
```

### 7.3 安全性

多层安全防护：

```
第一层：ToolGuard (工具调用前检查)
   │
   ├── 路径检查 (防止目录遍历)
   ├── 参数检查 (防止注入攻击)
   └── 权限检查 (防止未授权操作)

第二层：SkillScanner (技能加载前扫描)
   │
   ├── 敏感 API 检测
   └── 恶意代码检测

第三层：SecretStore (密钥安全存储)
   │
   ├── 加密存储
   └── 访问控制
```

## 8. 工程经验

### 8.1 为什么这样分层？

**分层的好处**：
- **可测试性**：每层可以独立测试
- **可替换性**：可以替换某层的实现而不影响其他层
- **可维护性**：问题可以快速定位到某层

**分层的代价**：
- **性能开销**：层间调用有开销
- **复杂度**：需要理解层间交互

### 8.2 可能的架构问题

| 问题 | 影响 | 改进建议 |
|------|------|----------|
| Agents 过于庞大 | 难以测试和维护 | 拆分为更小的组件 |
| 循环依赖 | 难以理解和测试 | 引入接口解耦 |
| 隐式耦合 | 隐藏的依赖关系 | 显式声明依赖 |

### 8.3 实际生产中的问题

- **并发问题**：多个请求同时处理时需要线程安全
- **资源泄漏**：长时间运行时需要正确释放资源
- **错误恢复**：某模块失败时需要优雅降级
