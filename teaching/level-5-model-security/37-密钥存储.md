## 概述

QwenPaw 的密钥存储系统使用 **Fernet**（AES-128-CBC + HMAC-SHA256）加密，通过四级密钥解析链（缓存 → keyring → 文件 → 生成）保护敏感数据，并支持备份恢复时的密钥冲突处理。

**Java 对比示例**：

```java
// Java KeyStore 方式
KeyStore keyStore = KeyStore.getInstance("JCEKS");
keyStore.load(null);
keyStore.setKeyEntry("mykey", key, password, certChain);

// Python Fernet 方式
from cryptography.fernet import Fernet
key = Fernet.generate_key()  # 生成 32 字节密钥
f = Fernet(key)
token = f.encrypt(b"secret")  # 加密
```

**关键差异**：
- **Java**：企业级密钥管理（KeyStore + HSM + KMS 多层）
- **Python Fernet**：轻量级对称加密，适合单服务密钥管理
- **QwenPaw**：通过四级密钥解析链兼顾安全与易用（keyring > 文件 > 自动生成）

**MultiFernet 密钥轮换**（类似 Java 的 KeyVersioning）：

```python
from cryptography.fernet import Fernet, MultiFernet

# 初始化多密钥支持轮换
key1 = Fernet(Fernet.generate_key())
key2 = Fernet(Fernet.generate_key())
mf = MultiFernet([key1, key2])  # 第一个用于加密，其他用于解密

# 加密消息
token = mf.encrypt(b"敏感数据")

# 轮换到新密钥
key3 = Fernet(Fernet.generate_key())
mf2 = MultiFernet([key3, key1, key2])  # 新密钥在前
rotated = mf2.rotate(token)  # 用新密钥重新加密
```

> **提示**：Java 的 `KeyStore` 支持硬件令牌（HSM），QwenPaw 的 keyring 类似但依赖 OS 实现。生产环境建议使用云 KMS（如 AWS KMS）替代本地 keyring。

### 1.1 获取 Fernet 实例

```python
_cached_fernet: Optional[object] = None

def _get_fernet():
    """返回由主密钥支持的缓存 Fernet 实例"""
    global _cached_fernet
    if _cached_fernet is not None:
        return _cached_fernet

    from cryptography.fernet import Fernet
    raw = _get_master_key()
    fernet_key = base64.urlsafe_b64encode(raw[:32])  # 仅使用前 32 字节
    _cached_fernet = Fernet(fernet_key)
    return _cached_fernet
```

### 1.2 加密

```python
# src/qwenpaw/security/secret_store.py:213
def encrypt(plaintext: str) -> str:
    """加密 plaintext 并返回 ENC:<base64-ciphertext>"""
    if not plaintext:
        return plaintext
    f = _get_fernet()
    token = f.encrypt(plaintext.encode("utf-8"))
```

### 1.3 解密

```python
# src/qwenpaw/security/secret_store.py:222
def decrypt(value: str) -> str:
    """如果值带有 ENC: 前缀则解密，否则透传"""
    if not value or not value.startswith(_ENC_PREFIX):
        return value
    try:
        f = _get_fernet()
        token = value[len(_ENC_PREFIX):].encode("ascii")
        return f.decrypt(token).decode("utf-8")
    except Exception:
        logger.warning("解密失败，返回原始密文")
        return value
```

| 密钥编码 | base64 urlsafe |

## 2. 四级密钥解析链

### 2.1 解析顺序

```python
# src/qwenpaw/security/secret_store.py:154
def _get_master_key() -> bytes:
    """返回 32 字节主密钥，如不存在则创建。

    使用双重检查锁定保证只有一个线程生成或加载密钥。

    解析顺序：
    1. 进程内缓存（快速路径，无锁）
    2. OS keychain（通过 keyring）
    3. 文件 SECRET_DIR/.master_key
    4. 生成新的 → 存储到 keychain（优先）和文件（后备）
    """
    global _cached_master_key
    if _cached_master_key is not None:
        return _cached_master_key  # 步骤 1

    with _master_key_lock:
        if _cached_master_key is not None:
            return _cached_master_key

        key_hex = _try_keyring_get()  # 步骤 2
        if not key_hex:
            key_hex = _read_key_file()  # 步骤 3
            if key_hex:
                _try_keyring_set(key_hex)  # 同步 keyring

        if not key_hex:
            key_hex = _generate_master_key()  # 步骤 4
            _try_keyring_set(key_hex)
            _write_key_file(key_hex)

        _cached_master_key = bytes.fromhex(key_hex)
        return _cached_master_key
```

### 2.2 Keyring 访问

```python
# src/qwenpaw/security/secret_store.py:71
_KEYRING_SERVICE = "qwenpaw"
_KEYRING_ACCOUNT = "master_key"

def _try_keyring_get() -> Optional[str]:
    """从 OS keychain 读取主密钥"""
    if _should_skip_keyring():
        return None
    try:
        import keyring
        value = keyring.get_password(_KEYRING_SERVICE, _KEYRING_ACCOUNT)
        return value or None
    except Exception:
        return None

def _try_keyring_set(key_hex: str) -> bool:
    """存储主密钥到 OS keychain"""
    if _should_skip_keyring():
        return False
    try:
        import keyring
        keyring.set_password(_KEYRING_SERVICE, _KEYRING_ACCOUNT, key_hex)
        return True
    except Exception:
        return False
```

### 2.3 跳过 Keyring 的条件

```python
# src/qwenpaw/security/secret_store.py:42-55
def _should_skip_keyring() -> bool:
    """当 OS keychain 不太可能可用时返回 True

    覆盖:
    - Docker 容器
    - 无显示器的 Linux 服务器
    - CI 环境
    """
    if EnvVarLoader.get_bool("QWENPAW_RUNNING_IN_CONTAINER"):
        return True
    if sys.platform == "linux" and not (
        os.environ.get("DISPLAY") or os.environ.get("WAYLAND_DISPLAY")
    ):
        return True
    if os.environ.get("CI", "").lower() in ("true", "1"):
        return True
    return False
```

### 2.4 文件存储

```python
# src/qwenpaw/security/secret_store.py:111-166
def _master_key_file() -> Path:
    return _get_secret_dir() / ".master_key"

def _write_key_file(key_hex: str) -> None:
    path = _master_key_file()
    path.parent.mkdir(parents=True, exist_ok=True)
    path.write_text(key_hex, encoding="utf-8")
    try:
        os.chmod(path, 0o600)  # 仅所有者读写
    except OSError:
        pass

def _generate_master_key() -> str:
    """生成 32 字节随机主密钥并返回其十六进制编码"""
    return secrets.token_hex(32)
```

### 2.5 双重检查锁定 (DCLP)

```python
# src/qwenpaw/security/secret_store.py:116-130
def _get_master_key() -> bytes:
    """使用双重检查锁定保证线程安全"""
    global _cached_master_key

    # 第一层：进程内缓存（无锁快速路径）
    if _cached_master_key is not None:
        return _cached_master_key

    with _master_key_lock:  # 第二层：线程锁
        # 双重检查
        if _cached_master_key is not None:
            return _cached_master_key

        # 密钥不存在 → 生成或加载
        key_hex = _try_keyring_get()
        if not key_hex:
            key_hex = _read_key_file()
            if key_hex:
                _try_keyring_set(key_hex)  # 同步到 keychain

        if not key_hex:
            key_hex = _generate_master_key()
            _try_keyring_set(key_hex)
            _write_key_file(key_hex)

        _cached_master_key = bytes.fromhex(key_hex)
        return _cached_master_key
```

### 3.2 加密/解密字典助手

```python
# src/qwenpaw/security/secret_store.py:308-336
def encrypt_dict_fields(data: dict, secret_fields: frozenset[str]) -> dict:
    """返回 data 的浅拷贝，secret_fields 被加密。

    防重复加密：如果字段已加密（ENC: 前缀），跳过
    """
    result = dict(data)
    for field in secret_fields:
        if (
            field in result
            and isinstance(result[field], str)
            and result[field]
        ):
            if not is_encrypted(result[field]):  # 已加密的不重复加密
                result[field] = encrypt(result[field])
    return result

def decrypt_dict_fields(data: dict, secret_fields: frozenset[str]) -> dict:
    """返回 data 的浅拷贝，secret_fields 被解密。"""
    result = dict(data)
    for field in secret_fields:
        if (
            field in result
            and isinstance(result[field], str)
            and result[field]
        ):
            result[field] = decrypt(result[field])
    return result
```

### 3.5 提供商加载（自动迁移）

```python
# src/qwenpaw/providers/provider_manager.py:1262-1280
def load_provider(self, provider_id: str, is_builtin: bool = False):
    """加载提供商配置。加密字段透明解密。

    如果检测到遗留明文 api_key，在读取时自动重新加密。
    """
    with open(provider_path, "r", encoding="utf-8") as f:
        data = json.load(f)

    # 检测遗留明文并触发迁移
    needs_rewrite = self._maybe_migrate_plaintext(data, PROVIDER_SECRET_FIELDS)

    # 透明解密
    data = decrypt_dict_fields(data, PROVIDER_SECRET_FIELDS)
    provider = self._provider_from_data(data)

    # 如果检测到明文，写回时加密
    if needs_rewrite:
        self._save_provider(provider, is_builtin=is_builtin, skip_if_exists=False)
    return provider
```

## 4. 完整加密/解密流程

### 4.1 加密流程

```
用户输入明文 (如 "sk-abc123")
        │
        ▼
encrypt("sk-abc123")
        │
        ├─ 空字符串? → 直接返回 ""
        │
        ▼
_get_fernet() 获取 Fernet 实例
        │
        ├─ 检查 _cached_fernet 缓存
        └─ 无缓存? → 用 master_key 生成新的 Fernet
        │
        ▼
fernet.encrypt("sk-abc123".encode("utf-8"))
        │
        ▼
base64 编码 → "gAAAAABh..." (Fernet token)
        │
        ▼
返回 "ENC:" + token → "ENC:gAAAAABh..."
```

### 4.2 解密流程

```
读取值 (如 "ENC:gAAAAABh...")
        │
        ▼
decrypt("ENC:gAAAAABh...")
        │
        ├─ 非 ENC: 前缀? → 直接返回原值（明文）
        ├─ 空字符串? → 直接返回
        │
        ▼
_get_fernet() 获取 Fernet 实例
        │
        ▼
提取 token: value[len("ENC:"):]
        │
        ▼
fernet.decrypt(token)
        │
        ├─ 成功 → 返回解密后的字符串
        └─ 失败 (Exception) → 记录警告日志，返回原始密文（优雅降级）
```

### 4.3 主密钥获取流程

```
_get_master_key() 调用
        │
        ├─ _cached_master_key 有缓存? → 直接返回 (无锁快速路径)
        │
        ▼
获取 _master_key_lock 锁
        │
        ├─ 双重检查缓存
        │
        ▼
_try_keyring_get() → OS Keychain 读取
        │
        ├─ 成功? → 缓存并返回
        └─ 失败/跳过? → 继续
        │
        ▼
_read_key_file() → 读取 SECRET_DIR/.master_key
        │
        ├─ 成功? → 同步到 keychain 并缓存返回
        └─ 失败? → 继续
        │
        ▼
_generate_master_key() → 生成新密钥 (secrets.token_hex(32))
        │
        ▼
_try_keyring_set(key_hex) → 存入 keychain (失败可接受)
_write_key_file(key_hex) → 写入文件并设置 0o600 权限
        │
        ▼
缓存并返回 32 字节密钥
```

```python
def reload_master_key_from_disk() -> None:
```

## 8. OS Keychain 后端与容器环境

### 8.1 支持的 Keychain 后端

不同操作系统使用不同的 Keychain 后端，keyring 库自动适配：

| 操作系统 | Keychain 后端 |
|----------|---------------|
| macOS | Keychain |
| Windows | Windows Credential Locker |
| Linux | Secret Service (GNOME) / kwallet |
| 容器/CI | 跳过 Keychain |

### 8.2 容器与 CI 环境密钥注入

在容器和 CI 环境中，OS Keychain 通常不可用（`_should_skip_keyring` 返回 True）。此时需要通过其他方式传入主密钥。

```bash

# 方式 2：挂载密钥文件
docker run -v ~/.qwenpaw/.master_key:/app/.qwenpaw/.master_key qwenpaw
```

**CI/CD 环境密钥注入：**

```yaml
# .github/workflows/deploy.yml
```

## 9. 密钥轮换操作

当需要更换主密钥时（如密钥泄露），按以下步骤操作：

```bash
# 1. 备份旧密钥
cp ~/.qwenpaw/.master_key ~/.qwenpaw/.master_key.bak

# 2. 删除旧密钥文件（触发重新生成）
rm ~/.qwenpaw/.master_key

# 3. 重启 QwenPaw（自动生成新密钥）
# 注意：使用旧密钥加密的数据将无法解密
```

> **警告**：密钥轮换后，所有用旧密钥加密的数据（Provider API Key 等）将无法解密。需要在轮换前重新记录所有敏感配置，轮换后重新配置。

## 11. 应用场景

### 11.1 API Key 安全存储

**场景**：存储第三方 API Key（如 OpenAI、Anthropic）。

**流程**：

2. ProviderManager 保存时调用 `encrypt_dict_fields()`

### 11.2 备份与恢复

**场景**：迁移到新机器，需要恢复配置和凭证。

**风险**：新机器的主密钥与备份不同，导致无法解密。

**解决方案**：
1. `handle_master_key_conflict()` 检测密钥冲突
2. 旧密钥备份到 `_pre_restore_keys/` 目录
3. 恢复后可通过旧密钥解密备份数据

### 11.3 容器环境部署

**场景**：在 Docker 容器中运行 QwenPaw。

**配置**：
```bash
QWENPAW_RUNNING_IN_CONTAINER=true
```
主密钥将跳过 keyring，直接使用文件存储。

## 13. 常见问题

### Q1: 忘记主密钥？

**说明**：主密钥丢失后，加密的数据无法恢复。请务必备份 `.master_key` 文件。

### Q2: keyring 操作失败？

**原因**：
- Linux 无 keyring 守护（如 in WSL）
- 权限不足
- keyring 服务未启动

**解决方案**：设置 `QWENPAW_RUNNING_IN_CONTAINER=true` 跳过 keyring。

### Q3: 解密失败？

**可能原因**：
1. 主密钥与加密时不同
2. 数据损坏
3. 格式错误

**处理**：返回原始密文（`decrypt` 的优雅降级策略）。

### Q4: 如何轮换主密钥？

**说明**：当前不支持主密钥轮换。更换主密钥后需要重新加密所有敏感数据。

### Q5: 备份恢复后凭证无法使用？

**原因**：恢复时使用了与备份时不同的主密钥。

**解决方案**：
1. `handle_master_key_conflict()` 会备份旧密钥
2. 可手动恢复旧密钥到 `_pre_restore_keys/` 目录
3. 或使用与备份相同的主密钥

## ★ Insight ─────────────────────────────────────
**加密的透明性**：调用方（如 ProviderManager）完全不需要知道某个字段是否被加密——`encrypt_dict_fields` 会自动跳过已经是 `ENC:` 前缀的值。这意味着同一个字段可以被多次"加密"而不破坏数据（幂等性）。

**优雅降级的安全含义**：`decrypt()` 在失败时返回原始密文而非抛出异常。这看起来是"不安全"的，但它确保了服务不会因为密钥不匹配而完全崩溃。在安全性和可用性之间，这是一个务实的权衡。

**容器环境的密钥困境**：在 Docker 容器中跳过 keyring 意味着主密钥只能存文件。如果容器的 `~/.qwenpaw.secret/.master_key` 文件被直接挂载到宿主机（常见的 Docker Compose 模式），文件的 0o600 权限可能失效。建议通过 `docker run --secret` 或环境变量传入密钥。

### 16.5 如何避免破坏架构

**加密系统规则**：
- 主密钥是 32 字节（256 位），必须使用 `secrets.token_hex(32)` 生成
- Fernet token 必须以 `ENC:` 前缀标识，便于区分加密和明文值
- `decrypt()` 失败时返回原始密文而非抛出异常，确保服务可用性

**密钥存储规则**：
- Keyring 操作失败必须静默处理（回退到文件存储）
- 文件权限必须设为 `0o600`，确保只有所有者可读写
- 跳过 Keyring 的条件必须明确：容器、CI、无 GUI 的 Linux

**数据迁移规则**：
- Provider 配置中的明文密钥必须自动迁移为加密形式
- 迁移必须在读取时触发，写回时加密

**测试要求**：
- 修改加密逻辑后，必须验证加密/解密往返一致性
- 修改密钥获取后，必须验证四级解析链的每个步骤
- 修改 Provider 加密后，必须验证明文迁移功能正常
