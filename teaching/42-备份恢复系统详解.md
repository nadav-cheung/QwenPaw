# 备份恢复系统详解

## 概述

QwenPaw 的备份恢复系统采用**两阶段提交 + 原子目录交换**协议，支持增量备份、SSE 进度流式推送、备份 ID 冲突处理，以及跨机器恢复时的密钥冲突解决。

**核心设计理念**：备份是数据安全的最后防线，系统通过原子操作确保恢复过程不会导致数据损坏，同时通过密钥冲突处理保证跨环境恢复的可行性。

**Java 对比示例**：

```java
// Java 原子文件替换
Path tmp = Paths.get("/tmp/backup.zip");
Path dest = Paths.get("/backup.zip");
Files.move(tmp, dest, StandardCopyOption.ATOMIC_MOVE);

// QwenPaw 三阶段原子交换
# Phase 1: 提取到 .restore_tmp
# Phase 2: .restore_old ← dst, tmp ← dst (原子 rename)
# Phase 3: 删除 .restore_old
```

**关键差异**：
- **Java**：依赖文件系统原生原子操作（`Files.move(..., ATOMIC_MOVE)`）
- **QwenPaw**：通过三阶段协议实现崩溃安全，支持 Windows 等不支持原子 rename 的系统
- **Zip Slip 防护**：Java 可以使用 `Path.normalize()` 防止路径遍历，QwenPaw 使用 `is_relative_to()` 验证

```python
# src/qwenpaw/backup/_ops/create.py:109
def _compress_to_tmp(tmp: Path, dest: Path, scope: BackupScope) -> None:
    """写入 .tmp 文件，成功后原子替换为 .zip"""
    with zipfile.ZipFile(tmp, "w", zipfile.ZIP_DEFLATED) as zf:
        # 1. Agent workspace 数据
        _add_agent_workspaces(zf, scope.include_agents, ...)
        # 2. 全局配置
        if scope.include_global_config:
            _add_global_config(zf)
        # 3. 密钥目录
        if scope.include_secrets:
            _add_secrets(zf)
        # 4. 技能池
        if scope.include_skill_pool:
            _add_skill_pool(zf)
    tmp.replace(dest)  # 原子替换
```

## 2. 三阶段原子目录交换

源码路径：`src/qwenpaw/backup/_utils/safe_swap.py`

### 2.1 交换协议

```
Phase 1: extract into .restore_tmp sibling directory
         ↓
Phase 2: atomically rename old dst → .restore_old
                then tmp → dst
         ↓
Phase 3: remove .restore_old
```

**为什么需要三阶段？**
- **原子性**：要么完全恢复，要么完全不恢复
- **可恢复性**：保留 `.restore_old` 目录直到新数据完全就绪
- **崩溃安全**：任何阶段崩溃都可以通过清理函数恢复

| 场景 3 | `.restore_old` 存在，`base_dir` 存在 | 清理过时的旧目录 |

## 3. 主密钥冲突处理

源码路径：`src/qwenpaw/backup/_ops/restore_helpers.py:108`

### 3.1 冲突处理逻辑

```python
# src/qwenpaw/backup/_ops/restore_helpers.py:284
def handle_master_key_conflict(zf: zipfile.ZipFile, bak_dir: Path) -> Path | None:
    """当备份的 .master_key 与当前磁盘不同时，备份当前密钥。

    将现有密钥保存到：
    BACKUP_DIR/_pre_restore_keys/<UTC-timestamp>.master_key.bak
    以便仍能用旧密钥解密用其加密的凭证。
    """
    if backup_mk_bytes != current_mk_bytes:
        bak = bak_dir / f"{ts}.master_key.bak"
        shutil.copy2(current_master_key, bak)
    return None
```

**为什么需要处理密钥冲突？**
- 不同机器的 `.master_key` 不同
- 恢复备份时如果直接替换密钥，旧密钥加密的数据将无法解密
- 解决：将旧密钥备份，保留解密能力

### 3.2 恢复后重载

```python
# src/qwenpaw/security/secret_store.py:249
def reload_master_key_from_disk() -> None:
    """使进程内主密钥缓存失效并重新同步 OS keyring"""
    global _cached_master_key, _cached_fernet
    with _master_key_lock:
        _cached_master_key = None
        _cached_fernet = None
```

## 4. 恢复模式与 Agent 冲突检测

### 4.1 恢复模式

```python
# src/qwenpaw/backup/models.py:58
mode: Literal["full", "custom"] = "custom"
```

| 模式 | 行为 |
|------|------|
| `full` | 完整替换，`agents.profiles` 全部使用备份数据 |
| `custom` | 重建 `agents.profiles`，防止幽灵 Agent |

**模式选择建议**：
- `full` 模式适用于全新环境或确定要完全覆盖的场景
- `custom` 模式是**默认推荐**，可防止遗留的幽灵 Agent

### 4.2 Agent 目标冲突检测

```python
# src/qwenpaw/backup/_ops/restore.py:99
def _plan_agent_destinations() -> None:
    """检测两种冲突类型"""
    # 1. 两个 Agent 解析到同一目录
    # 2. 新 Agent 目标与现有未恢复的 Agent 工作区碰撞
    if is_new and dst in other_workspace_paths:
```

**冲突类型**：
- **同目录冲突**：两个 Agent 的 ID 解析到同一目录
- **工作区碰撞**：新 Agent 的目标目录与现有工作区重叠

## 7. 完整恢复流程

```
POST /backups/{backup_id}/restore
         ↓
execute_restore() [orchestration.py]
         ↓
1. get_backup() 获取元数据
         ↓
2. 停止可能持有文件句柄的 Agent
         ↓
3. restore() 执行原子目录交换
         ↓
4. _preload_agents_background() 重启 Agent
         ↓
finally: 即使失败也重启已停止的 Agent
```

**关键保障**：无论恢复成功或失败，`finally` 块确保 Agent 总是重启。

## 11. 常见问题

### Q1: 恢复失败提示 "destination collides"？

**原因**：Agent 目标目录冲突（同一目录被多个 Agent 使用）。

**解决方案**：
1. 检查 `agents.profiles` 配置
2. 删除冲突的目录
3. 使用 `custom` 模式恢复

### Q2: 恢复后 Agent 无法启动？

**排查步骤**：
```bash
# 1. 检查 Agent 配置文件
cat ~/.qwenpaw/agents/profiles.json

# 2. 检查工作区权限
ls -la ~/.qwenpaw/workspaces/

# 3. 查看启动日志
tail -f logs/qwenpaw.log
```

### Q3: 备份文件过大？

**原因**：未排除不必要的文件或 Agent 工作区过大。

**优化方案**：
```python
# 配置备份范围，排除大文件
scope = BackupScope(
    include_agents=True,
    exclude_patterns=["**/*.log", "**/.cache/**"]
)
```

### Q4: 跨机器恢复后数据无法解密？

**原因**：主密钥冲突，备份的密钥与当前机器不同。

**正确做法**：
1. 恢复前**不要**勾选 `include_secrets`
2. 或确保两台机器使用相同的主密钥
