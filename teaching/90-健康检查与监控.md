# 健康检查与监控

## 概述

QwenPaw 的健康检查系统覆盖渠道、隧道和整体运行时状态，通过专用 API 端点支持 Kubernetes readiness 和 liveness 探测。系统提供多层次的健康监控能力，确保服务可靠性。

**核心特性：**
- **渠道健康检查：** 独立检查每个渠道（Telegram、Console 等）的状态
- **隧道健康监控：** 监控 Cloudflare Tunnel 连接状态
- **心跳机制：** 定期发送心跳维持外部连接
- **K8s 集成：** 支持 readinessProbe 和 livenessProbe

**源码路径：** `src/qwenpaw/app/routers/config.py`

```python
async def _resolve_channel_manager(request: Request, channel_name: str):
    """验证渠道名称并返回 channel_manager"""
    available = get_available_channels()
    if channel_name not in available:
        raise HTTPException(status_code=404, detail=f"Channel not available")

    agent = await get_agent_for_request(request)
    channel_manager = agent.channel_manager
    if channel_manager is None:
        raise HTTPException(status_code=503, detail="Channel manager not initialized")
    return channel_manager
```

```python
async def health_check(self) -> bool:
    """Return True if the tunnel process is running."""
    return self._process is not None and self._process.returncode is None
```

```python
# src/qwenpaw/tunnel/cloudflare.py:155
async def _monitor(self) -> None:
    """Drain stderr and log unexpected exit without auto-restart."""
    await self._drain_stderr()

    if not self._process:
        return

    await self._process.wait()
    rc = self._process.returncode
    logger.warning(
        "cloudflared exited with code %s; not restarting Quick Tunnel "
        "automatically because a new public URL would be issued.",
        rc,
    )

    self._info = None
```

## 3. 渠道健康状态

### 3.1 状态枚举

| 状态 | 说明 |
|------|------|
| `healthy` | 渠道正常运行，可以接收流量 |
| `unhealthy` | 渠道异常，需要排查 |
| `disabled` | 渠道被禁用 |

### 3.2 健康检查返回示例

**健康状态：**
```json
{
    "channel": "console",
    "status": "healthy",
    "detail": null
}
```

**异常状态：**
```json
{
    "channel": "telegram",
    "status": "unhealthy",
    "detail": "Connection timeout after 30s"
}
```

**禁用状态：**
```json
{
    "channel": "voice",
    "status": "disabled",
    "detail": "Channel disabled by configuration"
}
```

### 3.3 状态流转

```
启用渠道
    │
    ▼
检查健康 → healthy
    │
    ├── 连接正常 → 保持 healthy
    │
    └── 连接失败 → unhealthy → 尝试重连
                        │
                        ├── 重连成功 → healthy
                        │
                        └── 重连失败 → unhealthy（持续）
```

## 6. Kubernetes 探测集成

### 6.1 Readiness Probe

readinessProbe 用于检查渠道是否准备好接收流量：

```yaml
# readinessProbe 检查渠道是否可接收流量
readinessProbe:
  httpGet:
    path: /api/config/channels/console/health
    port: 8000
  initialDelaySeconds: 5   # 等待 5 秒后开始探测
  periodSeconds: 10        # 每 10 秒探测一次
  timeoutSeconds: 5       # 超时 5 秒
  failureThreshold: 3     # 连续 3 次失败标记为失败
```

### 6.2 Liveness Probe

livenessProbe 用于检查进程是否存活：

```yaml
# livenessProbe 检查进程是否存活
livenessProbe:
  httpGet:
    path: /api/version
    port: 8000
  initialDelaySeconds: 15  # 等待 15 秒后开始探测
  periodSeconds: 20        # 每 20 秒探测一次
  timeoutSeconds: 5       # 超时 5 秒
  failureThreshold: 3     # 连续 3 次失败重启容器
```

### 6.3 探测策略建议

| 探测类型 | 目标 | 建议间隔 |
|----------|------|----------|
| readinessProbe | 检查渠道可用性 | 10-30 秒 |
| livenessProbe | 检查进程存活 | 20-60 秒 |
| startupProbe | 慢启动应用 | 10-30 秒 |

## 8. 应用场景

### 场景 1: K8s 部署健康检查

**问题：** 在 Kubernetes 中部署 QwenPaw，需要配置健康检查

**解决方案：**
```yaml
apiVersion: apps/v1
kind: Deployment
spec:
  template:
    spec:
      containers:
      - name: qwenpaw
        livenessProbe:
          httpGet:
            path: /api/version
            port: 8000
          initialDelaySeconds: 15
          periodSeconds: 20
        readinessProbe:
          httpGet:
            path: /api/config/channels/console/health
            port: 8000
          initialDelaySeconds: 5
          periodSeconds: 10
```

### 场景 2: 外部监控告警

**问题：** 需要在渠道异常时收到通知

**解决方案：**
```python
# 定期检查所有渠道健康状态
async def monitor_all_channels():
    channels = await get_all_channels()
    unhealthy = []

    for channel in channels:
        health = await channel.health_check()
        if health.status != "healthy":
            unhealthy.append(channel.name)

    if unhealthy:
        await send_alert(f"Unhealthy channels: {unhealthy}")
```

### 场景 3: 自动重启异常渠道

**问题：** 渠道异常时需要自动重启

**解决方案：**
```bash
# 每分钟检查一次
*/1 * * * * curl -f http://localhost:8000/api/config/channels/telegram/health || \
  curl -X POST http://localhost:8000/api/config/channels/telegram/restart
```

## 10. 常见问题

### Q1: ReadinessProbe 一直失败

**原因：**
- 应用启动太慢
- 健康检查端点路径错误
- 端口配置不正确

**解决方案：**
```yaml
# 增加 initialDelaySeconds
readinessProbe:
  initialDelaySeconds: 30  # 等待更长时间

# 检查端点是否正确
curl http://localhost:8000/api/config/channels/console/health
```

### Q2: 渠道状态 unhealthy 但无法重启

**原因：**
- 重启端点返回错误
- 渠道管理器未初始化

**排查步骤：**
```bash
# 1. 检查渠道状态
curl http://localhost:8000/api/config/channels/telegram/health

# 2. 检查渠道管理器
curl http://localhost:8000/api/config/channels

# 3. 查看应用日志
tail -f logs/qwenpaw.log | grep -i "channel"
```

### Q3: 心跳未发送

**原因：**
- Heartbeat 配置未启用
- target URL 不可达
- 调度器未启动

**解决方案：**
```bash
# 检查心跳配置
curl http://localhost:8000/api/config/heartbeat

# 测试 target URL
curl -v https://your-server.com/heartbeat
```

### Q4: Tunnel 健康检查失败

**原因：**
- cloudflared 进程退出
- 网络问题

**解决方案：**
```python
# 检查 tunnel 进程
tunnel = await get_tunnel()
if not await tunnel.health_check():
    await tunnel.restart()
```

## 12. 总结

**核心要点：**

1. **健康检查端点：** `/api/config/channels/{name}/health` 返回渠道状态
2. **状态类型：** healthy、unhealthy、disabled
3. **心跳机制：** 定期发送心跳维持外部连接
4. **K8s 集成：** readinessProbe 检查可用性，livenessProbe 检查存活
5. **隧道监控：** Cloudflare Tunnel 健康检查

**K8s 探测配置建议：**
- readinessProbe: initialDelaySeconds=5, periodSeconds=10
- livenessProbe: initialDelaySeconds=15, periodSeconds=20

**最佳实践：**
- 合理设置探测间隔和阈值
- 监控 unhealthy 渠道并自动告警
- 定期检查心跳发送状态
- 日志记录健康检查结果
