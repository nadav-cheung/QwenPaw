## 概述

QwenPaw 的健康检查系统覆盖渠道、隧道和整体运行时状态，通过专用 API 端点支持 Kubernetes readiness 和 liveness 探测。系统提供多层次的健康监控能力，确保服务可靠性。

**核心特性：**
- **渠道健康检查：** 独立检查每个渠道（Telegram、Console 等）的状态
- **隧道健康监控：** 监控 Cloudflare Tunnel 连接状态
- **心跳机制：** 定期发送心跳维持外部连接
- **K8s 集成：** 支持 readinessProbe 和 livenessProbe

**源码路径：** `src/qwenpaw/app/routers/config.py`

    """验证渠道名称并返回 channel_manager"""
    available = get_available_channels()
    if channel_name not in available:
        raise HTTPException(status_code=404, detail=f"Channel not available")

## 6. Kubernetes 探测集成

### 6.1 Readiness Probe

readinessProbe 用于检查渠道是否准备好接收流量：

```yaml
# readinessProbe 检查渠道是否可接收流量
readinessProbe:
  httpGet:
    path: /api/config/channels/console/health
    port: 8000
  initialDelaySeconds: 5   # 等待 5 秒后开始探测
  periodSeconds: 10        # 每 10 秒探测一次
  timeoutSeconds: 5       # 超时 5 秒
  failureThreshold: 3     # 连续 3 次失败标记为失败
```

### 6.2 Liveness Probe

livenessProbe 用于检查进程是否存活：

```yaml
# livenessProbe 检查进程是否存活
livenessProbe:
  httpGet:
    path: /api/version
    port: 8000
  initialDelaySeconds: 15  # 等待 15 秒后开始探测
  periodSeconds: 20        # 每 20 秒探测一次
  timeoutSeconds: 5       # 超时 5 秒
  failureThreshold: 3     # 连续 3 次失败重启容器
```

### 6.3 探测策略建议

| 探测类型 | 目标 | 建议间隔 |
|----------|------|----------|
| readinessProbe | 检查渠道可用性 | 10-30 秒 |
| livenessProbe | 检查进程存活 | 20-60 秒 |
| startupProbe | 慢启动应用 | 10-30 秒 |

### 练习 3：自动重启异常渠道

**目标：** 实现异常渠道的自动重启逻辑。

```python
import asyncio

class AutoRestartManager:
    def __init__(self, max_retries: int = 3, retry_delay: int = 30):
        self.max_retries = max_retries
        self.retry_delay = retry_delay

    async def monitor_and_restart(self, channel_name: str):
        retry_count = 0
        while retry_count < self.max_retries:
            health = await check_channel_health(channel_name)
            if health.status == "healthy":
                retry_count = 0  # 重置重试计数
                await asyncio.sleep(60)  # 检查间隔
                continue

            # 不健康，尝试重启
            retry_count += 1
            logger.warning(
                f"Channel {channel_name} unhealthy, "
                f"attempting restart ({retry_count}/{self.max_retries})"
            )
            await restart_channel(channel_name)
            await asyncio.sleep(self.retry_delay)  # 等待重启完成

        # 超过最大重试次数，告警
        await send_alert(f"Channel {channel_name} failed to recover after {self.max_retries} attempts")
```

### 练习 5：心跳去抖动设计

**目标：** 实现心跳的防抖动机制，避免网络抖动误判。

```python
import asyncio
from dataclasses import dataclass

@dataclass
class HeartbeatState:
    consecutive_failures: int = 0
    last_success: float = 0

class DebouncedHeartbeat:
    def __init__(self, failure_threshold: int = 3):
        self.state = HeartbeatState()
        self.failure_threshold = failure_threshold

    async def beat(self) -> bool:
        try:
            await self.send_heartbeat()
            self.state.consecutive_failures = 0
            self.state.last_success = asyncio.get_event_loop().time()
            return True
        except Exception as e:
            self.state.consecutive_failures += 1
            if self.state.consecutive_failures >= self.failure_threshold:
                logger.error(
                    f"Heartbeat failed {self.failure_threshold} consecutive times: {e}"
                )
                await self.on_failure()
            return False

    async def on_failure(self):
        """连续失败后执行的恢复逻辑"""
        await send_alert("Heartbeat system degraded")
        # 可选：触发渠道重连
```

## 如果你来自 Java

QwenPaw 的健康检查与监控体系与 Spring Boot Actuator + Micrometer 生态高度对应，但更专注于 Agent 场景。

### 概念对应表

| Java Spring Boot | QwenPaw | 说明 |
|-----------------|---------|------|
| **Actuator `/actuator/health`** | `/api/config/channels/{name}/health` | 健康检查端点 |
| **HealthIndicator** | `ChannelManager.health_check()` | 健康检查实现 |
| **/@PreDestroy** | 渠道 `stop()` 方法 | 资源清理 |
| **Micrometer Gauge** | Prometheus 指标 | 数值型指标 |
| **Micrometer Counter** | 事件计数器 | 事件统计 |
| **Thread dump endpoint** | 暂无 | 线程分析 |
| **K8s Probe integration** | readinessProbe/livenessProbe | K8s 探测 |

### Spring Boot Actuator 对比

// Spring Boot: 自定义 HealthIndicator
@Component
public class TelegramHealthIndicator implements HealthIndicator {

### 心跳机制对比

Java Spring Scheduler vs QwenPaw APScheduler：

```java
// Spring: @Scheduled 注解
@Scheduled(fixedRate = 300_000)  // 5 分钟
public void sendHeartbeat() {
    restTemplate.getForObject(heartbeatUrl, String.class);
}
```

```python
# QwenPaw: APScheduler
scheduler = AsyncIOScheduler()

@scheduler.scheduled_job("interval", seconds=300)
async def send_heartbeat():
    async with aiohttp.ClientSession() as session:
        await session.get(heartbeat_url)
```

**总结：** Spring Boot 提供了开箱即用的健康检查生态，QwenPaw 需要更多手动配置但提供了更细粒度的 Agent 场景定制（渠道级健康检查、Tunnel 监控等）。
