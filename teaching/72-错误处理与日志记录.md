# 错误处理与日志记录

## 概述

QwenPaw 的错误处理采用多层策略：QueryErrorDump 转储错误上下文、标准化错误响应、SSE 流式错误传递。日志系统支持彩色终端输出和日志轮转。

`★ Insight ─────────────────────────────────────`
- QueryErrorDump 是**事后调试**的关键——异常发生时的完整上下文（堆栈、请求、Agent 状态）全部持久化到 JSON
- 异常转换器 `convert_model_exception` 是**统一对外错误契约**的核心：根据 status_code 和关键词将底层 Provider 异常映射为语义明确的业务异常
- 日志的 `propagate=False` 设计是**隔离依赖日志**的妙招：避免 uvicorn 等第三方库的日志污染
`─────────────────────────────────────────────────`

## 1. QueryErrorDump

**源码路径**: `src/qwenpaw/app/runner/query_error_dump.py:48`

### 1.1 功能说明

当 Agent 处理请求发生异常时，QueryErrorDump 将完整的错误上下文转储到临时 JSON 文件，供事后分析和调试。

### 1.2 转储内容

**源码路径**: `src/qwenpaw/app/runner/query_error_dump.py:48`

```python
def write_query_error_dump(
    request: Any,
    exc: BaseException,
    locals_: dict,
) -> str | None:
    """Write error log, traceback and agent/memory state to a temp JSON file.

    Returns the temp file path, or None if write failed.
    """
    payload = {
        "trace": trace_str,                    # 完整堆栈跟踪
        "exception_type": type(exc).__name__,   # 异常类型
        "exception_message": str(exc),           # 异常消息
        "request_info": request_info,           # 请求基本信息
        "request": request_full,                 # 完整请求（脱敏后）
        "agent_state": agent_state,             # Agent 状态
        "ts_utc": datetime.now(timezone.utc).strftime("%Y-%m-%dT%H:%M:%SZ"),
    }
```

### 1.3 转储字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `trace` | `str` | `traceback.format_exc()` 完整堆栈 |
| `exception_type` | `str` | 异常类名（如 `ValueError`） |
| `exception_message` | `str` | 异常消息 |
| `request_info` | `dict` | session_id, user_id, channel |
| `request` | `dict` | AgentRequest 序列化（脱敏后） |
| `agent_state` | `dict` | Agent state_dict（如果可用） |
| `ts_utc` | `str` | UTC 时间戳 |

### 1.4 安全序列化

**源码路径**: `src/qwenpaw/app/runner/query_error_dump.py:17`

```python
def _safe_json_serialize(obj: object) -> object:
    """Convert object to JSON-serializable form; use str() for unknowns."""
    if obj is None or isinstance(obj, (bool, int, float, str)):
        return obj
    if isinstance(obj, (list, tuple)):
        return [_safe_json_serialize(x) for x in obj]
    if isinstance(obj, dict):
        return {str(k): _safe_json_serialize(v) for k, v in obj.items()}
    return str(obj)
```

## 3. Runner 错误处理

**源码路径**: `src/qwenpaw/app/runner/runner.py:720`

### 3.1 错误处理流程

```python
except Exception as e:
    # 1. 获取模型名称
    model_name = None
    if agent and hasattr(agent, "model"):
        model_name = getattr(agent.model, "model_name", None)

    # 2. 转换异常
    converted = convert_model_exception(e, model_name)

    # 3. 写入错误转储
    debug_dump_path = write_query_error_dump(
        request=request,
        exc=converted,
        locals_=locals(),
    )

    # 4. 添加调试路径到异常
    if debug_dump_path:
        setattr(converted, "debug_dump_path", debug_dump_path)
        if hasattr(converted, "add_note"):
            converted.add_note(f"(Details:  {debug_dump_path})")

    # 5. 记录日志
    logger.exception(f"Error in query handler: {converted}{path_hint}")

    raise converted from e
```

## 6. Windows ANSI 支持

**源码路径**: `src/qwenpaw/utils/logging.py:28`

```python
def _enable_windows_ansi() -> None:
    """在 Windows 10+ 上启用 ANSI 转义码支持。"""
    if platform.system() != "Windows":
        return
    try:
        import ctypes
        kernel32 = ctypes.windll.kernel32
        # STD_OUTPUT_HANDLE = -11
        # ENABLE_VIRTUAL_TERMINAL_PROCESSING = 0x0004
        handle = kernel32.GetStdHandle(-11)
        mode = ctypes.c_ulong()
        kernel32.GetConsoleMode(handle, ctypes.byref(mode))
        kernel32.SetConsoleMode(handle, mode.value | 0x0004)
    except Exception:
        pass
```

## 7. 日志设置函数

```python
def setup_logger(level: int | str = logging.INFO):
    """配置日志输出，仅输出本项目日志，不输出依赖日志。"""
    logger = logging.getLogger(LOG_NAMESPACE)
    logger.setLevel(level)
    logger.propagate = False  # 关键：不向上传播，避免第三方库日志污染
    if not logger.handlers:
        handler = logging.StreamHandler(sys.stderr)
        handler.setFormatter(ColorFormatter(...))
        logger.addHandler(handler)
    return logger
```

## 9. 最佳实践

1. **始终使用异常转换器**：不要直接抛出 Provider 异常，通过 `convert_model_exception()` 转换为统一业务异常
2. **利用 dump_id 调试**：生产环境遇到错误时，优先通过 `dump_id` 获取完整错误上下文
3. **`propagate=False` 隔离**：QwenPaw 的日志设计不污染第三方库日志，调试时注意这一设计意图
4. **脱敏处理**：`write_query_error_dump` 会对敏感字段脱敏，不要在生产环境直接暴露 dump 文件路径
5. **macOS 日志轮转**：守护进程在 macOS 上使用 `RotatingFileHandler`，确保磁盘空间管理

## 10. 常见问题

### Q1: 错误转储文件会无限增长吗？

不会。QueryErrorDump 写入系统临时目录（`tempfile.gettempdir()`），由操作系统自动清理。文件名为 `qwenpaw_error_{uuid}.json`。

### Q2: 如何在调试时输出更详细的日志？

```bash
# 启动时指定日志级别
qwenpaw run --log-level debug

# 或设置环境变量
export QWENPAW_LOG_LEVEL=debug
```

### Q3: Windows 上日志颜色不显示？

Windows 10+ 自动启用 ANSI 支持。若仍不显示，检查是否使用了旧版 Windows 或禁用了终端颜色支持。

### Q4: 如何将日志同时输出到文件和控制台？

```python
from qwenpaw.utils.logging import setup_logger, add_project_file_handler

logger = setup_logger(level="DEBUG")
add_project_file_handler("/path/to/app.log")  # 同时写入文件
```
